## 1. 定位与边界

- **本篇管**：采集源的**类型体系**（哪些源、怎么归类）、设备/机器人的**登记与管理**（注册/状态/标定/内参）、**时间基准**（全链时间可对齐的前提）、**合规源头标记**（隐私源在源头打标）
- **不管**：各源怎么接进来（本域 02 适配器）、数据怎么校验上云（本域 03）、工厂怎么排产（本域 04）、算子怎么跑（生产域）
- **一句话**：接入域的元问题——**"这个世界有哪些源、哪些设备、它们长什么样"**——源与设备的登记做不清，后面所有适配、校验、血缘都是无根之木

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 源类型体系 | 定义采集源分类 | 四源 + rosbag 载体（§3）；SSOT 在算子-05 |
| 设备管理服务 | 设备注册/状态/标定管理 | RawDataPackage 设备侧字段的来源 |
| 标定参数管理 | 内参/外参/手眼标定的版本化 | 标定错 = 重建全错；标定参数必须随数据走 |
| 时间基准服务 | UTC + 单调时钟约定 | 多传感器对齐的前提（§5） |
| 合规源头标记 | 隐私/敏感源源头打标 | 脱敏前置的触发依据（算子-05 矩阵） |

> **与负载均衡/控制面同构**：这套就是**节点/实例管理 + 设备指纹**——设备注册 ≈ 节点纳管（登记才能上线），标定参数 ≈ 实例配置（错误配置的节点不许转发流量），内参/外参版本 ≈ 配置版本化（变更可回溯），时间基准 ≈ 全网时钟同步（NTP 偏差不修，所有日志对不齐时序），合规标记 ≈ 分级纳管（涉密节点与普通节点分开管）。我在 XLB 管集群：纳管、配置、健康、时钟，四件事是接入的第一道地基。

## 3. 源类型体系（四源 + rosbag 载体）

| 源类型 | 数据特点 | 结构化主线（引用算子-05 §1） | 接入形态 |
| --- | --- | --- | --- |
| **第一视角 ego** | RGB 视频，无本体真值 | 视觉重建（检测/手部/位姿/深度） | AR 眼镜/头显/互联网 ego 视频 |
| **遥操作** | 关节流 + 相机，**有本体真值** | 真值直读，视觉重建可跳过 | **rosbag 为主要载体** |
| **仿真** | 渲染 + **自带 GT** | GT 旁路，跳过感知重建 | 仿真器对接（GT 旁路入口） |
| **动捕/传感器** | marker/IMU/深度直读 | 传感器直读，视觉重建可跳过 | 动捕 SDK/传感器直采 |

- **rosbag 是载体不是源**：rosbag 是遥操作/真机采集的主流封装格式（话题/时间戳/坐标系齐全）——不是第五种源，是"遥操作源的标准入参形态"；管线对 rosbag 的解析在 [本域 02](02-多源接入适配器.md) 适配器层
- **四源决定算子裁剪**：源类型 → 算子适用矩阵（算子-05 §2：哪些算子 ✔/○/➖）——接入域只登记"是什么源"，裁剪在执行层
- **源类型是 RawDataPackage 的一等字段**：source_type 决定下游整条管线的走向（仿真走 GT 旁路、遥操作真值直读），也是血缘图的第一节点（治理 02）

## 4. 设备登记与管理

- **登记即准入**：设备上线前必须在设备管理服务注册——未登记设备采集的数据不入湖（源头拦截的第一道：**身份**）
- **登记字段**（与 RawDataPackage 设备侧字段对齐，总线 §4.1）：

```yaml
device_registry:              # 设计通识（字段以实现为准）
  device_id / name / type:    # 类型=机器人本体|相机|动捕系统|仿真实例
  owner / location / status:  # 状态=online|calibrating|offline|retired
  calibration: {intrinsics_ref, extrinsics_ref, handeye_ref, version, calibrated_at}
  sensor_set: [ {sensor_id, modality, model, serial} ]   # 相机/IMU/关节编码器…
  time_base: {protocol: ntp|ptp|monotonic, sync_error_est}
  compliance: {privacy_sensitive: true|false, blur_required: true|false}
```

- **标定参数是配置不是摆设**：内参（焦距/畸变）/外参（相机到机器人基座）/手眼标定——标定版本随数据记录，**标定变更触发复标 + 旧版本数据标记**（对齐治理 01 变更受控精神）；标定错的数据重建全错，且错误不可事后修复（源头错 = 整条链错）
- **异构是常态**：10+ 异构硬件（智域基石口径）——设备模型/序列号/传感器集差异登记在册，适配器（02）与算子（生产域）按设备能力路由

## 5. 时间基准（全链可对齐的前提）

- **双时钟约定**：绝对时间（UTC，跨源/跨天对账用）+ 单调时钟（同源内帧序与时长，防 NTP 跳变）——RawDataPackage 同时记录两者
- **时间同步是四源必需算子**（算子-05 §2 矩阵第一行）：多相机/相机-关节/相机-动捕的采样对齐——**同步偏差直接进重建误差**（手部轨迹与关节流错位 = 伪真值污染）
- **时基随数据走**：source/session 级时基声明（协议 + 估计误差）进元数据——血缘与评测（L1 时间对齐类指标）都要能回溯"这段数据的时间可信度"

## 6. 合规源头标记（脱敏前置的触发依据）

- **源头打标**：隐私敏感源（第一视角/含人脸场景）在源头标记 `privacy_sensitive + blur_required`——触发 [脱敏前置算子](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md)（算子-05 §2：第一视角 ✔ 脱敏前置、仿真 ➖ 无隐私）
- **标记进 RawDataPackage**：合规标记是接入→生产准入三查之一（总线 §4.2）——**源头没标 = 生产域不知道要脱敏 = 合规事故在源头埋雷**；未标记的隐私数据被拦截在源头，成本最低（对齐算子-06 规则前置省钱策略）
- **决策在治理**：合规标记的具体规则（什么算敏感、脱敏强度）由治理 07 合规引擎定义——本篇执行源头打标，不自行定义

## 7. 指标与质量门

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| 设备登记率 | 在产数据设备已登记比例 | **100%（未登记不产数据）** |
| 标定覆盖率 | 在产设备标定有效比例 | **100%（标定过期停产）** |
| 时间同步合格率 | 源内采样对齐合格比例 | 待标定（同步偏差超阈数据不跨域） |
| 合规标记完整率 | 隐私源带合规标记比例 | **100%（源头未标 = 源头拦截）** |
| 标定版本随数据率 | 数据带标定版本引用比例 | 100%（对齐三锁可复现） |

## 9. 红线与面试话术

**红线**：

1. **未登记设备不产数据**：身份不明的数据源头不信任——登记是源头第一道闸
2. **标定不过不开工**：标定参数缺失/过期 = 重建必错且不可事后修复——标定随数据、变更复标
3. **时间不同步不跨域**：同步偏差超阈的数据进不了生产（伪真值污染比缺数据更危险）
4. **隐私源必带合规标记**：源头没标 = 生产域不知道要脱敏 = 合规事故在源头埋雷（对齐治理 07）
5. **源类型是一等字段**：source_type 决定下游走向与血缘起点——源类型标错 = 整条管线走错门
6. **标定/时基随数据走**：可复现从源头的物理参数就位开始（对齐版本三锁精神）

**面试话术（30 秒）**：

> "接入域我先管两件元事：源和设备。源是四类——第一视角、遥操作、仿真、动捕，rosbag 是遥操作的载体不是第五类源；源类型决定算子裁剪（仿真走 GT 旁路、遥操作真值直读），也决定血缘图的起点。设备是登记制：上线前必须注册，标定参数——内参、外参、手眼——版本化管理随数据走，标定过期就不许产数据，因为源头错整条链错且不可事后修。时间基准双时钟：UTC 对账加单调时钟防跳变，时间同步是四源必需算子，偏差超阈的数据不跨域。合规源头打标：隐私源在源头就标 blur_required，触发脱敏前置，源头没标等于在源头埋雷，成本最低的拦截在源头。这套就是 XLB 节点纳管加设备指纹的搬运：登记、配置、健康、时钟——被管对象从集群节点换成采集设备。"
