# 03 · 源头校验与上云（三查 / 源头拦截 / 边缘缓存与断网续传 / 原始数据湖落位）

> 01-接入域第 3 篇。定位：**RawDataPackage 生成前的最后一关**——三查（源头完整性 / schema / 合规标记）全过才成包，上云保吞吐与可靠，不合格源头就地拦截（**最省 GPU 成本的一刀**）。边界：归一与适配 = [本域 02](02-多源接入适配器.md)；算子执行与 G0 门 = [生产域](../02-生产域/README.md)（[算子设计-02 §9](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md)）；湖仓物理布局与分区 = [资产域 01](../05-资产域/01-湖仓统一存储与多模态布局.md)（**本篇只负责放进去**）；合规规则定义 = [治理 07](../04-治理域/07-合规引擎.md)（**本篇只执行核验**）；准入契约 = [总线 §4.2](../00-总体架构/README.md)（接入→生产三查）。

## 1. 定位与边界

- **本篇管**：**三查**的执行（完整性/schema/合规核验）、**源头拦截**（隔离区 + 原因归档）、**上云通道**（边缘缓存/断网续传/批传/传输校验）、**原始数据湖落位**（只写原始层）
- **不管**：数据怎么归一（本域 02）、算子质量门怎么跑（生产域 G 门）、湖仓怎么分区怎么管元数据（资产域 01/02）、合规规则怎么定（治理 07）
- **一句话**：02 把源数据翻译成统一信号，本篇是「**能不能跨域**」的闸口——三查全过才成包上云，不过就在源头拦下，**坏数据不过河，GPU 不为它点卯**

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 完整性校验器 | 帧/流不丢不坏 | 帧连续性、时长、流完整性 hash |
| schema 校验器 | 字段齐全、声明就位 | 时基/标定版本/合规标记齐备（总线 §4.1 字段） |
| 合规核验器 | 隐私源已打标 | 规则在治理 07；本篇只核验标记在不在 |
| 拦截区管理 | 不合格数据隔离 | Quarantined 状态 + 原因归档 |
| 上云通道 | 边缘缓存/批传/续传 | 传前传后双校验（§5） |
| 落位写手 | RawDataPackage 写原始层 | 布局归资产域 01，本篇只写入并登记 |

> **与负载均衡/控制面同构**：这套就是**接入网关的健康检查与准入**——三查 ≈ 节点健康检查三件套（进程在、配置对、证书全），任何一项不过不许接流量；源头拦截 ≈ 边缘节点不合格在边缘就摘除，**绝不让坏流量进核心再清洗**（在源头挡是最便宜的挡法，算子-06 规则前置同理）；边缘缓存断网续传 ≈ 边缘日志本地暂存、连通后回放；传前传后双校验 ≈ 传输层 checksum 端到端确认。被管对象从接入流量换成原始数据，准入纪律一字不改。

## 3. 三查详解（能不能跨域的判据）

| 查 | 查什么 | 怎么查 | 不过怎么办 |
| --- | --- | --- | --- |
| **源头完整性** | 帧/流不丢不坏 | 帧连续性（丢帧/跳变）、时长对账（录制声明 vs 实际）、流完整性 hash | 源头拦截（§4） |
| **schema** | 统一形态字段齐全 | 总线 §4.1 字段就位：source_id/session_id/设备型号/内参/时间戳基准/合规标记；时基声明在、标定版本引用在 | 源头拦截（缺字段 = 下游无法溯源） |
| **合规** | 隐私源已打标 | 对照 [本域 01 §6](01-采集源与设备管理.md) 源头标记，核验 privacy_sensitive/blur_required 在位（**规则在治理 07，本篇执行核验**） | 源头拦截（未标隐私数据不许过河） |

- **三查是准入契约**：接入→生产的唯一关口（总线 §4.2）——生产域信任「过河的数据都查过」，不再重复源头校验（G0 接续的是算子侧检查，[算子-02 §9](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md)）
- **核验不是判断**：合规查只回答「标记在不在」，不回答「该不该标」——该不该标在本域 01 打标时按治理 07 规则定了，本篇不当第二裁判

## 4. 拦截策略（最省成本的一刀）

```
三查任一不过 ──► 源头拦截
                  ├─ 状态：Quarantined（治理 01 §5 生命周期，不进生产）
                  ├─ 原因归档：{failed_check, detail, device_ref, session_id}
                  └─ 去向：打回补采（可修复） | 显式废弃（不可修复）
                                │
                                ▼
              拦截原因 → 采集质量反馈（供本域 04 排产与采集侧整改；
              高频拦截原因 = 设备/标定/脚本问题信号）
```

- **为什么拦在源头最省**：数据一旦跨域进生产，GPU 算力就在为它点卯（解码、感知、标注全线跑一遍才发现坏，[算子-06](../02-生产域/算子设计/算子设计-06-算子成本模型.md) 规则前置的省法）——**源头一刀 = 省整条链**
- **拦截必归档**：每次拦截带原因与上下文——不归档的拦截只是丢数据，归档的拦截才是质量反馈（高频原因反推设备维护/标定复标/脚本缺陷，喂给 [本域 04](04-采集工厂与容量排产.md) 排产约束）
- **可修复优先打回**：丢帧/标记缺失类走补采重录（接入域侧闭环）；采集事故类（整段损坏）显式废弃留痕

## 5. 上云通道（吞吐与可靠）

- **边缘缓存**：采集现场断网/弱网时本地暂存（采集 Agent 侧缓冲），恢复后续传——**现场不断采**，产线不因网络停摆
- **批传**：按批次/session 打包上传（不逐文件碎片传）——批量校验、批量登记，传输开销摊薄
- **传前传后双校验**：传前算包 hash、传后云端复算对账——**传输完整性有自己的关**，不把坏在路上的数据当源头坏（两类问题两种修法：传输坏重传，源头坏拦截）
- **带宽与成本权衡**：上云走对象存储通道，与 GPU 算力侧解耦（**GPU 侧不背 IO**）——原始视频量大（多相机 × 小时级），批传窗口与带宽预算待标定

## 6. 原始数据湖落位（只写原始层）

- **落位动作**：RawDataPackage（源文件 + schema 元数据 + 三查结果）写入湖仓 `raw/` 原始层（[资产域 01 §5](../05-资产域/01-湖仓统一存储与多模态布局.md)：`raw/{source}/{session}/…`，不可变留存）
- **布局不归本篇**：分区/路径/CAS 规范在资产域 01（SSOT）——本篇只负责「放进去」并带上登记信息（[资产域 02](../05-资产域/02-数据集目录与检索.md) 目录登记的原始层入口）
- **原始层只读不加工**：一切加工（感知/标注/封装）在生产域产出新制品——原始层是「底片」，只增不改（对齐资产域 01 红线）

## 7. 关键字段示意

```yaml
raw_package_manifest:            # 设计通识（字段以实现为准）
  package_id / source_id / session_id
  device_ref: {device_id, model, calibration_ref}      # 本域 01
  checks:                         # 三查结果（总线 §4.2）
    integrity: {frames_continuous: pass, duration_match: pass, stream_hash: …}
    schema:      {fields_complete: pass, time_base_declared: true}
    compliance:  {privacy_flagged: true, rule_version: …}   # 治理 07 规则版本
  verdict: pass | quarantined{failed_check, reason, disposition}
  transfer: {batch_id, uploaded_at, pre_hash, post_hash, verified: true}
  storage: {layout_ref: "raw/{source}/{session}/", registered_in_catalog: true}
```

## 8. 指标与质量门

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| 三查覆盖率 | 跨域数据全过三查比例 | **100%（三查不全不跨域）** |
| 漏拦率 | 生产域/G 门兜底发现的源头缺陷率 | 趋势 0（每次漏拦复盘校验项） |
| 传输完整性 | 传后 hash 对账通过率 | 100%（双校验兜底） |
| 拦截原因归档率 | 拦截带原因记录比例 | **100%（不归档的拦截=丢数据）** |
| 上云时延 / 断网续传成功率 | 现场到落位的时效与可靠 | 待标定（现场不断采为底线） |

## 10. 红线与面试话术

**红线**：

1. **三查不全不跨域**：任何一查不过的数据停在源头——跨域的坏数据要靠 GPU 陪葬才发现（总线 §4.2 契约）
2. **拦截原因必归档**：拦截不归档只是丢数据，归档才是采集质量反馈——高频拦截原因要能反推设备/标定问题
3. **上云必验传输完整性**：传前传后双 hash——传输坏重传、源头坏拦截，两类问题不混谈
4. **原始层只读不加工**：底片只增不改，一切加工产出新制品（资产域 01 红线）
5. **合规核验不当第二裁判**：本篇只核验标记在位，规则与判定在治理 07——执行层不自定合规标准
6. **现场不断采**：断网走边缘缓存续传——网络问题不让产线停摆（产能优先于链路洁癖）

**面试话术（30 秒）**：

> "源头校验我做成 RawDataPackage 生成前的最后一关，三查：完整性查帧连续、时长对账、流 hash；schema 查总线定义的字段齐不齐、时基和标定版本声明没声明；合规查隐私源标记在不在——规则在治理域，我只核验不过夜。任一不过就地拦截，状态进 Quarantined，原因归档，能修的打回补采、不能修的显式废弃——拦在源头是最省成本的一刀，因为数据一旦过河，GPU 全链都在为它点卯，这正是成本模型里规则前置的省法。上云走边缘缓存加批传：现场断网本地暂存恢复续传，按 session 打包传，传前传后双 hash 对账，传输坏和源头坏分开处理。落位只写湖仓原始层，布局归资产域，原始层只读不加工，底片只增不改。这套就是 XLB 接入网关健康检查的搬运：三件套准入、边缘摘除不让坏流量进核心、传输 checksum——被管对象从接入流量换成原始数据。"
