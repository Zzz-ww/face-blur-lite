## 1. 设计目标、原则与平台边界

### 1.1 设计目标

一个平台覆盖「采集 → 生产 → 治理 → 资产 → 消费」全链路，让数据从原始信号变成可直接训练、可审计、可迭代的数据集资产。

### 1.2 设计原则（业内通识）

1. **面分离**：控制面（编排/调度/状态）与数据面（算子执行）分离——各自独立演进，接口只通过声明式规格交互
2. **数据集为中心**：一切域围绕"数据集资产"运转——作业吃数据集、产数据集，治理管数据集，消费读数据集
3. **声明式 + 不可变**：期望状态声明，控制循环收敛；数据集版本一经发布不可变（可精确复现）
4. **可追溯**：血缘制品化贯穿全链路（这条样本怎么来的、被哪次训练用过）
5. **门禁驱动发布**：质量门禁（规则→互检→抽检→回归）是数据集版本晋升的唯一通道
6. **渐进演进**：MVP 先通链路，控制面/治理后补强，规模化再上多租户与计量

### 1.3 平台边界（Scope）

- **管到**：数据采集、生产、治理、资产、数据消费（导出/评测/回流）
- **不管**：策略训练框架本身、机器人控制、在线推理服务
- **边界制品**：`TrainingRelease`（训练发布集）是平台与模型/训练平台的清晰交界——平台交付可训练数据集，训练作业（Ray Train/Tune）归属模型平台

> 面试防守点：被追问"是否覆盖策略训练/控制"时，明确收敛到边界制品，不发散。

## 3. 六大域详设（职责 / 关键组件 / 接口）

### ① 接入域（采集工厂）

- **职责**：多源数据接入（真机遥操作、第一视角、仿真、动捕、rosbag）、设备/机器人管理、数据上云、源头完整性校验、**仿真源适配（GT 旁路接入）**
- **组件**：采集 Agent/客户端、设备管理服务、数据接入网关、仿真源适配器、原始数据湖（对象存储）
- **接口**：`RawDataPackage`（原始文件 + schema 元数据；接入即校验，不合格源头拦截）
- **业内参照**：智域基石式真机采集工厂（异构硬件统一接入）；华为云 CloudRobo 多本体接入

### ② 生产域（数据面 · 算子流水线）

- **职责**：执行算子全集——预处理（帧规范化）、感知结构化（检测/重建/深度/位姿）、语义标注（VLM）、**标注（自动标注 + 人工标注台 + 标注质检）**、清洗质检、脱敏合规、格式封装（LeRobot v2/v3 / RLDS）
- **组件**：算子库（Data-Juicer 式）、算子引擎（CPU Ray Data / GPU Actor / RayJob / RayService）、算子 DAG 执行器、标注服务（自动 + 人工）
- **接口**：输入数据集 + PipelineSpec（DAG）→ 输出 `StructuredDataset` + `AnnotationSet` + 质检报告
- **业内参照**：阿里云 PAI Data-Juicer VLA 流水线（算子级拆解见 [算子设计-01](../02-生产域/算子设计/算子设计-01-业内通用算子全集总览.md)）

### ③ 管控域（控制面）

- **职责**：任务编排（DAG/重试/断点续跑）、调度（队列/配额/优先级/gang scheduling）、状态机与生命周期、资源管理、多租户分池
- **组件**：KubeRay（RayCluster/RayJob/RayService CRD）、Kueue 调度器（ElasticQuotaTree）、状态存储（etcd/元数据库）、任务管理服务
- **接口**：声明式 PipelineSpec → 作业生命周期状态
- **业内参照**：KubeRay + Kueue 跨团队调度（阿里云 ACK 验证；细节见 [调研笔记-02](../92-调研笔记/调研笔记-02-Ray分布式框架调研与管线应用.md) 与 [算子设计-03](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md)）

### ④ 治理域

- **职责**：数据集版本管理（不可变快照）、血缘追踪（制品化）、质量门禁（规则→互检→抽检→Golden Set 回归→发布审批）、合规引擎、**四层评测（L1–L4）与回归**
- **组件**：元数据/血缘服务、版本服务、质检网关、评测回归服务、合规引擎
- **接口**：版本晋升申请 → 门禁审批结果；血缘查询 API
- **业内参照**：Voxel51 数据集版本与修改追踪 + 版本快照；RoboLineage 类型化血缘制品

### ⑤ 资产域（数据集资产）

- **职责**：数据集目录（检索/打标/浏览）、统一湖仓存储（原始文件+元数据+向量）、不可变快照、版本回溯、训练样本快照、冷热分层与 TTL
- **组件**：数据集目录服务、湖仓（DLF 式统一管理）、向量检索、快照服务
- **接口**：数据集资产 API（查询/导出/快照）
- **业内参照**：阿里云 Agentic Lakehouse（DLF 统一原始文件+向量+元数据）

### ⑥ 消费域

- **职责**：训练消费（数据集导出→分布式训练，训练本身归属模型平台）、下游评测、Badcase 回流驱动数据迭代
- **组件**：数据集导出服务、训练衔接（Ray Train/Tune）、下游评测服务、回流通道
- **接口**：`TrainingRelease`（训练集）+ `EvaluationReport`（评测报告）→ 回流样本
- **业内参照**：GigaBrain 多阶段 QC 后接训练

## 4. 标准制品模型与域间契约（总线核心）

> 六域之间传递的不是散落的文件，而是**带 schema、带版本、带质检状态的标准制品**。这是"总线"二字的落地方式，也是面分离与可追溯的载体。

### 4.1 六类标准制品

| 制品 | 生产者 | 内容构成 | 关键字段 |
| --- | --- | --- | --- |
| **RawDataPackage** 原始数据包 | 接入域 | 源文件 + 采集元数据 + 源头校验 | source_id / session_id / 设备型号 / 内参 / 时间戳基准 / 合规标记 |
| **StructuredDataset** 结构化数据集 | 生产域 | 四层结构化轨迹（手部⊕相机⊕场景⊕物体）+ 阶段质检报告 | 轨迹结构 / QCReport（见 01） |
| **AnnotationSet** 标注集 | 生产域（标注） | 自动/人工标注 + 来源标记 + 置信度 | label_source ∈ {sim_GT, pseudo_GT, human_GT, model}；confidence；annotator |
| **DatasetVersion** 数据集版本（不可变） | 治理域 | 数据文件 + 元数据 + 标注 + 质检报告 + 血缘图 + 三锁版本 | version_id / 三锁 / lineage_graph / gate_result |
| **TrainingRelease** 训练发布集 | 资产域 | 按 split 导出的 train/val/test/golden | split 指针 / 配额统计 / 版本引用 |
| **EvaluationReport** 评测报告 | 消费域/治理域 | L1–L4 指标 + 回归结论 + 回流建议 | l1~l4 指标 / 回归基线 / 回流建议 |

### 4.2 域间契约表（准入即校验，不达标不跨域）

| 上游 → 下游 | 制品 | 准入校验 |
| --- | --- | --- |
| 接入 → 生产 | RawDataPackage | 源头完整性、schema、合规标记 |
| 生产 → 治理 | StructuredDataset + AnnotationSet + QCReport | 阶段门 G0–G4（见 02） |
| 治理 → 资产 | DatasetVersion（晋升令牌） | 全门禁 G5/G6 + 发布审批 |
| 资产 → 消费 | TrainingRelease | split 隔离 + 防泄漏检查（见 07） |
| 消费 → 治理 | EvaluationReport + Badcase | 回流标记 + 血缘定位 |
| 治理 → 生产/接入 | 回流任务 / 补采指令 | 缺陷分类 + 目标算子 |

### 4.3 制品流转总览

```
① 接入域                ② 生产域              ④ 治理域              ⑤ 资产域          ⑥ 消费域
RawDataPackage ──►  StructuredDataset ──►  DatasetVersion ──►  TrainingRelease ──► 训练/评测
（源头校验）         AnnotationSet          （门禁晋升令牌）      （split 隔离）        │
                     + QCReport                                                        │
                          ▲                                                            ▼
                          └──────── 回流任务/补采 ◄──── EvaluationReport+Badcase ◄──────┘
                                            （治理域血缘定位）
```

## 5. 数据流与元数据流（双流）

### 5.1 主数据流（产物流动）

```
接入域 ──原始数据──► 生产域 ──结构化数据集──► 资产域 ──训练集──► 消费域
   ▲                                                │
   └────────────── Badcase 回流（消费→治理→生产）──┘
```

### 5.2 元数据流（登记与治理）

```
每一步执行 → 登记 血缘节点 + 数据集版本 + 算子版本 + 模型版本 + 指标 → 治理域元数据服务
门禁晋升 → 资产域快照 → 消费域读取版本 → 评测报告回流治理域
```

**关键点**：数据流是"产物流动"，元数据流是"审计与治理"——两者分离，但通过血缘图关联。

### 5.3 仿真数据旁路与三套 GT 评测体系（具身特色链路）

- **仿真旁路**：仿真源自带 GT（深度/位姿/分割/动作），在生产域走 **GT 旁路**——跳过 L2 感知重建直接结构化（详见 [算子设计-05 采集源差异矩阵](../02-生产域/算子设计/算子设计-05-采集源差异矩阵.md)）
- **三套 GT 评测手段（用途不可混用）**：
  - **仿真合成 GT（主力）**：全真值、大规模、低成本——算法迭代主评测
  - **伪 GT（补真实域）**：强模型（MegaSaM/HaWoR 等）对真实数据打标——补真实域缺口；须标注置信度，可被真实 GT 推翻
  - **真实 Hold-out GT（最终验证）**：小规模人工精标、冻结不参与训练——只做最终结论
- **Sim2Real 域错配治理**：合成数据预训练 + 少量真实微调；治理域评测服务监测**域间指标差距**，差距过大触发边界/接触约束正则或真实补采（GeoPT 范式定位见主笔记：借范式、不借身份）

## 6. 关键机制

1. **版本三锁**：数据版本 + 算子版本 + 模型版本，一次产出完整锁定，可复现（执行层落点见 [算子设计-04](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md)）
2. **不可变快照**：数据集版本发布即冻结，训练引用精确到版本
3. **门禁晋升流**：规则校验 → 双模型互检 → 分层抽检 → Golden Set 回归 → 发布审批（任一环节失败不得晋升）；算子/阶段级落点 = [算子设计-02](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md) 的 G0–G6
4. **声明式控制循环**：用户声明期望数据集 → 管控域调度执行 → 治理域校验 → 资产域发布
5. **四层数据隔离**：训练/验证/测试/回归集在治理域强制隔离，防泄漏（见 [算子设计-07](../02-生产域/算子设计/算子设计-07-四层数据集分流与防泄漏.md)）
6. **四层评测体系（L1–L4）**：

   | 层级 | 指标 | 落点域 | 驱动 |
   | --- | --- | --- | --- |
   | **L1 算法质量** | 手部 ATE、重建成功率、6DoF ADD、深度一致性 | 生产域算子级 + 治理域 | 单算子模型版本晋升 |
   | **L2 管线工程** | 通吃率、人工介入率、违规率、端到端成功率 | 生产域 + 管控域 | 阶段门 G0–G4 |
   | **L3 性能成本** | GPU 秒/样本、吞吐、失败率、队列延迟 | 管控域 + 横切可观测 | 算子调优、成本预算（见 [06](../02-生产域/算子设计/算子设计-06-算子成本模型.md)） |
   | **L4 下游收益** | 策略/VLA 任务成功率提升、数据消融收益 | 消费域评测 | 版本发布决策、补采方向 |

   规则：L1/L2 不过不入下一层；L4 不做硬阻断（成本高），作为发布/迭代的最终收益证据。

7. **数据生命周期管理**：

   ```
   Raw → Processing → Quarantined(DLQ/隔离) → Validated(过门禁) → Published(不可变) → Deprecated/Archived
   ```

   状态转换由门禁或治理动作触发；Quarantined 与执行层 DLQ 共用通道（见 [03](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md)）；资产域做冷热分层与 TTL 降本。
8. **回流闭环**：Badcase → 血缘定位 → 缺陷分类 → 重跑/补采/算子修复 → 回归验证，驱动数据飞轮。

## 7. 关键架构决策与权衡（ADR）

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 数据集为中心 vs 作业为中心 | **数据集为中心** | 资产可沉淀、版本可复现、血缘可审计 |
| Ray vs 纯 Spark | **Ray 为主、Spark 兼容** | GPU 算子密集、Actor 常驻模型；CPU 批处理可复用 Spark |
| 声明式 vs 命令式 | **声明式 PipelineSpec** | 可静态校验（环/schema 提前拦截）、可重放、控制面收敛 |
| 批处理 vs 流式 | **生产以批为主、采集可流式** | 批可重跑、可检查点；流式用于接入与监控 |
| 湖仓 vs 纯文件存储 | **湖仓** | 统一原始文件+元数据+向量+版本（DLF 式） |
| 质量门前置 vs 后置 | **多层前置 + 发布门兜底** | 源头拦截最省 GPU 成本（规则前置省钱，见 [06](../02-生产域/算子设计/算子设计-06-算子成本模型.md)） |

## 8. 演进路径（四阶段）

| 阶段 | 重点 | 交付 |
| --- | --- | --- |
| **P1 MVP** | 单源接入 + 关键算子（感知/封装）+ 资产版本 + 单格式消费 | 端到端能产出一版可训练数据集 |
| **P2 控制面完整化** | KubeRay + 调度 + 状态机 + 血缘 + 门禁 + 四层评测 | 多作业并行、失败自愈、版本可审计 |
| **P3 规模化** | 多源工厂、仿真旁路、多租户、计量计费、湖仓检索、合规 | 平台化运营、多团队共享 |
| **P4 智能闭环** | Badcase 回流驱动自动补采、评测驱动数据迭代（L4 反哺） | 数据-评测-补采自动闭环 |

## 9. 架构要点总结（总设计师话术）

> "我把平台切六域：接入管采集、生产跑算子、管控做编排调度、治理管版本血缘门禁评测、资产做湖仓快照检索、消费管训练评测回流；可观测、安全、多租户三层横切。域间不传散文件，而是传六类标准制品——原始数据包、结构化数据集、标注集、不可变数据集版本、训练发布集、评测报告，准入即校验，这就是'总线'。核心机制是数据集为中心的不可变版本 + 门禁晋升 + 血缘制品化 + L1–L4 四层评测；仿真数据走 GT 旁路、三套 GT 分工，是具身平台区别于通用数据平台的特色。控制面和数据面严格分离，平台边界止于训练发布集，不越界做策略训练。这套骨架让数据从原始信号到训练资产全程可追溯、可复现、可迭代，是一个'数据工厂操作系统'的完整形态。"
