# 01 · Ego 数据资产化场景导读

> 跟着一批第一视角视频走完首次发布、手部模型升级和训练追溯。六域职责及标准制品以[总体架构 §4](README.md#4-标准制品模型与域间契约总线核心)为准，各步的执行细节见对应专题。

## 核实状态（2026-11-19）

- 已对照本目录的发布门禁、增量物化、训练消费和血缘契约。批次、版本和训练编号均为设计示例，场景待实测。

## 1. 首次发布 `ego-v3`

一批已获授权的 Ego 视频登记在原始数据包 `raw-017` 中。以其中一个 Clip `s-ego-001` 为例，后续加工和追溯通过稳定样本 ID、源媒体引用和时间区间关联。

| 步骤与负责域 | 交接制品 | 通过条件与失败去向 |
| --- | --- | --- |
| ① 接入域登记视频，校验采集元数据和时间同步 | `RawDataPackage` → 生产域 | 通过 G0 后进入加工。缺包或同步失败按原因修复、重传或补采。见[源头校验与上云](../01-接入域/03-源头校验与上云.md)。 |
| ② 管控域按 `PipelineSpec` 编排，生产域预处理、重建手部与相机轨迹、标注动作并质检 | `StructuredDataset`、`AnnotationSet`、`QCReport` → 治理域 | G1–G4 记录各阶段结果。处理故障按检查点恢复，样本质量问题按门禁进入复核或隔离。见[执行与编排](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md)、[质量门表](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md#第-9-节-算子级质量门体系)。 |
| ③ 治理域验证候选并批准晋升 | `DatasetVersion ego-v3`（`Published`）→ 资产域 | G0–G4 通过后进入 `Validated`。G5 核验封装和跨集泄漏，G6 在固定 Golden Set 上做发布回归，两门通过后由发布责任人审批。失败保留判定证据，候选修复后重新送审。见[版本生命周期](../04-治理域/01-版本管理与不可变快照.md#5-版本生命周期状态机)、[回归与发布](../04-治理域/05-回归与发布.md)。 |
| ④ 资产域固定快照，按请求装配训练发布集 | `TrainingRelease rel-ego-v3` → 消费域 | 使用 `ego-v3` 的快照装配 split 清单、样本快照和授权，按本次导出范围检查隔离与泄漏。检查失败即拒绝导出。见[TrainingRelease 装配与导出](../05-资产域/05-TrainingRelease装配与导出.md)。 |
| ⑤ 消费域校验并绑定 release，模型平台执行训练 `tr-042` | 消费意图、保护引用、实际消费记录 → 治理血缘 | 预取前验证授权与精确版本并保护快照，各 rank 达到所声明模式的就绪条件后开跑。校验异常停止交付并保留证据。见[训练消费契约](../06-消费域/01-训练导出与模型平台衔接.md)、[供数与完整性基准](../06-消费域/04-训练供数性能与DataLoader基准.md)。 |
| ⑥ 消费域评测，治理域定位问题并决定回流 | `EvaluationReport`、`Badcase` → 治理域 → 生产或接入域 | 带发现上下文、模型或数据版本和血缘定位才受理。按原因选择重跑、重标或补采。复测通过、回归无倒退并归档证据后关闭。见[下游评测](../06-消费域/02-下游评测执行与L4收益.md)、[Badcase 回流闭环](../06-消费域/03-Badcase回流闭环.md)。 |

`DatasetVersion` 固定已通过治理的样本和信号版本。`TrainingRelease` 基于它固定一次消费可用的 split、样本清单和授权。G5 检查候选的封装与跨集泄漏，装配检查约束实际将要交付的清单和权限，两处各自留下记录。

## 2. 手部模型升级，生成 `ego-v4`

复核发现，`s-ego-001` 在遮挡后的手部轨迹不连续。治理域通过血缘定位到 `ego-v3` 的 `op-per-hand` 和对应模型版本。生产域准备新版手部模型，管控域以 `ego-v3` 和固定依赖图为基线制定重算计划。样本来源、时间基准和切分规则沿用原值，因此继续使用 `s-ego-001`。

| 产物 | 本次处理 |
| --- | --- |
| 原视频、相机位姿、深度 | 原视频沿用原有引用。若手部结果没有回注到相机或深度，且两者的输入指纹、版本、完整性与质量状态都通过复用校验，沿用已有结果。 |
| 手部轨迹、平滑轨迹、动作解算、手部质检 | 对本次升级覆盖的样本重算手部轨迹及依赖字段。若平滑依赖整条 Episode，范围扩大到 Episode。若发现手部结果回注其他字段，继续沿依赖扩大范围。 |
| 候选版本与训练发布集 | 按受影响范围执行质量检查，再走 G5、G6 和发布审批。通过后形成 `ego-v4`，资产域装配 `rel-ego-v4`。失败时隔离候选，既有发布继续按原版本供数。 |

重算清单由字段依赖决定，发布由门禁和回归决定。字段依赖不完整时按阶段或整集保守重算。详见[增量物化 §4–5](../05-资产域/06-样本宽表与增量物化.md#4-由变化生成重算计划)及[算子血缘与版本三锁](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md)。

## 3. 从一次训练追溯到实际用过的数据

查询 `tr-042` 时，从实际消费记录找到 `rel-ego-v3` 的 `train` split、实际样本引用及状态，再追到 `ego-v3`、表快照、`s-ego-001` 对应的手部结果、算子与模型版本和原始媒体。计划样本快照用于重放。若训练提前终止，实际消费可能只覆盖计划的一部分，按最后提交的训练进度和失败记录核对。

```text
tr-042 → 实际消费记录 → rel-ego-v3 / train → ego-v3 / 表快照
                                      └→ s-ego-001 → 手部结果与三锁 → 原视频区间
```

`rel-ego-v4` 发布后，`tr-042` 仍按精确引用使用 `rel-ego-v3`。任务结束或失败后归档实际消费，将需要留存的引用交给实验保留策略管理。表快照、信号结果和原始媒体等均随保护引用保留。详见[血缘查询](../04-治理域/02-血缘制品与版本三锁.md)、[训练样本快照](../05-资产域/03-不可变快照与训练样本快照.md)及[引用保护](../05-资产域/06-样本宽表与增量物化.md#6-三种版本与引用保护)。

## 4. 阅读时用到的两套编号

- **加工步骤**在早期工程笔记中写作 L1–L4，指预处理、感知与重建、语义标注、清洗脱敏与封装。本篇使用步骤全称。见[工程笔记](../91-工程笔记/具身数据管线工程笔记-L2感知层数据流与效果衡量-RayCluster与RayJob调度辨析-附GeoPT理解与迁移设想.md)。
- **评测层级**在治理专题中也写作 L1–L4，指算法质量、管线工程、性能成本和下游收益。G0–G6 是门禁编号。G6 回归用于发布判定，下游收益作为评测证据按治理口径归档。见[四层评测体系](../04-治理域/04-四层评测体系L1-L4.md)。
