## 1. 定位与边界

- **本篇管**：**RBAC 权限模型**（五角色底表 + 数据集/版本/作业级细化）、**作业准入钩子**（PipelineSpec 提交时三合一检查）、**审计日志基础设施**（三类日志的存与防篡改）、**脱敏执行强制**（前插位置强制 + 覆盖校验 + P0 告警联动）
- **不管**：合规规则怎么定义（治理 07 策略即代码，SSOT）；配额怎么调度（管控 02 Kueue，SSOT）；脱敏算子怎么实现（生产域算子库）；门禁怎么裁决（治理 03）
- **一句话**：治理 07 写「应该怎么处理数据」，本篇保证「不这么做就走不通」——权限拦住不该做的人，准入拦住不合规的作业，审计让做过的事赖不掉，脱敏强制让漏网变成 P0

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| RBAC 鉴权中心 | 角色 × 资源 × 操作判定 | 默认拒绝，按需授权（§3） |
| 作业准入钩子 | PipelineSpec 提交时三合一检查 | 权限 + 合规标记 + 配额预算，不过不下发（§4） |
| 审计日志库 | 三类日志 append-only 存储 | 操作/访问/导出；不可篡改不可关停（§5） |
| 脱敏强制器 | DAG 前插位置强制 + 覆盖校验 | 漏网 = P0 硬告警（§6） |
| 合规门执行点 | 版本晋升/出境的检查项执行 | 规则与审批在治理 07，本篇落检查项 |

> **与负载均衡/控制面同构**：这套就是**控制面管理平面的安全纪律**——RBAC ≈ 管理面 API 鉴权（改配置先验权限，转发路径不背鉴权开销，鉴权在入口一次做完）；作业准入钩子 ≈ 配置下发前的安审闸门（不合规的配置在进版本库之前就被拒，绝不「先合入再线上兜底」）；审计日志 ≈ 操作审计（谁在何时从哪个入口改了哪条配置——能被关掉的审计保护不了任何人）；脱敏强制 ≈ 强制路径（敏感操作没有旁路可绕，绕过本身就是告警）。被管对象从配置与流量换成数据与作业，安全底座的姿势一字不改。

## 3. RBAC 权限模型（附录 C 底表 + 资源粒度细化）

- **五角色底表**（[总线 附录 C](../00-总体架构/README.md) 原文，本篇不重定义只细化粒度）：

| 角色 | 主操作域 | 关键权限（附录 C 原文） | 本篇细化（资源粒度） |
| --- | --- | --- | --- |
| 数据工程师 | 生产域、管控域 | 算子/PipelineSpec 编辑、提交作业 | 作业级：提交/重跑/取消自己项目的作业 |
| 算法工程师 | 消费域、算子模型版本 | 数据集导出、评测、模型版本登记 | 数据集/版本级：导出申请、评测作业、白名单 split（[消费 02 §4](../06-消费域/02-下游评测执行与L4收益.md)） |
| 标注团队 | 生产域标注、治理域抽检 | 人工标注、质检复核 | 标注任务级：只见已脱敏数据（治理 07 §5 红线） |
| 平台运维 | 管控域、横切 | 调度/资源/配额/可观测 | 配额调整走审批（联动 [本域 03](03-多租户与计量计费.md)），不许直改 |
| 合规 | 治理域 | 脱敏规则、审计、合规门审批 | 策略版本评审、豁免审批、审计查询 |

- **最小权限，默认拒绝**：没授予的就是禁止的——角色是起点不是套餐，跨域操作逐项授权（运维能调资源但看不了未脱敏数据，合规能审计但不能改作业）
- **权限变更留痕**：每一次授权/回收入审计日志（§5）——权限是谁给的、什么时候给的，事后必须能回答

## 4. 作业准入钩子（三合一，拦截在控制面）

```
用户提交 PipelineSpec
        │
        ▼
【准入钩子 · 三合一检查】（提交时，静态）
   ① RBAC 授权：提交者对输入数据集/目标算子有权限？
   ② 合规检查：输入数据分级标记齐不齐？策略版本（治理 07 §3）评估过不过？
   ③ 配额预算：项目配额/预算余量够不够？（口径见 本域 03）
        │
   ├─ 任一不过 ──► 拒绝下发 + 原因入审计（结构性失败，不重试，算子-03 §7）
   └─ 全过 ──► 编译为 RayJob + Workload ──► Kueue 运行时配额闸门（管控 02 §3 L1）
```

- **不合格不下发**：违规作业拦在控制面，不进队列不占资源——**最省的一刀**（对齐 [算子-06](../02-生产域/算子设计/算子设计-06-算子成本模型.md) §3 规则前置：能在提交时挡住，就不让 GPU 为违规作业点卯）
- **与 Kueue 不重复**：钩子管「该不该跑」（权限/合规/预算，提交时静态判），Kueue 管「什么时候跑」（配额/优先级，运行时动态判）——两级闸门各司其职，钩子不替代 Kueue（[管控 02 §3](../03-管控域/02-调度与多租户.md) 四级链）
- **准入结果入审计**：拒绝与放行都留痕（谁提交的、查了什么、依据哪个策略版本）——放行记录是事后追责的起点

## 5. 审计日志（append-only 基础设施）

- **三类日志**（[治理 07 §8](../04-治理域/07-合规引擎.md) 原文口径，本篇是基础设施提供方，报告出口在治理）：**操作**（谁改了策略/阈值/版本状态）、**访问**（谁读了哪个 split/版本）、**导出**（谁把什么导去了哪，含外部 API 调用）
- **必须覆盖的动作**：版本晋升、数据集导出、权限变更、门禁审批、配额调整、准入拒绝——**没有审计版的动作等于没发生**
- **不可篡改、不可关停**：追加写 + 哈希链（或外部存证，实现通识沿治理 07 §8）——审计日志被改 = 审计失效；删除/覆盖本身也要留痕
- **与可观测分仓联动**：审计日志是 [本域 01](01-可观测性.md) 日志三仓之一（算子/作业/审计），存储归观测平台、口径与出口归本篇与治理 07——不建两套日志

## 6. 脱敏执行强制与合规门

- **前置纪律是规则，强制是执行**：顺序红线「脱敏 → 人工标注台 → 外部 VLM API」定义在 [治理 07 §5](../04-治理域/07-合规引擎.md)——本篇管它走不通旁路
- **DAG 前插位置强制**：涉敏输入的 PipelineSpec，脱敏算子（`op-pre-desensitize`）位置由准入钩子校验——**排后面了就是提交失败**，不靠自觉
- **覆盖校验 + P0 硬告警**：脱敏漏网（G1 覆盖不达标/G4 违规）触发 [本域 01](01-可观测性.md) P0 硬告警——**不许静默、不许自动恢复，只有人确认才能消**
- **脱敏版本入三锁**：用哪版脱敏算子处理哪批数据，随 [算子-04](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md) 三锁锁定——脱敏算法升级 = 数据血缘变更，走回归
- **合规门与出境控制点执行**：版本晋升前的合规审批（治理 07 合规门）、出境检查项（存储区域标记/出境清单/导出审计，治理 07 §7）——审批与口径在治理，检查项执行落本篇

## 7. 关键字段示意

```yaml
security_enforcement:             # 设计通识（字段以实现为准）
  rbac:
    roles: [data-eng, algo, annotator, ops, compliance]   # 总线附录 C 五角色
    resource_scope: [project, dataset, version, job, split] # 资源粒度
    default: deny                 # 最小权限：默认拒绝
  admission_hook:                 # PipelineSpec 提交时三合一
    checks: [rbac, compliance_policy@v, quota_budget]
    on_reject: {classify: structural_no_retry, audit: true} # 算子-03 §7
  audit_log:
    categories: [operation, access, export]               # 治理 07 §8 三类
    immutability: {append_only: true, hash_chain: true}   # 不可篡改不可关停
  desensitize_enforce:
    dag_check: pre_insert_position_mandatory              # 前插位置强制
    coverage_alert: {level: P0, auto_resolve: false}      # 漏网=P0，人确认才消
```

## 10. 红线与速讲话术

**红线**：

1. **规则不重定义**：合规规则 SSOT 在治理 07，本篇只执行强制——横切重写规则 = 口径漂移的第二裁判
2. **最小权限默认拒绝**：没授予的就是禁止的——「图方便全开权限」是数据平台的万恶之源
3. **审计不可篡改、不可关停**：append-only 且删除/覆盖留痕——能被关掉的审计保护不了任何人（同治理 07 红线 4）
4. **准入不合格不下发**：违规作业拦在控制面，不进队列——让 GPU 为违规作业点卯是最贵的错误（对齐算子-06 规则前置）
5. **脱敏漏网 P0 硬告警**：不静默、不自动消解，只有人确认才能消（联动本域 01 告警纪律）
6. **权限变更与门禁审批必留痕**：谁授权的、谁批的、依据什么——事后必须能回答，没留痕等于没发生

**速讲话术（30 秒）**：

> "安全合规我做成横切的执行强制层，核心纪律是规则和执行分离：规则全在治理域的合规引擎——策略即代码、分级分类、脱敏前置——我不重写规则，只保证不按规则走不通。权限是 RBAC，以总线附录 C 五角色为底表，数据工程师、算法、标注、运维、合规各管各的操作域，细化到数据集、版本、作业、split 粒度，默认拒绝、变更留痕。作业提交时过三合一准入钩子：权限够不够、合规标记齐不齐、预算够不够，任一不过直接拒绝、原因入审计，拦在控制面——这是规则前置的思路，不让违规作业进队列烧 GPU；它和 Kueue 不重复，钩子管该不该跑，Kueue 管什么时候跑。审计日志三类：操作、访问、导出，append-only 加哈希链，不可篡改不可关停，和可观测的日志中心分仓但不建两套。脱敏是执行强制：涉敏管线的脱敏算子前插位置在提交时校验，排后面就提交失败，漏网是 P0 硬告警只有人能消，脱敏算子版本进三锁。这套就是 XLB 管理面安全纪律的搬运：鉴权在入口、安审在下发前、操作审计在身后、强制路径无旁路——被管对象从配置换成数据与作业。"
