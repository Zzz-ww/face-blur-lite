# 03 · 多租户与计量计费（项目模型 / 计量 / 预算治理 / 配额治理视图 / 租户隔离）

> 90-横切第 3 篇（本域收尾篇）。定位：**六域共用的计量与预算治理层**——谁用了多少算力/存储/带宽/人力、花了多少钱、预算怎么管；配额执行归管控域，本篇管「配额从哪来（预算）、花了多少（计量）、谁买单（账单）」。横切不是第七域，是注入六域的底座。边界：配额调度执行（Kueue / ElasticQuotaTree）= [管控 02 §4](../03-管控域/02-调度与多租户.md)（**执行 SSOT**）；成本口径（GPU 秒/样本）= [算子-06 §1](../02-生产域/算子设计/算子设计-06-算子成本模型.md)（**口径 SSOT，本篇只聚合不重定义**）；存储分层成本 = [资产 04 §8](../05-资产域/04-冷热分层与TTL.md)（引 SSOT 不重算）；权限矩阵 = [本域 02](02-安全合规.md)（SSOT）。**核心纪律：本篇是「账房」，不是「调度器」。**

## 1. 定位与边界

- **本篇管**：**项目/租户模型**（项目 = 计费与配额单元）、**计量**（算力/存储/带宽/人力四类用量的聚合与对账）、**预算治理**（申请/审批/超支熔断）、**配额治理视图**（预算→配额→用量→账单闭环）、**租户隔离视图**（数据 + 作业隔离的账房视角）
- **不管**：配额怎么调度（管控 02 Kueue，SSOT）；成本口径怎么定（算子-06，SSOT）；权限怎么判（本域 02 RBAC，SSOT）
- **一句话**：管控域是闸门，本篇是账房——**闸门放行的每一分资源，账房都要能算到项目头上**；配额不是免费的，是从预算里来的

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 项目/租户登记 | 计费与配额单元管理 | 数据集/作业/模型版本的归属主体（§3） |
| 计量聚合器 | 四类用量归集到项目 | 算力（算子-06 口径）/存储/带宽/人力（§4） |
| 预算治理台 | 预算申请/审批/核算 | 配额的来源；超支熔断（§5） |
| 配额治理视图 | 预算→配额→用量→账单闭环 | 配额调整走审批留痕（§6） |
| 账单与对账 | 项目账单出具与口径核对 | 计量与真实成本一致（联动 [本域 01](01-可观测性.md) 成本视图） |

> **与负载均衡/控制面同构**：这套就是**云账房的计量计费闭环**——计量 ≈ 流量计量与带宽计费（先有逐流量的精准计量，才谈得上按 GB 计费；算子级 GPU 秒/样本就是「逐流量」粒度）；预算熔断 ≈ 客户配额与欠费停机（余额耗尽停的是新会话，不掐在途会话——本篇熔断停的也是新作业准入，不杀运行中的）；配额治理视图 ≈ 容量规划闭环（预算→采购→上架→用量→账单，每一环可对账）；租户隔离 ≈ 多租户系统的硬隔离（一个租户看不到另一个的用量与数据是底线不是 feature）。被管对象从流量换成算力/存储/人力，账房语言一字不改。

## 3. 项目/租户模型（计费与配额单元）

- **项目是归属主体**：数据集目录、作业、模型版本都挂项目——[资产 02](../05-资产域/02-数据集目录与检索.md) 目录有归属，[消费 02 §4](../06-消费域/02-下游评测执行与L4收益.md) 评测作业有归属，成本才归得拢
- **层级模型**：平台 → 组织/团队 → 项目——对齐 [管控 02 §4.2](../03-管控域/02-调度与多租户.md) 层级弹性配额树（ElasticQuotaTree 理念：父池下挂子池，保底+借用+回收），**账房层级与配额树层级同构**，不然账算不平
- **与 RBAC 联动**：角色在项目内继承（[本域 02](02-安全合规.md) 五角色底表 + 项目内授权）——权限判「能不能做」，计量记「做了多少」，两者对同一资源主体（项目）说话

## 4. 计量（四类用量，只聚合不重定义）

| 计量类 | 口径来源 | 聚合链 |
| --- | --- | --- |
| **算力** | GPU 秒/样本 × 单价 = [算子-06 §1](../02-生产域/算子设计/算子设计-06-算子成本模型.md)（SSOT） | 算子成本 → 数据集成本 → 项目成本（[本域 01](01-可观测性.md) 成本视图同链） |
| **存储** | 三层分层用量 = [资产 04 §3](../05-资产域/04-冷热分层与TTL.md)（热/温/冷单价不同） | 数据集/版本占用 → 项目存储账单 |
| **带宽** | 上云/导出流量（[接入 03](../01-接入域/03-源头校验与上云.md) 批传、[消费 01](../06-消费域/01-训练导出与模型平台衔接.md) 导出） | 按项目归集出入口流量 |
| **人力** | 人工标注小时（[标注体系-01](../02-生产域/标注体系/01-自动标注与人工标注台.md)） | 标注任务 → 项目人力成本 |

- **口径纪律**：每类计量只引 SSOT（算子-06 / 资产 04），本篇做的是**乘单价、归项目、出账单**——重定义口径 = 账单对不上真实成本
- **计量与账单对账**：聚合成本与真实账单（云厂商/内部核算）定期核对，偏差入 [本域 01](01-可观测性.md) 成本视图准确率指标——**对不上的账就是错的账**

## 5. 预算治理（配额的来源）

- **预算申请/审批流**：项目立项时申报周期预算（算力/存储/人力分列）——审批通过才有配额，**配额不是平台送的，是预算换的**
- **超支熔断是硬约束**：预算耗尽 = 暂停该项目**新作业准入**（联动 [本域 02](02-安全合规.md) 准入钩子的配额预算检查）——不杀运行中作业、不删数据，但新花钱的门关上；想继续走追加预算审批，不走「先跑着再说」
- **按项目/周期核算**：预算执行率（用量/预算）周期复盘——长期低执行率的配额回收再分配（对齐管控 02 §5.3 借用公平：配额是公共资源不是领地）

## 6. 配额治理视图与租户隔离

```
预算（本篇 §5）──► 配额（管控 02 §4：ClusterQueue nominalQuota/borrowingLimit）
                     │  Kueue 执行准入（运行时闸门）
                     ▼
                  用量（本篇 §4 计量：算力/存储/带宽/人力）
                     │  聚合到项目
                     ▼
                  账单与预算执行率 ──► 反哺下一周期预算/配额调整（走审批）
```

- **闭环要点**：预算、配额、用量、账单四环相扣，任何一环对不上就能定位到责任方（预算批少了/配额设错了/计量漏了/账单错了）——**配额调整必走审批留审计痕**（谁加的配额、为什么，[本域 02](02-安全合规.md) 审计覆盖动作）
- **租户隔离（账房视角）**：数据隔离（目录/版本/split 权限，本域 02 RBAC）+ 作业隔离（namespace/资源池，[管控 02 §4.3](../03-管控域/02-调度与多租户.md) 执行）+ **计量隔离**（一个项目的成本绝不允许算到另一个头上）——隔离不可绕过，越权访问与成本串账都是 P0 事件（联动 [本域 01](01-可观测性.md) 告警）

## 10. 红线与面试话术

**红线**：

1. **计量口径 SSOT 不重复**：算力成本只在算子-06 定义、存储只在资产 04——本篇重定义口径 = 账单对不上真实成本
2. **配额执行不越界**：Kueue 调度归管控域，本篇只做预算与计量——账房指挥闸门 = 两头都乱
3. **超支熔断是硬约束**：预算耗尽停新作业准入，不手软不放行——「先跑着再说」是成本失控的起点
4. **配额调整必审批留痕**：谁加的配额、为什么、何时——无审批的配额变更 = 资源黑箱
5. **租户隔离不可绕过**：数据、作业、计量三层隔离，越权与串账都是 P0——租户信任是平台化的前提
6. **账单必对账**：计量聚合与真实成本定期核对，对不上的账就是错的账——对账偏差是告警不是报表注脚

**面试话术（30 秒）**：

> "多租户计量我按账房做，核心是三条 SSOT 边界：成本口径在生产域算子成本模型——GPU 秒/样本，我只聚合不重定义；配额执行在管控域 Kueue——nominalQuota 保底加借用，我不碰调度；权限在本域安全篇——我只按项目记账。项目是计费与配额单元，层级对齐配额树，数据集、作业、模型版本都有归属，成本才归得拢。计量四类：算力按算子级 GPU 秒聚合到数据集再到项目，存储按资产域三层冷热分档计价，带宽算上云导出，人力算标注小时——每类口径都引 SSOT，账单和真实成本定期对账。预算是配额的来源：立项审批、周期核算，超支熔断是硬约束——预算耗尽停的是新作业准入，不杀运行中的，想继续走追加审批。配额治理是个闭环：预算到配额到用量到账单，任何一环对不上都能定位责任方，配额调整必走审批留审计痕。这套就是云账房计量计费的搬运：逐流量计量、配额欠费停机、容量规划闭环——被管对象从流量换成算力、存储和人力。"
