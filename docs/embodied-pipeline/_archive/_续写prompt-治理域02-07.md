# 六篇核心内容与口径（直接采信，避免编造）

## 02-血缘制品与版本三锁（深化算子-04，不重抄其单条 Schema）
- 算子-04 已给「三锁（op/data/model）+ 每样本一条 produced_by 记录」；本篇讲**图如何聚合、查询、审计、应用**。
- 血缘图模型（DAG）：节点类型（数据集/样本/算子/模型/作业/版本），边类型（produced_by 产出、derived 派生、consumed_by 被训练消费）；每样本血缘 → 聚合为**版本级 lineage_graph**，作为 DatasetVersion 组成（引 01 篇 §4）。
- 两类查询：**正向溯源**（这条样本/版本怎么来的，复现路径）；**反向影响面 blast radius**（某算子/模型/数据有缺陷，波及哪些版本、哪些训练、哪些下游）。
- 应用：可复现（三锁+config_snapshot+hash）、Badcase 定位（下游失败→回溯→定位算子/模型版本）、影响面分析、泄漏审计（去重/切分算子痕迹，链 06）。
- 血缘完整性：断链检测（每个样本都有完整 produced_by 链）、血缘与 manifest 一致性校验；血缘存元数据服务（图库/关系库），与数据文件分离。
- 可引用总线已核实的 RoboLineage（arXiv 2606.22142，类型化血缘制品，标已核实）；给出血缘查询 API 示意（get_lineage / find_impact / trace_badcase，字段以实现为准）。

## 03-质量门禁G0-G6（深化算子-02 §9，不重抄 G0–G6 表）
- 算子-02 §9 已给 G0–G6 位置/检查项/阈值/失败处理；本篇讲**门禁作为治理裁决如何编排、签批、留痕、治阈值**。
- 门禁引擎：门禁是晋升闸门（不是算子内部检查）；门禁结果持久化为 `gate_result` 制品（gate_id/version/检查项/阈值/实测值/结论/时间/签批方）。
- 软门 vs 硬门：硬门（G4 违规率=0、G5 泄漏=0、G6 回归无倒退，不过即阻断/回滚）vs 软门（G2/G3 质量阈值，可回流/人工修复后重试）；G0/G1 源头门。
- 阈值治理：阈值默认建议值可配置、阈值本身版本化；例外/豁免必须走审批工单 + 留痕 + 有期限，禁止静默放行。
- 抽检统计：分层抽检比例要有样本量/置信度依据（避免「抽检通过」无统计意义）；门禁误判分假阳（误拦）/假阴（漏放，代价更大）。
- 分工：G0–G4 算子/阶段级（生产执行）、G5 封装/泄漏、G6 发布回归（治理裁决）；自动门规则签批，发布门人工签批（05 篇）。
- 门禁与回流闭环：失败→血缘定位→重跑/人工/模型修复→回归。

## 04-四层评测体系L1-L4（展开总线 §6 那张表，给每层完整指标与 GT 来源）
- L1 算法质量：手部 ATE、重建成功率、6DoF ADD、深度一致性、分割 IoU 等（具体指标按各模型卡引用，不要编造数值）；L2 管线工程：通吃率/人工介入率/违规率/端到端成功率；L3 性能成本：GPU 秒/样本/吞吐/失败率/队列延迟（成本 SSOT 算子-06）；L4 下游收益：VLA/策略任务成功率、数据消融（ablation）增益。
- 每层四要素：**指标定义 / GT 来源 / 评测频率 / 阻断性**（L1/L2 硬、L4 不硬，只作收益证据）。
- 三套 GT 在 L1–L4 的分工（重点，引仿真 GT 旁路）：仿真合成 GT 主评测（全真值、可算几何误差）、伪 GT 补真实域、真实 Hold-out 精标做最终结论，用途不可混用；L1 的几何指标主要在仿真 GT 上可精确算，真实域靠 Hold-out 抽检。
- 评测隔离：Golden/Hold-out 评测集绝不进训练（链 06）；评测集管理链 05。
- L4 消融与归因：哪类数据/哪个子集带来下游提升，指导补采方向（数据增益归因）；L4 由消费域跑训练评测，治理域定评测标准并归档报告。
- EvaluationReport 制品结构：l1/l2/l3/l4 指标 + GT 来源 + 回归基线对比 + 回流建议（字段以实现为准）。

## 05-回归与发布（全新，G6 与发布审批展开）
- 版本回归：三锁任一变更（算子升级/模型替换/数据增删）触发，在 Golden Set 上跑全指标、对比基线，关键指标无倒退才放行（G6）。
- 回归基线：每算子/每层质量指标记录基线（baseline），基线版本随 Golden Set 受控更新；指标对比要给容忍度/显著性（避免噪声抖动当倒退）。
- 发布审批流：Validated → G6 回归 → 发布检查清单（三锁齐/泄漏=0/违规=0/评测达标）→ 审批（规则自动门 + 人工发布门）→ Published（链 01 篇状态机）。
- 发布物料：DatasetVersion 晋升令牌、release notes（版本 diff）、EvaluationReport、下游兼容说明；发布是受控变更（change record）。
- 回滚：发布后发现倒退/缺陷，默认版本指针切回稳定版（链 01 篇 §6，不删历史）。
- Golden Set 管理：固定版本、防过拟合、受控扩充走评审 + 全量重基准（引算子-07 §5）；可补「灰度/canary：新版本先小比例下游验证」为可选（标通识）。

## 06-数据分流与防泄漏（深化算子-07，算子三道防线引用不复制）
- 算子-07 已给四集定义、算子层分流（op-stat-sample）、三道防线、泄漏检测；本篇讲**泄漏类型体系、治理审计、访问隔离、泄漏事件响应**。
- 泄漏类型系统：跨集重复（同/近重复）、时间泄漏（同采集会话/连续帧跨集）、本体/场景泄漏（同本体/同场景跨集）、标注泄漏（标注泄漏答案）、指令/语义泄漏（相似指令/模板跨集）。
- 治理侧：发布前泄漏审计（G5/G6）+ 定期 embedding 相似度审计 + 血缘交叉核验（去重/切分算子执行痕迹）。
- split 访问隔离：消费侧按 split 授权，test/hold-out 严格限制访问（谁能看哪个集合）；训练/评测侧防泄漏责任延伸到消费域。
- 泄漏事件响应：发现泄漏→停止发布/撤回版本（01 篇）→血缘影响面（02 篇）→重切分/重训→重新回归（05）。
- 四集用途严禁混淆（训练迭代/验证调参/测试一次性结论/Golden 回归）；从严口径（按会话/场景分组、同本体同场景只落一个集合）作为治理选择说明。

## 07-合规引擎（全新，聚焦工程机制，不做法律意见）
- 合规引擎（policy engine）：策略即代码（policy-as-code），可版本化、可测试、可审计；违规在 G1/G4 拦截。
- 数据分级分类（公开/内部/敏感/个人信息）；PII 检测（人脸/人像、姓名、位置、声音、设备标识）。
- 隐私脱敏：人脸/人像脱敏（G1 覆盖检查、G4 违规率=0 硬红线）；**脱敏前置**——脱敏先于人工标注台、先于外部 VLM API（人/外部 API 都是数据出域消费者）。
- 采集合规：授权同意（consent）、采集范围与知情；数据留存与删除（留存期限、TTL、删除请求的传播与凭证）。
- 跨境/出境：数据本地化、出境清单与评估（只给工程控制点与「需法务/安全确认」，不编造具体法条）。
- 审计：操作/访问/导出审计，不可篡改审计日志（谁在何时访问/导出了什么），与血缘联动。
- 合规报告（给监管/内审的数据处理记录）；明确法规条款（如个人信息保护法/GDPR）只作为背景提及并标注「需法务确认」，工程文档只承诺机制。
