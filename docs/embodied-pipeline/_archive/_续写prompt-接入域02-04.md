## 第 2 篇：`02-多源接入适配器.md`

**主题**：各源怎么接进来——四源适配器的形态与职责，对接算子-05 差异矩阵的**接入侧动作**（时间同步/标定/字段归一），仿真 GT 旁路入口。

**定位句**：源与设备在 01 已登记，本篇把「源数据」变成「统一形态的原始信号」——四源各自适配、字段归一、时间同步与标定在此层执行、仿真 GT 旁路在此开入口。

**边界（不管）**：源/设备登记（本域 01）；源头校验与上云（本域 03）；算子执行（生产域）；调度（管控域）。

**必须覆盖的正文要点**：

1. **四源适配器形态**：第一视角 ego（视频导入：AR/头显/互联网视频，格式归一 mp4→帧流）；遥操作（rosbag 回放解析：话题/时间戳/坐标系，联合标定，真值直读）；仿真（仿真器对接：渲染管线输出直接映射，**GT 旁路入口**——深度/位姿/分割 GT 直出）；动捕（SDK/传感器直采：marker/IMU 流，动作对齐）。每源一张表或小节：输入形态/适配动作/输出。
2. **字段归一**：四源异构字段 → 统一 RawDataPackage 形态（source_type/schema/时基/合规标记）——适配器是"方言翻译层"，翻译错 = 下游全链错。
3. **时间同步与标定（接入侧执行）**：算子-05 §2 矩阵第一行"四源必需"的落地——多传感器对齐、联合标定（相机-关节/手眼）；同步偏差与标定版本随数据记录。
4. **GT 旁路入口（具身特色）**：仿真源在接入层就分离出 GT 通道（不混入感知重建流）——GT 旁路数据的 label_source=sim_GT 标记在这里打上；旁路与真机源的配比（CloudRobo 20% 真机/80% 生成口径为业内参照）。
5. **适配器是配置不是代码**：源类型 × 设备型号 → 适配器配置（设备能力路由），新设备加配置不加代码；适配器版本参与三锁（算子-04）。
6. 红线：字段归一不丢不篡（方言翻译错了全链错）；GT 旁路标记在源头打；同步/标定不合格不跨适配层。

## 第 3 篇：`03-源头校验与上云.md`

**主题**：RawDataPackage 生成前的最后一关——源头完整性校验、schema 校验、合规标记核验（三查），以及数据上云（边缘缓存/断网续传/批传）。

**定位句**：02 把源数据归一成统一形态，本篇是「能不能跨域」的闸口——三查全过才生成 RawDataPackage，上云保吞吐与可靠，不合格源头就地拦截（最省 GPU 成本的一刀）。

**边界（不管）**：算子执行与 G0 门（生产域）；湖仓物理布局（资产域 01）；合规规则定义（治理 07）。

**必须覆盖的正文要点**：

1. **三查详解**：完整性（帧/流不丢不坏：帧连续性/时长校验/流完整性 hash）、schema（字段齐全/时基声明/合规标记就位）、合规（隐私源已打标——规则在治理 07，本篇执行核验）；三查任一不过 → 源头拦截（进隔离区/打回补采，不跨域）。
2. **拦截策略**：拦截在源头最省成本（算子-06 规则前置）；被拦截数据的状态（Quarantined，对接治理 01 生命周期）；拦截原因归档（供采集侧整改，形成采集质量反馈）。
3. **上云通道**：边缘缓存（断网续传/本地暂存）、批传（按批次/session 打包上传）、校验在传前传后各一次（传输完整性）；带宽与成本的权衡（GPU 侧不背 IO）。
4. **原始数据湖落位**：RawDataPackage 落原始数据湖（接入域视角：只写原始层）；湖仓物理布局/分区/元数据在资产域 01（本篇只负责"放进去"，不重写布局）。
5. **字段示意**：raw_package_manifest（三查结果/传输记录/存储位置）。
6. 红线：三查不全不跨域；拦截原因必归档；上云必验传输完整性；原始层只读不加工（加工在生产域）。

## 第 4 篇：`04-采集工厂与容量排产.md`

**主题**：真机采集工厂的运营视角——异构设备集群、采集任务编排、容量排产与设备利用率，对接"采集侧编排 vs 管控域管线调度"的边界。

**定位句**：源、设备、适配、校验都就位后，本篇回答**"一批采集任务怎么排、设备怎么用满、产出怎么稳定"**——采集工厂是平台的产能源头，排产质量直接决定数据产量与成本。

**边界（不管）**：管线算子调度（管控域）；数据质量门（生产域 G 门）；补采指令来源（治理域回流）。

**必须覆盖的正文要点**：

1. **工厂形态**：真机采集工厂（智域基石口径：万平工厂/400+ 机器人/10+ 异构硬件为业内参照）；多本体、多工位、多班次；设备健康与维护窗口。
2. **采集任务编排**：任务 = 场景脚本 × 设备 × 时间段；编排产出采集计划（批次/session）；任务下发到采集 Agent（边缘侧）。
3. **容量排产**：设备利用率、场景覆盖目标、批次优先级（补采任务优先——回流驱动，治理域指令）；排产约束：设备维护、标定周期、场景切换成本。
4. **与管控域的边界**：采集编排（接入域：设备/批次/产能）vs 管线调度（管控域：算子作业/GPU 队列）——**采集是产能侧，管线是算力侧**，两套调度通过 RawDataPackage 衔接，不互相接管。
5. **产能指标**：设备利用率、批次产出率、单批次时延、场景覆盖达成率——反馈到排产模型。
6. 红线：补采任务优先级受治理指令约束（不自行加塞）；设备健康不达标不排产；排产不越界管线调度；产能缺口反馈不隐瞒（缺数据如实上报）。
