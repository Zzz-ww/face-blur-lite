## 02-数据集目录与检索（Catalog / 数据发现 / 向量检索）
- 数据目录（Catalog / 数据地图）：数据集、版本、样本的登记、业务术语（glossary）、打标与分类；技术/业务/操作三类元数据统一管理。
- 多维检索：按任务类型、场景、本体、模态、标签、来源（label_source）、版本检索与浏览；样本预览、统计画像（profile）。
- 向量检索：样本/场景/指令 embedding 建索引（**落盘在 01 湖仓，索引在本篇**）；用途——找相似、辅助去重佐证、案例/素材挖掘、badcase 快速检索；与精确条件检索互补。
- 目录挂血缘：从目录可直接正向溯源（引治理 02，不重写）；目录与 01 物理布局、03 快照对齐。
- 业内参照（标已核实通识）：DataHub / OpenMetadata / Hive Metastore、DLF 数据目录；向量库 Milvus 等（**具体选型以实现为准**）。
- 边界：本篇管「怎么找到/浏览」，不管物理文件怎么存（01）、数据怎么冻结（03）。

## 03-不可变快照与训练样本快照（快照服务 / 时间旅行 / 训练可复现）
- 发布即快照：治理发布（DatasetVersion 令牌）触发资产物理快照；两层快照——**表格式快照（Iceberg 等 snapshot）+ 存储/对象快照**。
- CAS 物理实现：底层内容寻址 blob（引 01 §5），快照记录指针清单（manifest），不重复拷贝未变块。
- 版本回溯/时间旅行：按版本 ID 或时间点取数（物理恢复/只读挂载）。
- **训练样本快照（重点）**：每次训练消费的精确样本集快照——DatasetVersion + split + 采样/过滤记录（含每样本引用），保证「同一份数据」可复现训练；与血缘 consumed_by 回写（治理 02）呼应。
- 与治理版本分工：治理定版本合法性、默认指针、晋升；资产做物理快照、保留、恢复（不重复治理规则）。
- 快照恢复演练与保留策略；快照本身不可变、只追加。

## 04-冷热分层与TTL（分层降本 / 缓存加速 / 归档与删除的物理执行）
- 存储分层：热（在线/SSD，高频训练）/ 温（标准对象存储）/ 冷（归档，低访问）；按访问频率、版本状态、时间自动迁移（生命周期策略）。
- 训练热点加速：本地 NVMe / 缓存集群预热热点数据，供训练高吞吐（引 01 §2 加速层；05 供数）。
- TTL 物理执行：到期归档或删除；**删除/留存决策来自治理 07（合规）、生命周期状态来自治理 01，资产只执行物理动作并回写结果/凭证**。
- 归档可恢复（恢复时延/成本权衡）；冷数据的元数据/血缘仍在线（不随数据归档）。
- 成本视角：分层与去重（CAS）共同降本；口径引算子-06，不重算。
- 边界：状态机/规则在治理，物理迁移/删除在资产。

## 05-TrainingRelease装配与导出（资产域唯一制品，重点）
- 制品定义（总线 §4.1）：TrainingRelease = 按 split 导出的 train/val/test/golden，含 split 指针、版本引用、配额统计。
- 装配流程：从 Published DatasetVersion 取数 → 按 split 组织（01 分区）→ 生成 release manifest（split 指针、文件清单、版本精确引用）。
- 准入校验（**资产→消费契约**，总线 §4.2）：**split 隔离 + 防泄漏检查**（检测手段引算子-07 §4，不重写）；不过不导出。
- 训练供数：数据本地化/预取、流式加载、缓存预热（与 04 加速层联动）；明确与消费域边界——**资产装配到 TrainingRelease 并保证供数通道，加载后的训练/评测在消费域**。
- 导出最小授权：test/hold-out 按白名单导出（引治理 06 split RBAC）。
- 给 TrainingRelease 字段示意（release_id / dataset_version / split 指针 / 配额统计 / 校验结果，字段以实现为准）。
