# 算子设计 09 · 具身在线算子调用与结果契约

**设计稿，2026-11-24。** 调用方提交已采集的视频片段，服务异步返回结果。首期覆盖手部重建 `op-per-hand` 和相机位姿 `op-per-cam`。下面是待实现的项目接口，样例采用虚构的不可变引用与结果。外部产品的真实字段单列于[火山 LAS 调研](../../92-调研笔记/调研笔记-06-火山LAS具身在线算子拆解.md)。后台状态转换沿用[执行与编排规范](算子设计-03-算子执行与编排规范.md)。

## 1. 调用者选择什么

| 请求项 | 语义 |
| --- | --- |
| 算子与输入 | 固定 `op_id`、`op_version` 和模型版本。输入绑定 `sample_id`、不可变媒体视图、源时间基准、半开区间和标定版本。受理时校验媒体访问权限、区间、视图与标定是否匹配。 |
| 相机产物 | `camera_pose` 提供逐帧相机到局部世界的变换。标明参考视图、轴向、矩阵方向、平移单位、尺度来源与局部世界 ID。深度和动态不确定性按后端能力另作可选信号。 |
| 手部产物 | 可请求像素关键点 `hand_2d`、相机系关键点 `hand_cam`、局部世界关键点 `hand_world`。MANO 参数、腕相对关键点如需交付须另行声明，分别记录表示方法、关节序和单位。 |
| 世界坐标路径 | `pose_source=external` 固定可读取的相机结果引用；`internal` 登记手部模型实际生成的位姿与局部世界 ID。只请求二维时可省略此项。分别固定必需和可选产物，必需项覆盖要求写入有版本的质量策略。 |

本例沿用 `raw-017` 的双目样本 `s-ego-001`，两次单目推理都取左视图。源帧区间为 `[0,600)`，时间基准为 `tb-30fps-v1`。实际可变帧率视频按 PTS 映射；切片、重采样、去畸变须保留回到源时间和像素的映射。按时间基准、视图和采样帧关联手部与位姿。[样本身份与宽表](../../05-资产域/06-样本宽表与增量物化.md)

接口采用两个逻辑操作。提交返回 `task_id` 和当前执行状态；查询按租户和任务 ID 返回进度、失败原因或终态清单引用。获取清单及其指向的对象时校验样本读权限。下面为方便阅读，将查询结果与对应清单摘录并排放在同一个 JSON 中。

## 2. 一次相机调用

请求示例。引用 `raw-017/left@1` 代表已登记的媒体视图，`rig-017@1` 可解析到与该视图一致的标定。

```json
{
  "request_key": "cam-001-a", "op_id": "op-per-cam", "op_version": "1.1.0",
  "model_version": "megasam-baseline-1", "sample_id": "s-ego-001",
  "media_ref": "raw-017/left@1", "calibration_ref": "rig-017@1",
  "time_range": {"start_tick": 0, "end_tick": 600, "timebase_ref": "tb-30fps-v1"},
  "required": ["camera_pose"], "quality_policy": "cam-coverage@1"
}
```

受理后返回 `task_id=task-cam-01`。下面是终态查询及其清单摘录。两个区间表示跟踪有效，中间五帧丢失，仍使用同一已确认的局部世界。重定位产生新原点时，须另发世界 ID；跨段拼接另存对齐变换及质量证据。

```json
{
  "task_id": "task-cam-01", "execution_state": "Succeeded", "manifest_ref": "cam-manifest-002",
  "manifest": {
    "sample_id": "s-ego-001", "timebase_ref": "tb-30fps-v1", "lineage_ref": "lin-cam-002",
    "camera_pose": {"result_ref": "camera-002", "world_id": "world-cam-002",
      "reference_view": "left", "transform": "camera_to_world", "translation_unit": "m",
      "scale_source": "monocular_estimate", "valid_ranges": [[0,180],[185,600]],
      "invalid_ranges": [{"range": [180,185], "reason": "tracking_lost"}]}
  }
}
```

完整结果文件按源 tick 给出有效矩阵或无效原因。本例左相机轴为右、下、前，局部世界以首个有效相机为原点并沿用其轴向，采用齐次列向量。平移按米表达，尺度来自单目估计。与有标定的真值比较时，分别报告允许尺度对齐和固定尺度的误差。

## 3. 一次手部调用

同一视频中，操作者在理线，对面有人伸手，操作者的右手短暂出画。此例把像素和相机系手部结果列为必需，把世界系结果列为可选，并绑定上例的 `camera-002`。若消费方只接受世界轨迹，应在请求中把 `hand_world` 列为必需并选择相应的质量策略。

```json
{
  "request_key": "hand-001-a", "op_id": "op-per-hand", "op_version": "1.2.0",
  "model_version": "hawor_cvpr25", "sample_id": "s-ego-001",
  "media_ref": "raw-017/left@1", "calibration_ref": "rig-017@1",
  "time_range": {"start_tick": 0, "end_tick": 600, "timebase_ref": "tb-30fps-v1"},
  "required": ["hand_2d","hand_cam"], "optional": ["hand_world"],
  "pose_source": "external", "camera_pose_ref": "camera-002", "quality_policy": "ego-hand@1"
}
```

受理后返回 `task_id=task-hand-01`。终态和结果清单摘录如下。示例保留三个时刻的四条帧手记录。完整结果中另存坐标数组、关键点顺序、逐点有效标记、归属依据和缺失原因。`world_status` 按请求范围与目标轨迹汇总世界坐标覆盖，全部、部分、零覆盖分别记为 `complete / partial / unavailable`。

```json
{
  "task_id": "task-hand-01", "execution_state": "Succeeded", "manifest_ref": "hand-manifest-004",
  "manifest": {
    "sample_id": "s-ego-001", "timebase_ref": "tb-30fps-v1", "lineage_ref": "lin-hand-004",
    "result_ref": "hand-004", "pose_source": "external", "camera_pose_ref": "camera-002",
    "world_id": "world-cam-002", "world_status": "partial",
    "records": [
      {"tick": 170, "track_id": "h1", "handedness": "right", "owner": "wearer",
       "observation": "observed", "valid": {"hand_2d": true, "hand_cam": true, "hand_world": true}},
      {"tick": 182, "track_id": "h1", "handedness": "right", "owner": "wearer",
       "observation": "observed", "valid": {"hand_2d": true, "hand_cam": true, "hand_world": false},
       "reason": "camera_tracking_lost"},
      {"tick": 210, "track_id": "h1", "handedness": "right", "owner": "wearer",
       "observation": "missing", "valid": {"hand_2d": false, "hand_cam": false, "hand_world": false},
       "reason": "out_of_view"},
      {"tick": 210, "track_id": "h2", "handedness": "right", "owner": "unknown",
       "observation": "observed", "valid": {"hand_2d": true, "hand_cam": true, "hand_world": true}}
    ]
  }
}
```

- **身份**。手别描述左右，`track_id` 在本任务内关联轨迹，`owner` 取 `wearer / other / unknown`。调用方结合佩戴者证据或人工复核判断归属。第 210 帧虽有几何有效的右手，却缺少归属证据，排除于操作者右手训练集。
- **观测**。对预期轨迹在采样时刻记录直接观测、插值、模型补全或缺失（`observed / interpolated / inferred / missing`）。例如第 210 帧操作者自己的 `h1` 出画，如有补全则单列来源，无依据则记缺失。数值缺失用空值和原因表示。腕相对三维若缺相机系腕位置，无法直接变换成世界点。
- **消费**。世界点使用相同时间、视图、单位和轴向的 `camera_to_world` 变换相机系点，且使用者应能解析同一 `world_id`。先检查清单总体状态，再筛这只手、这一帧及所需关节的有效标记，最后执行任务的身份、覆盖率和补全准入策略。图像信号仍可单独进入相应质量门。

## 4. 重试、入湖和重算

| 事件 | 调用方和平台的约定 |
| --- | --- |
| 提交响应丢失、重复或并发提交 | `request_key` 按租户隔离。平台原子登记键、规范化请求指纹与任务 ID，同键同内容返回原 ID，同键异内容报告冲突。提交超时后用原键对账。 |
| 查询超时或执行失败 | 查询超时后按原 ID 退避续查。区分任务终态超时、临时资源故障和媒体/标定错误。可恢复执行沿原任务递增 attempt，从检查点重试；仅当前 attempt 能登记结果。需修正输入时用新键，保留前次关联。 |
| 部分有效或清单损坏 | `Succeeded` 表示本次声明的必需产物通过对应执行检查。可选世界轨迹可部分可用；必需覆盖不足则记录质检失败、隔离相关结果供复核。清单或大数组缺失、校验值不符时阻断登记，通过恢复流程补齐。 |
| 结果入湖 | 清单带 Schema 版本、各产物摘要、标定与坐标说明、逐帧质量和血缘。先复制或钉住不可变产物并校验，再受控提交样本信号和 `QCReport`。保留三锁、配置快照、输入指纹、物化键及模型权重摘要。托管后端若仅暴露 API 版本，记录可见版本和原始输出，底层权重标为未知，重放或复用按证据判断。 |
| MegaSaM 换成 DROID-W | 在外部位姿路径，新相机结果使 `hand_world` 及依赖它的动作、质检失效。若 `hand_2d`、`hand_cam` 的字段级物化键、输入和质量都满足复用条件，可沿用；只有整包键或缺依赖时保守扩大重算。HaWoR 内置路径的位姿随其自身依赖追踪。 |

任务 ID 用于查执行；样本 ID、结果引用和物化键分别定位样本、不可变输出和计算条件。世界轨迹只写入满足消费策略的区间。样本的其他字段可独立登记。数据集仍需通过适用门禁、G5、G6 和审批才能发布。[血缘与版本三锁](算子设计-04-算子血缘与版本三锁.md) · [增量物化与提交](../../05-资产域/06-样本宽表与增量物化.md) · [Ego 发布案例](../../00-总体架构/01-Ego数据资产化场景导读.md)

## 5. 首次验收怎么做

可先用[手部与相机在线算子验收样例集](验收样例/手部与相机在线算子验收样例集.md)回放四个设计窗口，核对轨迹身份、有效区间和坐标变换。以下指标用于接入真实素材及服务后的验收。

固定同一批获授权的片段、采样时间、标定、硬件、并发及冷热启动条件，分列正常理线、多人交叉、短时出画和相机跟踪中断。人工标记操作者、可见区间和部分关键点。有标定位姿真值的子集用于几何误差。首轮产出基线，阈值由目标任务据此选定。

| 验收问题 | 报告口径 |
| --- | --- |
| 请求是否及时完成？ | 排队时间取受理到开始。端到端延迟取受理到结果可读，报告成功任务 P50/P95、样本数，以及失败、超时、仍在途数。终态失败率按终态任务计，重试次数另列。 |
| 手是否跟对人、轨迹是否可用？ | 在已裁决归属的预测中，误归为操作者的其他人手数 / 被判为操作者的手数，按帧手计；单列未知率与漏检率。用同一批已标注目标时刻统计有效世界轨迹覆盖，直接观测与允许补全分别报告，分母为零记 N/A。 |
| 位姿后端如何比较？ | 同片比较跟踪中断次数、有效源时间覆盖、分段漂移。对有真值的片段按相同对齐方式计算绝对轨迹误差（ATE）及同时间间隔的相对位姿误差（RPE），记录平移单位和旋转单位。 |
| 合格数据花了多少钱？ | 对同一消费策略计量 `C_data/H_eff`，重试、失败、人工复核开销计入成本。合格帧映射到同一源时间轴再取区间并集；两手、重试和重复调用均去重。无合格小时报告支出和原因。[成本口径](算子设计-06-算子成本模型.md) |
