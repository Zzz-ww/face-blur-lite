## 1. 成本口径

| 指标 | 定义 |
| --- | --- |
| GPU 秒/样本 | 分摊的 GPU 占用/计费时间（含加载、空闲等待与失败重试）；活跃计算时间单列，不用利用率折扣账单 |
| CPU 秒/样本 | 区分分配的核秒、进程 CPU 时间和任务墙钟时间；报告必须声明采用哪一种 |
| 吞吐 | 样本/小时（分阶段） |
| 单小时数据成本 | 数据生产全成本 / 产出有效数据小时数；分母及费用边界统一见 §4–§6 |

## 3. 省钱策略（按优先级）

1. **规则前置**：去重/过滤/完整性校验先跑（CPU 便宜），拦截无效样本再进 GPU 环节
2. **分层采样**：对海量原始数据先抽样评估，再决定全量处理
3. **模型降级**：成本敏感环节用轻量替代（跨档替换为主，如位姿 MegaSaM→COLMAP；同档替换需实测）
4. **批处理与复用**：GPU Actor 常驻避免反复加载；同段先验结果复用
5. **缓存**：去畸变/脱敏等确定性算子结果按 hash 缓存
6. **成本监控**：每算子 GPU 秒/样本入监控，异动告警

## 4. 转化漏斗与有效小时（口径 SSOT，2026-11-19 增补）

本节为设计规范，尚未接入实际计量。沿同一来源批次、截止时间和选择规则统计：

`原始接入 → 通过筛选 → 完成加工 → 通过门禁 → 发布 → 实际训练消费`

| 阶段 | 小时集合 | 同时记录 |
| --- | --- | --- |
| 接入 | H_raw：收到并登记的源时间区间 | 损坏/缺失、不完整上传，采集设备和人工准备时间另列 |
| 筛选 | H_selected：进入本轮加工的区间 | 规则版本、拒绝原因、保留/复核/隔离去向 |
| 加工 | H_processed：所需信号齐备的区间 | 失败、重试、人工返工、尚在排队的积压 |
| 门禁 | H_valid：满足本次声明门禁的区间 | 质量门/来源/任务分层；本节默认 H_eff = H_valid |
| 发布 | H_released：纳入已发布清单的区间 | release/版本与样本清单 |
| 消费 | H_consumed：已交付并进入训练步骤的唯一区间 | 意图/预取/仅读与实际训练消费分开，已提交步与失败 attempt 分项；多 epoch 读取量另计 |

**分母规则**：

- 在同一 source/session 时间轴上取区间并集；多视角按同一采集实体的同步时间区间去重，重叠 Clip、复制、增广、重复 epoch 不增加独立小时。身份和时间基准见[资产06](../../05-资产域/06-样本宽表与增量物化.md)。
- 无可靠共享时间轴的源分别统计；真实、仿真、世界模型生成数据按来源分层。不把未知时长填成零或把图片条数按任意帧率换算为小时，改用样本数/轨迹数并声明单位。
- H_eff 表示技术门禁合格，不表示每小时都有已证实的训练收益。若比较发布/消费成本，必须显式使用 H_released/H_consumed，并写出与 H_valid 的差异。
- 邻接阶段转化率为 H_next/H_prev，分母为零报 N/A；同批次应满足集合包含关系。跨批拼接、合成新增源和返工重入分别建批次/来源账，不伪造成单调漏斗。
- 失败/筛掉数据的加工支出仍进入成本。重跑按物化键去重业务产出，按实际尝试累计资源支出。

## 5. 数据生产全成本与实验全投入

`C_data = C_compute + C_storage + C_requests + C_network + C_human`

- 计算覆盖 CPU/GPU 分配、加载/等待、失败重试与返工；共享资源按可解释的计量键分摊，并单列尚未分摊部分。
- 存储按保留窗口计费，包括热缓存、中间产物和历史版本；请求/网络不能因使用对象存储而忽略。
- 人力包含采集、标注、复核、纠错；同时报告人员小时和费用换算假设。若无法取得采集成本，明确本次仅报“加工成本”，不可称全生产成本。
- `C_h = C_data/H_eff`，单位为元/有效小时；H_eff=0 时不输出有限单价，保留实际支出与失败原因。
- `C_total = C_data + C_training + C_evaluation` 用于实验投入产出；训练/评测费用由模型平台回传，避免把数据加工费当成全部实验投入。共享历史预训练等是否计入要固定边界。

资源消耗与货币成本都保留，卡型、单价、币种和时间窗口固定后再比较；不能直接相加不同卡型的 GPU 小时作为等价成本。观测只展示本节定义，不另起公式。

## 6. 单位增益与边际投入产出

对固定任务分布，令 S 为任务成功率，以**百分点 pp**报告 ΔS，不混淆相对百分比。在同一基础数据/模型、声明的训练预算与相同评测套件下：

- 新增数据的边际单位增益 `U_add = (S_base+subset − S_base)/ΔH_eff`，单位 pp/新增有效小时。ΔH_eff 使用相对基线新增的唯一区间，不用重复训练次数扩大分母。
- 同时报原文建议的总体归一化口径时，用 `U_total = (S_candidate − S_reference)/H_eff,candidate`，仅在候选小时已知且大于零、来源与计时单位可比时计算，明确参考组及总小时分母；否则记 N/A 并报告 ΔS、样本量/轨迹数和成本。不能与 U_add 混排排名。
- 删除或替换数据、ΔH_eff≤0、来源单位不同，或有效时长未知时，不计算 U_add；报告 ΔS、样本/小时差异与成本差异。负收益如实保留，不能筛掉后只报正值。
- `R = ΔS/ΔC_total` 只在新增成本 ΔC_total>0 且费用边界一致时用于边际效率比较；零/负新增成本报告“增益—成本变化”二元结果，不输出无穷大或反号 ROI。它是任务指标的成本效率，不是财务利润率。

这些比值是条件性实验结果，不是数据的永久属性；基线模型、混训比例和目标任务变化后需要重评。实验条件、置信区间、训练随机性与分层报告见[消费02](../../06-消费域/02-下游评测执行与L4收益.md)；L4 保持收益证据定位，不新增硬阻断。
