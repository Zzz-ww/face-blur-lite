# 手部与相机在线算子验收样例集

给定相机清单和两个人的右手记录，消费方最终会把哪只手、哪几个时刻、哪个坐标系的结果写入训练候选？本页给出四个可复算的答案。它们共用[算子设计 09](../算子设计-09-具身在线算子调用与结果契约.md)的 `s-ego-001`，可从[样例 JSON](ego-hand-camera-v1.json)独立读取。

**证据状态（2026-11-24）**。目前没有实例真值。片段、身份、位姿中断和坐标均由样例指定，`media_binding` 为 `null`。这份材料可用于契约评审、适配器联调和消费规则回归。真实视频上的误认率、跟踪精度与服务时延均待实测。

## 1. 统一输入与判定方法

- **输入**。源为 `raw-017/left@1`（左目），标定 `rig-017@1`，源区间 `[0,600)`，固定 30 帧/秒。tick 从 0 开始，所有区间含起点、除终点。四例是同一任务清单上的四个验收窗口；继承原请求的媒体、时间基准、相机结果和手部结果。换成变帧率素材时须使用源 PTS 映射。
- **相机与手部**。先消费 `op-per-cam` 的 `camera-002`，再消费绑定该引用的 `op-per-hand` 输出。世界 ID 为 `world-cam-002`。`records[].range` 是相邻帧记录的压缩写法，展开后沿用契约的 `tick / track_id / owner / observation / valid`。参考视图、时间基准、相机引用或世界 ID 不匹配时，世界信号转入复核。
- **消费策略**。本轮只选佩戴者右手的直接观测，再分别检查 `hand_2d`、`hand_cam` 和 `hand_world`。世界信号还要求同 tick 的相机位姿有效。逐项比较 **（源 tick，轨迹 ID，信号）**，两个右手同时出现时，单看帧数会漏掉身份错误。本样例将目标手绑定为 `h1`；真实后端可使用其他轨迹 ID，评测时需先与已裁决的目标轨迹关联。

## 2. 四个验收窗口

| 场景与源区间 | 输入中故意安排的情况 | 应交付给操作者右手消费方 | 失败判定与去向 |
| --- | --- | --- | --- |
| 正常理线 `normal [168,173)` | `h1` 为佩戴者右手；第 169、170 帧也能看到佩戴者左手 `h3`。相机有效 | 三种信号均交付 `h1 [168,173)`，各 5 帧手。第 170 帧另核对腕部坐标 | 混入 `h3`，或世界点变换错误，记录手别或坐标适配失败 |
| 多人交叉 `crossing [196,201)` | 佩戴者 `h1` 和对面人的 `h2` 同时为右手，两条轨迹均有有效几何。此窗口给定证据足以判定 `h2=other` | 三种信号均只交付 `h1 [196,201)`，各 5 帧手 | 若 `h2` 顶替 `h1`，即使总数仍为 5 也判失败，送身份复核 |
| 右手出画 `out_of_view [208,214)` | `h1` 在 `[210,212)` 出画。`h2` 同时可见，此窗口归属证据不足，记 `unknown` | 三种信号均只交付 `h1 [208,210)` 和 `[212,214)`，各 4 帧手。缺口保留 `out_of_view`；未知轨迹留给复核 | 用旁人或补全值填作佩戴者实测即失败。即便另产有效的 `inferred` 结果，本轮直接观测策略也应排除这两帧 |
| 相机丢跟 `camera_lost [178,187)` | `h1` 全程可见；相机在 `[180,185)` 无效，第 185 帧起已恢复到同一局部世界 | 二维和相机系各交付 9 帧手；世界系只交付 `[178,180)` 和 `[185,187)`，共 4 帧手 | 第 182 帧写出有效世界点，或同时丢弃可用二维结果，均判失败。保留故障区间与原因；消费方若要求全窗世界轨迹，则该窗口不予交付 |

四窗合计 25 个源 tick。此策略应交付 23 个二维、23 个相机系和 18 个世界系目标帧手。第 180 帧属于丢跟区间，第 185 帧属于恢复区间。各窗的分母固定为窗口长度；这些计数仅用于逐项检查样例。验收结果可挂入 G2 的 `QCReport`，数据集发布仍按原有门禁执行。[质量门体系](../算子设计-02-算子接口规范与质量门体系.md)

## 3. 手算第 170 帧

样例把腕点设为相机系 `(0.1, 0.2, 0.5) m`。相机到世界的变换先绕 Z 轴转 90°，得到 `(-0.2, 0.1, 0.5) m`，再加平移 `(0.3, -0.1, 0.2) m`，预期为 **`(0.1, 0.0, 0.7) m`**。使用矩阵逆、遗漏平移或把米按毫米解释，都会偏离此结果。JSON 中的容差只覆盖这道算术题的浮点舍入。

## 4. 本地回放

在仓库根目录执行下方命令，使用 Python 标准库即可。命令展开四个窗口，分别对比每个信号的消费清单，然后检查腕点。与适配器联调时，固定 `expected_ranges` 和目标轨迹映射，用适配后的结果替换记录。

```sh
python3 - 'docs/embodied-pipeline/02-生产域/算子设计/验收样例/ego-hand-camera-v1.json' <<'PY'
import json
import math
import sys

with open(sys.argv[1], encoding="utf-8") as source:
    fixture = json.load(source)

camera = fixture["camera_pose"]
hand = fixture["hand_result"]
assert fixture["hand_request"]["camera_pose_ref"] == hand["camera_pose_ref"] == camera["result_ref"]
assert hand["world_id"] == camera["world_id"]
assert hand["reference_view"] == camera["reference_view"] == fixture["source"]["reference_view"]
time_range = fixture["source"]["time_range"]
assert hand["timebase_ref"] == camera["timebase_ref"] == time_range["timebase_ref"]
camera_ticks = {t for bounds in camera["valid_ranges"] for t in range(*bounds)}
lost_ticks = {t for gap in camera["invalid_ranges"] for t in range(*gap["range"])}
assert camera_ticks.isdisjoint(lost_ticks)
assert camera_ticks | lost_ticks == set(range(time_range["start_tick"], time_range["end_tick"]))
policy = fixture["consumer"]
target = fixture["expected_target_track_id"]
for case in fixture["cases"]:
    bounds = range(*case["range"])
    actual = {signal: [] for signal in case["expected_ranges"]}
    for record in case["records"]:
        for tick in range(*record["range"]):
            assert tick in bounds, (case["id"], tick)
            valid = record["valid"]
            if valid["hand_world"]:
                assert tick in camera_ticks and valid["hand_cam"], (case["id"], tick)
            if record["observation"] == "missing":
                assert not any(valid.values()), (case["id"], tick)
            if all(record[key] == value for key, value in policy.items()):
                for signal in actual:
                    if valid[signal]:
                        actual[signal].append((tick, record["track_id"]))
    for signal, ranges in case["expected_ranges"].items():
        expected = [(t, target) for interval in ranges for t in range(*interval)]
        assert sorted(actual[signal]) == sorted(expected), (case["id"], signal)
    print(case["id"], {signal: len(rows) for signal, rows in actual.items()})

probe = fixture["geometry_probe"]
assert probe["world_id"] == camera["world_id"] and probe["tick"] in camera_ticks
assert camera["transform"] == "camera_to_world" and camera["translation_unit"] == "m"
assert len(probe["camera_to_world"]) == 4 and all(len(row) == 4 for row in probe["camera_to_world"])
assert len(probe["point_camera_m"]) == len(probe["expected_point_world_m"]) == 3
point = [*probe["point_camera_m"], 1.0]
transformed = [sum(a * b for a, b in zip(row, point)) for row in probe["camera_to_world"]]
assert math.isclose(transformed[3], 1.0)
for value, expected in zip(transformed[:3], probe["expected_point_world_m"]):
    assert math.isclose(value, expected, rel_tol=0, abs_tol=probe["numeric_tolerance_m"])
print("腕点坐标通过", transformed[:3])
PY
```

## 5. 什么时候开始比较模型

| 想回答的问题 | 需要补齐的证据 |
| --- | --- |
| 模型能否识别操作者、出画和丢跟？ | 绑定可用于评测的真实片段与媒体摘要、相机视图和源 PTS。由人工逐段标记佩戴者身份、手别、出入画和可裁决区间，留下不确定项。相机丢跟可另用受控故障注入检查消费路径，并记录注入区间。 |
| MegaSaM 和 DROID-W 哪个后端更适用？ | 两者运行同一批片段、同一采样与标定。联调后可先记录端到端 P95、中断次数、覆盖和成本。有独立参考相机轨迹且时间、坐标和尺度对齐时，再报告 ATE/RPE。需公开参考素材时，可从 HOT3D-Clips 的训练划分筛选公开标注帧，其相机文件带相机到世界的变换；理线和多人交叉仍需按场景另行核验。[HOT3D-Clips 官方数据说明](https://github.com/facebookresearch/hot3d/blob/main/hot3d/clips/README.md) |

首轮真实报告应分开列出样本量、未裁决帧、操作者误认率、有效世界轨迹覆盖、服务 P95 和每合格小时成本。无对应证据的指标填“未测”，精度与成本的定义沿用[算子 09 验收口径](../算子设计-09-具身在线算子调用与结果契约.md#5-首次验收怎么做)。
