## 1. 定位与边界

- **本篇管**：标注的**生产线**——自动标注全量跑什么、人工介入哪几类、标注台怎么派单与留痕、效率怎么衡量
- **姊妹篇 02 管**：标注的**裁判席**——来源标记、四级质检漏斗、指标门禁、血缘溯源；本篇的人工队列正是其漏斗第 3/4 级的承接方
- **制品归属**：所有标注（自动与人工）汇入 `AnnotationSet`；本篇定义人工侧如何正确产出 `human_GT` 与 `human_fixed`，**不另造 schema**
- **域归属**：标注台是生产域「标注服务」组件，不是独立域；质检结论的裁决权在 02 与治理域门禁

## 2. 核心概念与术语

| 术语 | 含义 | 要点 |
| --- | --- | --- |
| 自动标注 | 模型/规则算子对全量样本产标注（`label_source = model / pseudo_GT`） | 必带 `confidence`；模型原理见模型卡 01–06，本篇不重复 |
| 预标注（pre-label） | 自动标注结果作为人工任务的**初始值**，人工只修正、不从零标 | 效率关键；采纳率是核心运营指标（§5） |
| 人机协同闭环 | 自动全量 → 门控分流 → 人工长尾 → 回流迭代的回路（§3） | 闭环转一圈，下一代自动标注更准 |
| 人工任务类型 | 人工不可替代的 5 类任务（§4.2） | 提示 / 复核 / 建模板 / 校对 / 精标 |
| 标注台 | 承接人工任务的平台：队列、界面、协同、管理、留痕（§4.3） | 生产域组件；具身特化界面需二次开发 |

## 3. 总体流程：人机协同闭环

```
① 自动标注全量（L2 模型卡 01–05 + L3 模型卡 06；label_source = model / pseudo_GT + confidence）
        │
        ▼
② 自动门控：置信度门 + 双模型互检 + 规则校验（全量、便宜 = 02 §4 漏斗前两级）
        │
        ├── 高置信 · 一致 ────────────► AnnotationSet（待 02 分层抽检）
        │
        └── 低置信 / 互检分歧 / 规则异常
                │
                ▼
③ 人工任务队列（智能路由派单；预标注打底——人工只修正，不从零标）
        │
        ▼
④ 写回 AnnotationSet（精标 → human_GT；修正 → human_fixed，留 edit_trace）
        │
        ▼
⑤ 回流：Badcase 按算子定位（算子设计-07）→ 模型/规则迭代 → 回到 ①（标注飞轮）
```

闭环里的两个「自动→人工」接口：② 的分流规则 = [02 §4 路由规则](02-标注质检与来源标记.md)（低置信 / 互检分歧 / 规则异常 → 人工队列）；⑤ 的回流通道 = 治理域血缘定位（`rejected / human_fixed` 按「数据+算子+模型」三锁找到责任算子）。

## 4. 关键机制

### 4.1 总原则：自动优先，人工只碰长尾

- **自动标注跑全量**（`model / pseudo_GT`），人工只做「提示 + 复核 + 建模板 + 校对 + 精标」五类任务（§4.2）——**通吃率是标注生产的第一 KPI**
- 成本逻辑：模型推理可摊销（GPU Actor 常驻，[算子设计-06](../算子设计/算子设计-06-算子成本模型.md)），**人工不可摊销**（每件任务单都是人力时间）——每压低一个百分点介入率，都是线性人力节省
- 与语义层「规则与生成分治」同构（[模型卡 06](../模型卡/06-语义标注-VLM.md)：高频动作用模板、VLM 只兜长尾）：标注层就是「自动兜全量、人工兜长尾」

### 4.2 人工不可替代的 5 类任务

| # | 任务 | 触发来源 | 对接模型/算子 | 产出 | 量级定位 |
| --- | --- | --- | --- | --- | --- |
| 1 | **首帧提示**（分割链冷启动） | 每个新样本进分割链；首帧质检门失败件 | [模型卡 04](../模型卡/04-分割跟踪-SAM2+TAPIR.md)：ego 路径 EgoHOS 自动出首帧 mask（人工校验/修正），开域路径 Grounded-SAM 需文本提示 | 合格首帧 mask（首帧质检门是硬门：带病禁止传播） | 每样本 1 次 + 失败重提示 |
| 2 | **低置信 / 互检分歧复核** | 置信度门（示例 <0.6，算子设计-02 §10）、`op-clean-crosseval` 分歧件 | 模型卡 01/02/03 等产出方 | 修正标注（`human_fixed`） | 长尾（介入率 ≤10% 目标内） |
| 3 | **少样本 6DoF 建模板** | 无 CAD 的新物体入库 | [模型卡 05](../模型卡/05-物体6DoF-FoundationPose.md) 少样本免 CAD 模式 | 物体参考图/模板（供 test-time 优化） | 每新物体 1 次 |
| 4 | **VLM 指令校对与子任务边界确认** | G3 指令抽检失败件 | [模型卡 06](../模型卡/06-语义标注-VLM.md)（GigaBrain「LLM 重写 + 人工多阶段 QC」同构） | 修正指令/片段边界 | 抽检量 |
| 5 | **Golden Set / 真实 Hold-out 精标** | 治理域回归（G6）与最终评测需求 | [总线 §5.3](../../00-总体架构/README.md) 三套 GT 之真实 Hold-out | `human_GT` 标尺（**冻结、只评测不训练**） | 小规模、最贵、最终标尺 |

5 类共同点：都是**模型做不了或做了不可信**的环节（冷启动提示、低置信仲裁、模板构建、语义把关、标尺精标），而不是「人工比模型便宜」。

### 4.3 标注台能力清单

| 能力 | 内容 | 要点 |
| --- | --- | --- |
| 任务队列与智能路由 | 按置信度/来源/类别/优先级派单（§4.4） | 高风险层高抽检率，呼应 02 分层抽检 |
| 预标注 | 模型先出 `pre_label`，人工只修正 | 效率关键；界面呈现「修正前/后」差异 |
| 多类标注界面 | 2D mask/关键点（任务 1/2）、3D 6DoF 位姿（任务 3）、动作片段切分（任务 4）、指令校对文本视图（任务 4） | 具身特化界面是自研重点 |
| 多人协同与进度 | 并行派单、任务状态机、积压/SLA 监控 | 积压是加人或回调阈值的信号 |
| 标注员管理与一致性 | 培训、标注规范、IAA / Cohen's Kappa 度量、盲抽交叉复核 | Kappa 建议 ≥0.8（团队自定） |
| 操作留痕 | `edit_trace` + `qc_trace`，每动作可审计 | 人工环节不可复现，留痕是唯一凭证 |

业内参照：Label Studio / CVAT 等开源标注平台覆盖队列/界面/协同/留痕的基础能力（设计通识）；具身特有的 6DoF 位姿修正、动作片段边界、指令校对界面通常需二次开发。

### 4.4 智能路由

- **路由维度**：置信度分位、label_source、类别、采集源、标注员技能与负载
- **派单原则**：贵任务派资深（Golden/精标、分歧仲裁），常规复核池化轮派；**分歧仲裁件优先级最高**（阻塞下游 G2/G3 门）
- **配额联动**：抽检任务量 = 02 分层抽检的层配额；精标任务量 = 治理域 Golden 预算——队列不是想标多少标多少

### 4.5 预标注与规则前置

- 预标注把人工从「生产者」变「校对者」——`action=accept`（直接采纳）比例即采纳率，采纳率越高说明自动侧越准、人工越省
- 规则前置同理由：确定性高的环节（腕速切分、模板化指令）交给规则，模型与人工都只兜长尾
- 与 [算子设计-06](../算子设计/算子设计-06-算子成本模型.md) 呼应：省成本的次序 = 规则替代模型 → 预标注省人工 → 通吃率升 → 介入率降

## 6. 数据结构与字段：人工任务单

任务单是标注台的**工单**，不是新制品——执行结果最终写回 `AnnotationSet`（schema 见 [02 §6](02-标注质检与来源标记.md)，本篇不另造一套）：

```yaml
human_task:                          # 人工任务单（派发与留痕的最小单元）
  task_id: <全局唯一>
  task_type: first_frame_prompt | lowconf_review | crosseval_review | template_build | instruct_review | golden_label
  item_ref: {dataset: <版本引用>, frame_id | seg_id | object_id | ann_id}   # 指向待处理帧/片段/物体/标注
  route_reason: low_conf | crosseval_disagree | rule_violation | stratified_sample | golden_quota
  pre_label:                         # 预标注快照（人工只修正不从零标）
    label_ref: <自动标注 ann_id>
    model_version: <模型三锁之一>     # 快照可追溯到哪版模型
  assignment: {annotator: annotator_007, assigned_at: <ts>, sla: <时长预算>}
  result:
    action: accept | fix | reject | relabel        # 采纳 / 修正 / 驳回 / 重标
    edit_trace: [...]                              # 修正前后差异（操作留痕）
    label_source_after: model | human_GT           # 见下方二分约定
    qc_status_after: pass | human_fixed | rejected
  qc_trace: [...]                     # 与 AnnotationSet.qc_trace 同一留痕链
  data_version / operator_version / model_version: <三锁>   # 沿用 02 §6
```

**修正深度的二分约定（本篇设计约定）**：

- 人工**重标/大幅修正**（relabel、推翻性 fix）→ 新 `ann_id`，`label_source = human_GT`，`qc_trace` 保留原记录不抹历史
- 人工**确认/微调**（accept、小幅 fix）→ 保留原 `label_source`，`qc_status = human_fixed`
- 二分的意义：`human_GT` 是可信度最高、可当评测标尺的来源——把「点了一下确认」也标成 human_GT 就是变相混标（02 红线 1）

## 8. 红线与面试话术

**红线**：

1. **隐私前置**：标注员看到的画面必须**已过人像脱敏**（`op-pre-desensitize`，G1 脱敏覆盖检查；终审 `op-des-audit`）——人工标注环节**不得先于脱敏**。人与外部 API 同构（[模型卡 06](../模型卡/06-语义标注-VLM.md) 的 VLM 红线）：都是数据出域消费者，脱敏前置不可倒置
2. **人工不做全量**：全量人工 = 成本崩溃 + 一致性劣化（Kappa 随疲劳下滑）；自动率（通吃率）是第一 KPI，人工只碰 5 类长尾任务
3. **Hold-out 冻结**：Golden Set / 真实 Hold-out 精标结果绝不进训练（沿用 02 红线 2——最终标尺不容污染）
4. **修正深度如实标记**：确认/微调不得标 `human_GT`（二分约定，§6）；混标即 02 红线 1 的变体
5. **操作留痕不可绕过**：人工环节天然不可复现（02 红线 5「自动部分幂等」），`edit_trace + qc_trace` 是评测与追责的唯一凭证，任何「快速通道」绕过留痕即违规

**面试话术（30 秒）**：

> "标注生产我们的原则是自动跑全量、人工只碰长尾。所有样本先过自动标注——L2 感知加 L3 语义模型全量出标签带置信度，然后置信度门加双模型互检自动分流：高置信直接入库待抽检，低置信和分歧件进人工队列。人工只做五类不可替代的任务：分割链首帧提示、低置信和互检分歧复核、少样本 6DoF 建模板、VLM 指令校对、Golden Set 精标。标注台三个能力是效率关键：智能路由按置信度和类别派单、预标注让人工只修正不从零标、全程操作留痕可审计。KPI 上通吃率 90%、人工介入率 10% 以内——因为人工是最贵且不可摊销的环节，每压一个点介入率都是线性人力节省。还有一条硬红线：标注员看到的画面必须先脱敏，人工环节绝不能先于脱敏。"
