# 模型卡 02：相机位姿 · MegaSaM

> 02-生产域 模型卡系列第 2 张。定位：管线「相机位姿 / SLAM」算子的标杆模型，全链路**坐标系枢纽**。承接 [算子设计-01 §4 相机位姿行](../算子设计/算子设计-01-业内通用算子全集总览.md)；素材底稿 = [调研笔记-01 场景 B](../../92-调研笔记/调研笔记-01-具身数据处理模型-场景化选型与管线结合.md)。

## 核实状态（2026-10-17）

- ✅ 出处：CVPR 2025 **Best Paper Honorable Mention**（动态场景结构与运动重建）
- ✅ 工程量级：第三方 OpenReview 对比表约 **13s/样本、约 7GB 内存**，长视频需切段（https://openreview.net/forum?id=oBOVYRRSy2）
- ✅ 管线口径：与 [算子设计-03](../算子设计/算子设计-03-算子执行与编排规范.md) PipelineSpec 示例 `op-per-cam`（model: megasam, seg_len: 256）、[算子设计-06](../算子设计/算子设计-06-算子成本模型.md) 量级表一致

## 1. 定位与算子位置

- **任务**：从（含动态物体的）单目视频估计 **`camera_to_world[T,4,4]`** 相机轨迹——全链路最重要的坐标转换矩阵
- **算子位置**：生产域 · L2 感知结构化 → 相机位姿 / SLAM 算子（`op-per-cam`）
- **坐标系**：本模块自己定义世界系——所有模块（手部/物体/场景）的相机系输出都靠它抬升到**世界系**
- **定位**：坐标系枢纽 + 场景重建通道标杆；工程上是 L2 成本大头之一（秒级/样本），是切段与资源配置的重点对象

## 2. 模型原理（一句话 + 三模块）

- **核心思想**：把动态场景下"相机轨迹 + 稠密深度"的联合估计做成**可微优化**，用深度先验与运动分割处理动态物体
  1. **可微 BA 骨架**（DROID-SLAM 路线）：轨迹与深度联合迭代优化，端到端可微
  2. **单目深度先验注入**：外部深度（管线内 = MoGe）作为初始化与约束项，**不强制绑定深度尺度**
  3. **运动分割**：识别动态物体区域并降权，缓解"手在动、物体在动"对静态场景假设的破坏
- 学术出处：CVPR 2025（Best Paper Honorable Mention）

## 3. 输入 / 输出规格

- **输入**：
  - L1 规范化 RGB 帧序列 + 时间戳
  - 内参：分支 A（AR/头显有标定内参）直接进 SLAM；分支 B（互联网 ego 视频无内参）**GeoCalib 前置**预测焦距/主点/畸变恢复虚拟内参
  - 回注④：MoGe 深度图（深度先验）
  - 辅助⑤：手/物体 mask（动态区域屏蔽）
- **输出**：
  - `camera_to_world[T,4,4]`、相机光心世界坐标、旋转四元数时序、场景稀疏/半稠密跟踪点
- **字段命名建议**：`camera_to_world[T,4,4]`、`cam_center_world[T,3]`、`cam_quat_world[T,4]`

## 4. 管线位置与上下游

- **上游 / 回注**：MoGe 深度先验（[模型卡 03](03-单目深度-MoGe+DepthAnythingV2.md)）；分割 mask 动态屏蔽（[模型卡 04](04-分割跟踪-SAM2+TAPIR.md)）
- **下游分发（3 处）**：
  - 回注② 手部抬世界系（[模型卡 01 HaWoR](01-手部重建-HaWoR.md)，仅后处理）
  - 送⑥ 物体 6DoF 抬世界系（[模型卡 05](05-物体6DoF-FoundationPose.md)，仅后处理）
  - L2 全局几何一致性校验（出口质检门）
- **组合**：与深度（先验环）+ 手部/物体（抬升链）构成 L2 的"一环两链"——它是环和链的公共节点

## 5. 指标与资源

- **工程量级（第三方 OpenReview 对比表）**：约 13s/样本、约 7GB 内存——**长视频必须切段**（PipelineSpec 示例 seg_len=256）+ 段间轨迹拼接
- **质检指标**：SLAM 跟踪丢失率、轨迹平滑度、重投影误差（阶段质检门消费）
- **资源**：GPU 推理（L2 感知池 GPU Actor 常驻）；实测耗时 / 显存 / 吞吐：待跑 benchmark（按算子设计-06 成本口径回填）

## 6. 选型与替代

- **适用**：动态场景（手物操作视频必然动态）优先 MegaSaM
- **替代 / 互检**：
  - **DROID-SLAM**：遮挡密集场景兜底（MegaSaM 的可微 BA 基础，学术经典）
  - **GeoCalib**：无内参分支的前置标定（不是替代，是分支组件）
  - **COLMAP**：静态场景 SfM 事实标准——静态采集场景（无动态物体）下的工程界常用替代
- **降级**：成本敏感 + 场景基本静态 → COLMAP/轻量位姿（跨档替换，见算子设计-06 省钱策略 #3）；前沿模型先跑 Pilot 验证再全量

## 7. 失效模式与红线

- **失效**：
  - 动态物体（手运动、移动物体）破坏静态假设——优先用⑤mask 屏蔽
  - 长视频漂移累积——切段 + 段间拼接
  - 无内参视频完全依赖 GeoCalib 预测，预测误差持续传导给所有下游
- **红线**：
  - **camera_to_world 只用于后处理坐标变换，禁止回灌**进②MANO 拟合、③自身优化、⑥6DoF 优化回路（误差循环放大发散）
  - 深度先验仅作初始化/约束，SLAM 仍会尺度漂移——这是**整条管线尺度不一致的根源**，不能假设先验对齐
  - 尺度链：MoGe 深度 → 相机轨迹 → 手/物体抬世界，每步漂移，L2 出口统一几何一致性校验

## 速讲话术（30 秒）

> "相机位姿模块是整条感知管线的坐标系枢纽，MegaSaM 是这个槽位的标杆——CVPR 2025 Best Paper Honorable Mention，核心是把相机轨迹和稠密深度做可微联合优化，外部深度先验只做初始化和约束，动态物体用运动分割降权。它输出 camera_to_world，手部和物体的相机系结果全靠这个矩阵抬到世界系。工程上它是成本大头，第三方对比约 13 秒每样本，所以长视频必须切段加段间拼接。选型上：动态场景用它，遮挡密集 DROID-SLAM 兜底，无内参的互联网视频先过 GeoCalib 恢复虚拟内参，纯静态场景直接 COLMAP 更省。红线是相机矩阵只能做后处理，绝不能回灌进任何优化回路。"
