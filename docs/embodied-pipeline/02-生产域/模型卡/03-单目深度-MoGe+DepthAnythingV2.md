# 模型卡 03：单目深度 · MoGe + Depth Anything V2

> 02-生产域 模型卡系列第 3 张。定位：管线「单目深度估计」算子的双模型组合（MoGe 主尺度基准 + DAv2 互检），全链路**尺度源头**。承接 [算子设计-01 §4 单目深度行](../算子设计/算子设计-01-业内通用算子全集总览.md)；素材底稿 = [调研笔记-01 场景 C](../../92-调研笔记/调研笔记-01-具身数据处理模型-场景化选型与管线结合.md)。

## 1. 定位与算子位置

- **任务**：逐帧输出**深度图 + 点云 + 法线图 + FoV**——一个模型喂多个下游
- **算子位置**：生产域 · L2 感知结构化 → 单目深度算子（`op-per-depth`）
- **坐标系**：逐帧相机系（深度/点云沿相机光轴），FoV 是视场参数非坐标量
- **定位**：L2 的**前向源头模块**——无任何回注输入，DAG 上游最少（只吃 L1 帧流）；同时是全链路**尺度源头**，它的漂移向下游全量传导

## 2. 模型原理（一句话 + 双模型分工）

- **核心思想**：把"深度 + 点云 + 法线 + FoV"作为一套单目几何**整体估计**，以 metric 真实尺度为主基准输出
  1. **MoGe（主尺度基准）**：单目几何估计，输出 metric 深度 / 点云 / 法线 / FoV 四件套（CVPR 2025 Oral；MoGe-2 为增强版，已在阿里云 PAI 具身管线被直接消费）
  2. **Depth Anything V2（互检侧）**：相对深度 / 视差输出，高速、泛化强、社区大——**无绝对尺度**，专用于与 MoGe 交叉验证找异常帧
- **组合逻辑**：MoGe 出可用的绝对尺度 → 喂下游；DAv2 出视差 → 只做一致性校验。工业量产配置是**双模型互检**（对齐总线 G 门"双模型互检"环节）

## 3. 输入 / 输出规格

- **输入**：L1 规范化 RGB 帧序列（逐帧独立，无时序依赖——所以它是前向源头）
- **输出（逐帧）**：
  - MoGe：metric 深度图 [H,W]、点云 [H,W,3]（相机系）、法线图 [H,W,3]、FoV 标量
  - DAv2：视差图 [H,W]（相对量）
- **字段命名建议**：`depth_metric_cam[T,H,W]`、`pointcloud_cam[T,H,W,3]`、`normal_cam[T,H,W,3]`、`fov[T]`、`disparity_dav2[T,H,W]`

## 4. 管线位置与上下游

- **上游 / 回注**：无回注（唯一只吃 L1 的 L2 模型）
- **下游分发（5 路）**：
  1. MoGe 深度 → ③ SLAM 深度先验注入（[模型卡 02](02-相机位姿-MegaSaM.md)）
  2. MoGe FoV → 回注② 手部 2D 投影约束（[模型卡 01](01-手部重建-HaWoR.md)）
  3. MoGe 深度 → ⑥ FoundationPose 的 RGB-D 之 D 通道（[模型卡 05](05-物体6DoF-FoundationPose.md)）
  4. DAv2 视差 ↔ MoGe 互检，检测深度异常帧
  5. 逐帧法线图 / 点云 → L2 产物输出（送 L3 语义与 L4 封装）
- **组合**：一个模块驱动两条先验环（深度环 + FoV 环）——L2 DAG 里它必须最先跑，是并行程的起点之一

## 5. 指标与资源

- **量级**（[算子设计-06](../算子设计/算子设计-06-算子成本模型.md) 估算表）：GPU 10–100ms/帧（模型相关）；具体实测：待跑 benchmark
- **质检指标**：深度置信度占比、MoGe ↔ DAv2 一致性误差、无效深度像素占比（异常帧即互检失败帧，进 DLQ/复检通道）
- **资源**：GPU 推理，逐帧可批量（Ray Data map_batches 或 GPU Actor 池均可）

## 6. 选型与替代

- **适用**：单目 ego 视频通道的尺度源头；需要四件套齐备（深度/点云/法线/FoV）时 MoGe 一站式
- **替代 / 互检**：
  - **Depth Anything V2**：单目深度事实标准之一——只做互检不够格做主基准（无绝对尺度）
  - **Depth Anything V1 / UniDepth**：工程界常见替代（UniDepth 亦可出内参/尺度）
  - **MiDaS**：老一代相对深度
- **降级**：成本敏感 → 只跑 DAv2 做相对深度质检（放弃绝对尺度链）；MoGe-2 换 MoGe-1 看精度/成本权衡（同档替换需实测）

## 7. 失效模式与红线

- **失效**：
  - 弱纹理、强遮挡、互联网低质视频下 MoGe metric 尺度**仍会漂移**——宣称 metric ≠ 无条件可信
  - 动态物体区域深度不可靠（单帧模型无运动推理）
- **红线**：
  - **DAv2 是相对深度，不能单独作③的深度先验产出绝对尺度轨迹**，只能做辅助校验
  - **尺度链传导**：深度漂移 → 相机轨迹 → 手部/物体抬世界，全链路跟着错——L2 出口必须做几何一致性校验，不能假设天然对齐
  - 深度先验进 SLAM 不绑定尺度（SLAM 自行收敛尺度），两边各自漂移是预期行为

> "单目深度是感知管线的尺度源头，我们用 MoGe 加 Depth Anything V2 双模型互检：MoGe 是 CVPR 2025 Oral，一站式输出 metric 深度、点云、法线加 FoV，做主尺度基准；DAv2 出相对视差，泛化强、速度快，专做交叉校验找异常帧。它的下游有五路：深度喂 SLAM 做先验、FoV 反哺手部投影约束、深度给 FoundationPose 当 D 通道、和 DAv2 互检、法线点云直接出产物。关键红线是 MoGe 宣称 metric 但弱纹理遮挡下照样漂移，而深度漂移会沿着尺度链传导给相机轨迹、手部和物体，所以 L2 出口必须做统一的几何一致性校验，深度永远不能被无条件信任。"
