## 1. 定位与算子位置

- **任务**：从第一视角（egocentric）视频恢复**世界坐标系下的 3D 手部运动**（MANO 参数化）
- **算子位置**：生产域 · L2 感知结构化 → 手部检测与重建算子
- **坐标系**：中间产物在相机系，最终手部轨迹经相机轨迹抬升到**世界系**
- **定位**：该任务目前最具代表性的开源方案，手部结构化通道标杆；相对"分件路线"（WiLoR/YOLO 检测 → MANO 拟合 → Masked DROID-SLAM 平滑），它是**自带检测+MANO+ego SLAM+出视野补全的一体化升级路线**

## 2. 模型原理（一句话 + 三模块）

- **核心思想**：第一视角下相机与手同时运动，直接回归世界坐标病态 → **解耦**
  1. **手部检测与跟踪 → 相机空间 MANO 重建**：帧间检测生成 tracklet（手性 + 每帧置信度），Transformer 逐帧回归 MANO（β 形状 / θ 姿态）
  2. **自适应第一视角 SLAM（adaptive egocentric SLAM）**：针对第一视角快速运动 / 低视场改进鲁棒性，估计世界系相机轨迹
  3. **运动补全网络（motion infilling）**：手短暂出视野（out-of-view）时补全轨迹
- **组合逻辑**：相机空间手部轨迹（①）+ 世界空间相机轨迹（②）= 世界空间手部运动；③ 兜底出视野
- 与管线「相机位姿回注手部抬升世界系」同构——**相机轨迹是公共坐标系**

## 3. 原生输出与在线交付

HaWoR 的输入是第一视角视频。生产侧还要固定媒体视图、源时间戳和标定来源。模型分别估计相机系手部运动和相机轨迹，再补全缺失运动。调用方按下表解释结果。[HaWoR 项目说明](https://hawor-project.github.io/) · [原始实现](https://github.com/ThunderVVV/HaWoR)

| 模型或中间表示 | 拟交付的信号 | 适配时要做的事 |
| --- | --- | --- |
| 相机系 MANO 姿态、形状、手腕朝向与平移 | `hand_cam` 或单列 MANO 参数 | 按固定 MANO 版本解码并声明关键点顺序、参考视图和单位。45 个关节姿态参数和形状参数分别存储。消费 21 点坐标时需导出相应点集。 |
| 图像检测、关键点观测或重投影 | `hand_2d` | 标记坐标源于检测还是重投影，并还原到源画面像素。手部掩码若由渲染或独立分割生成，登记该派生步骤。 |
| 相机系手部与内置 ego SLAM | `hand_world`，路径 `internal` | 固定内部轨迹引用和局部世界 ID，保留逐帧有效性、补全标记与尺度依据。 |
| 相机系手部与显式传入的 `camera_pose_ref` | `hand_world`，路径 `external` | 平台适配方案。按时刻和单位对齐，再变换相机系点。替换相机结果时按字段依赖重算世界系。 |

手别和任务内轨迹 ID 由适配层与帧记录关联，操作者归属需另外提供证据。多人交叉或手出画后，允许归属未知。双目采集需声明实际送入模型的视图；双目三角测量须另行实现和验收。[在线结果契约](../算子设计/算子设计-09-具身在线算子调用与结果契约.md)

现有管线示例还使用每手 54 维特征，由腕位 3 维、旋转 6D 表示和 MANO 关节姿态 45 维拼接而成。形状参数 β 另存。若消费者选择这种表示，应声明特征布局和版本；21 点关键点对应另一套输出 Schema。

## 4. 管线位置与上下游

- **本地外部位姿路径的上游 / 回注**：
  - L1 帧流 + 内参（无内参走 GeoCalib）
  - 深度模块回注 **FoV**（手部 2D 投影约束）
  - 相机位姿模块回注 **camera_to_world**（**仅后处理坐标变换，不参与 MANO 拟合**）
- **下游**：
  - 手部 mask → 分割/跟踪算子（遮挡屏蔽）
  - 世界系手部轨迹 → 语义层（动作分割的腕速曲线）
  - 尺度锚 scale_factor → 可给物体 6DoF 提供初值
- **组合**：与分割（手/物 mask）+ 6DoF（物体位姿）组合 → 手-物交互结构化（接触边界 + 相对位姿），这是操作数据最有价值的部分

## 5. 指标与资源

- **相机轨迹**。论文表 2 报告尺度对齐后 ATE 为 3.36 mm，使用估计尺度时全体序列 ATE-S 为 14.61 mm。两项均评估相机位置。[论文表 2](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhang_HaWoR_World-Space_Hand_Motion_Reconstruction_from_Egocentric_Videos_CVPR_2025_paper.pdf)
- **手部精度**。表 1 在 DexYCB 上按遮挡比例报告相机系手部 PA-MPJPE 和 AUC；表 3 另评估 HOT3D 的世界系手部重建。项目评测还需覆盖操作者误认、未知归属和短时出画。[论文表 1、表 3](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhang_HaWoR_World-Space_Hand_Motion_Reconstruction_from_Egocentric_Videos_CVPR_2025_paper.pdf)
- **资源**：
  - 检测 + MANO 回归为 GPU 推理；SLAM 部分可 CPU 化 → 匹配 L2 GPU Actor 池（GPU Actor 常驻 + SLAM 旁路）
  - 长序列按资源预算切段。跨段轨迹需有重叠观测及可验证的坐标对齐；对齐失败保留各段局部世界。
  - 实测耗时 / 显存 / 吞吐：待跑 benchmark

## 6. 选型与替代

- **适用**：第一视角手-物操作数据、需要世界系手部轨迹
- **替代 / 互检**：
  - **WiLoR**（端到端手部定位+重建，出朝向初值）
  - **HaMeR** 根据单图、手框和手别回归 MANO 网格。可在双方均有可见观测的帧比较手形或关键点；跨帧身份和世界轨迹另行评估。[HaMeR 项目](https://geopavlakos.github.io/hamer/)
  - **FrankMocap**（轻量，精度低）
  - **分件路线**：YOLO/WiLoR 检测 → MANO 拟合 → Masked DROID-SLAM 时序平滑（不修改 β）
- **降级**：算力受限时可评测 WiLoR 或 HaMeR 的逐帧方案；仅需图像关键点时可选择 2D 方案。

## 7. 失效模式与红线

- **失效**：
  - 快速运动、严重遮挡（手被物体大面积遮挡 → 关键点失效 → MANO 崩坏）
  - 手出视野（补全网络缓解但不消除）
  - 极端光照下检测退化
  - 长视频漂移（需切段拼接）
- **红线**：
  - **camera_to_world 禁止回灌进 MANO 拟合优化回路**（仅后处理），否则把 SLAM 漂移放大到 MANO 参数
  - 尺度链：MoGe 深度 → SLAM 相机轨迹 → 手部抬世界，每步漂移，不能假设天然对齐，L2 出口做几何一致性校验
  - 域错配：输入帧率 / 分辨率 / 内参与训练口径不一致需先校验

## 速讲话术（30 秒）

> HaWoR 分别估计手和相机的运动，再重建世界系手部轨迹。对理线视频，调用方要知道轨迹属于谁、哪些时刻靠补全、哪一段相机位姿足以支撑世界坐标。手部关键点评估、相机定位精度与服务端时延应分别报告。
