- **平台边界**：仿真数据生产属于「数据生产」，产物是训练数据资产（TrainingRelease）；平台**不做策略训练与控制**，仿真器里的 rollout 仅用于"造数据"而非"练策略"

## 2. 为什么需要仿真 GT（真实数据的真值缺口）

- **第一视角/互联网 ego 视频没有本体真值**：深度、相机位姿、物体 6DoF、实例分割、接触点全部依赖模型估计（HaWoR/MegaSaM/MoGe/FoundationPose/SAM2），估出来的结果无法直接当作训练感知模型的 GT，也无法对算法做精确评分
- **仿真渲染自带精确真值**：渲染管线天然知道每个像素的深度、相机内外参、物体位姿、实例归属、关节状态——真值"免费"且逐帧精确
- **仿真数据的四个不可替代价值**：
  1. 大规模、低成本、可复现（不依赖真机采集与人力）
  2. 真值齐全（真实通道最稀缺的位姿/接触力都有）
  3. 可构造长尾、危险、稀有场景（碰撞、跌落、极端光照）
  4. 为真实通道的估计模型提供**真值校验/标定基准**（见 §4 对照）

## 3. 仿真数据生产链路

```
场景/资产 ──► 仿真器 ──► 域随机化 ──► 轨迹/动作生成 ──► 渲染(RGB-D+多模态) ──► GT 导出
 (3D场景/CAD/URDF/材质光照)        (脚本/遥操回放/rollout)            (随渲染同步产出真值)
```

- **场景与资产**：3D 场景、物体 CAD 模型、机器人/手 URDF、材质（PBR）、光照与相机配置
- **仿真器**（业内通识，按团队任务选型，**不写版本指标**）：
  - **Isaac Sim / Isaac Lab**（GPU 大规模并行、照片级渲染，操作类主流）
  - **ManiSkill**（机械臂操作、GPU 并行、benchmark 友好）
  - **MuJoCo**（接触动力学精度高、物理仿真经典）
  - **Genesis / SAPIEN**（生成式物理 / 铰接可交互物体）
- **域随机化（Domain Randomization）**：纹理、光照、相机位姿/内参、材质、物理参数（摩擦/质量/阻尼）随机化，强制模型学本质而非渲染表象，提升 Sim2Real 泛化
- **轨迹/动作来源**：脚本化轨迹、遥操作轨迹回放、或仿真内策略 rollout（rollout 仅用于造数据）
- **数据配方优先级（GeoPT 消融结论，调研笔记-03 §4）**：**几何多样性 > 动态多样性**——优先堆场景结构、物体形状、手形的多样性，其次才是速度/动力学配置；几何多样性是主要瓶颈

## 4. GT 导出清单（本篇核心）

仿真 GT 既是训练数据，又是真实通道估计模型的**标定/真值校验基准**：

| 仿真自带 GT | 对应真实通道模型（可被该 GT 校验/标定） | 标注体系来源 |
| --- | --- | --- |
| 深度图 / 点云 | MoGe / Depth Anything V2（单目深度） | sim_GT |
| 相机内参 / 外参 / 位姿 | MegaSaM / DROID-SLAM（SLAM） | sim_GT |
| 物体 6DoF 位姿 | FoundationPose | sim_GT |
| 实例 / 语义分割 mask | SAM2 / EgoHOS | sim_GT |
| 手部 / 关节状态 | HaWoR | sim_GT |
| 接触点 / 接触力 | TAPIR 接触边界（真实通道仅能推 2D） | sim_GT |
| 动作 / 子任务标签 | 腕速切分 + VLM 指令 | sim_GT（指令可过 VLM 生成） |

**导出三原则（决定能不能和真实数据混训）**：

1. **同 schema**：字段名、维度、坐标系（相机系/世界系）、时间戳基准与真实通道完全对齐
2. **同封装**：统一封装为 LeRobot v2/v3，下游训练对数据来源无感知
3. **同血缘**：固定标 `label_source=sim_GT`，并记录仿真器版本（进版本三锁中的"模型版本"位）

```yaml
sim_sample:
  sim_source: isaac_sim | maniskill | mujoco | ...   # 仿真器
  simulator_version: <版本，进三锁>
  scene_id: <场景>
  object_cad_id: <物体模型>
  robot_urdf: <机器人/手模型>
  randomization_seed: <域随机化种子，保证可复现>
  physics_params: {friction, mass, damping, contact_model}
  gt:
    depth_cam: [T,H,W]
    camera_to_world: [T,4,4]
    obj_pose_cam: [T,4,4]
    instance_mask: [T,H,W]
    hand_joint: [T,54]
    contact_points: [T,N,3]
    action_label: <动作/子任务>
  label_source: sim_GT          # 固定，禁止与真实混标
  data_version: <三锁之一>
```

## 5. GT 旁路并入主管线（跳过 L2）

```
第一视角/遥操作真实视频 ──► L1预处理 ──► L2感知重建(HaWoR/MegaSaM/MoGe/SAM2/FoundationPose) ──► 结构化
                                                                          │
仿真器渲染 RGB-D ──GT直出(深度/位姿/分割/关节/接触/动作) ─► 动作分割(可自动) ─► VLM指令 ─┤
   （自带真值，跳过 L2 感知重建；合成无隐私，跳过脱敏）                                   │
                                                                                          ▼
                                                        清洗/质检 ─► 统一封装 LeRobot v3(同schema) ─► TrainingRelease
```

- **跳过项**（算子-05 仿真列）：目标检测/分割、手部重建、单目深度、物体 6DoF 均为「GT 直出（➖）」；脱敏前置「➖（合成无隐私）」
- **保留项**：时间同步/标定、动作分割（可自动）、VLM 指令生成（仿真片段同样需要语言标注）、清洗/去重/合规、统一封装
- **相机位姿**：仿真引擎直接已知，无需 SLAM
- **统一出口**：仿真与真实四源最终都封装为同一样本 Schema，下游训练无感知——这是旁路能成立的工程前提

## 6. 三套 GT 分工与真实/仿真配比（仿真侧视角）

| GT 类型 | 来源标记 | 在仿真链路中的角色 | 规模 |
| --- | --- | --- | --- |
| 仿真合成 GT | sim_GT | **预训练/算法迭代主力**，L1 算法指标主评测 | 大规模、低成本 |
| 伪 GT | pseudo_GT | 强模型对真实数据打标；**仿真 GT 可作为标定强模型的基准**（先在仿真上验证模型再去真实打标） | 中等 |
| 真实 Hold-out GT | human_GT | 小规模人工精标、冻结、**绝不能用仿真替代**，只做最终结论 | 小、贵 |

- **配比方向**：CloudRobo 实践约 20% 真机 / 80% 生成（仅作方向，非本团队定标）；通用范式为**合成数据预训练 + 少量真实数据微调**
- **混合要点**：同 schema 后按比例/权重采样；`sim_GT` 与 `pseudo_GT` 进训练需配比加权，`human_GT` Hold-out 只评测不训练
- **仿真 GT 与伪 GT 的关系**：可先用"仿真 GT vs 强模型估计"量化模型在仿真域的误差，作为该模型对真实数据产出伪 GT 的可信度参考

## 7. Sim2Real 域错配与纠偏

三类域差与对应手段：

| 域差类型 | 表现 | 纠偏手段 |
| --- | --- | --- |
| 视觉域 | 纹理/光照/渲染风格、相机噪声差异 | 域随机化、照片级渲染、加噪模拟、真实微调 |
| 物理域 | 接触、摩擦、质量、刚体动力学差异 | 物理参数系统辨识、高保真接触模型 |
| 传感器域 | 深度/相机噪声分布差异 | 噪声模型注入、真实传感器标定 |

**GeoPT 范式（借范式、不借身份）**：

- 可借鉴的核心：把静态几何 + **合成动力学**拼成自监督预训练数据，轨迹带**边界接触/粘住约束**（`1_outside_G`，碰几何边界即停），让模型先获得"物体怎么动"的物理直觉，再少量真实标签微调——**接触/粘住正是操作任务的物理核心**，与具身最相关
- 成本（调研笔记-03，二手待回对原文）：合成监督约 0.2s/样本（80 核），134.6 万样本约 5TB/3 天；对比真实物理标签，标签需求减少 20–60%、收敛加速最高 2×
- **关键谨慎口径**：GeoPT 验证的是流体/固体力学物理仿真预训练；L2 感知模型是"感知"而非"动力学预测"，迁移到具身是**待验证的核心假设**（需重新定义速度场 V 与监督信号），不能当作已验证方案直接宣称收益
- 治理域评测服务监测**域间指标差距**（合成评测 vs 真实 Hold-out），差距过大触发接触/边界约束正则加强或真实补采（总线 §5.3）

## 8. 红线与面试话术

**红线**：

1. **仿真 GT 不能替代真实 Hold-out 做最终结论**——最终效果必须在真实冻结集上验证
2. **仿真/真实必须同 schema、同坐标系、同字段**，否则无法混训，旁路不成立
3. 仿真数据**如实标 `sim_GT`**，禁止混入真实集冒充 human_GT
4. 仿真 GT 受**物理引擎保真度限制，不是"绝对真值"**（接触/柔体/光照本身有建模误差），引用其精度要保留此口径
5. **预训练输入空间必须与真实任务一致**（几何表示/坐标系/速度场参数化），否则微调失效或倒退（GeoPT 输入空间不匹配红线）
6. **合成几何分布必须覆盖真实采集域**（几何域外会导致收益消失甚至训练不稳）
7. 数据配方优先堆**几何多样性**（GeoPT 消融：几何多样性 > 动态多样性）
8. 仿真若由真实资产（真实扫描/真实纹理）衍生，须做 split 隔离，防仿真-真实跨集泄漏

**面试话术（30 秒）**：

> "真实第一视角视频最大的痛点是没有本体真值，深度、位姿、6DoF 全靠模型估，没法当训练标签。仿真渲染自带这些真值，所以我们让仿真走一条 GT 旁路：跳过 L2 感知重建、也不用脱敏，GT 直出后和真实通道同 schema 封装成 LeRobot，下游训练对来源无感知。导出的仿真 GT 有双重用途：既当大规模预训练数据，又当真实模型——MoGe、MegaSaM、FoundationPose 这些——的标定基准。三套 GT 分工不能混：仿真 GT 做主力迭代、强模型伪 GT 补真实域、真实 Hold-out 精标冻结只做最终结论，配比方向参考 CloudRobo 的 20% 真机加 80% 生成。Sim2Real 靠域随机化加少量真实微调，GeoPT 那套边界接触自监督可以借鉴，但它验证的是物理仿真、迁移到具身感知还是待验证假设，我不会把它当已验证收益。最硬的红线是仿真永远不能替代真实 Hold-out 做结论，且仿真真实必须同 schema、如实标来源。"
