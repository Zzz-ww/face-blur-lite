# 04 · 冷热分层与TTL（存储降本 / 训练热点加速 / 归档与删除的物理执行）

> 05-资产域第 4 篇。定位：**资产域的降本与提速**——数据按热度分层摆、训练热点加速读、到期数据物理归档/删除。边界：生命周期状态机与状态迁移规则 = [治理 01](../04-治理域/01-版本管理与不可变快照.md)（**状态在治理**）；删除/留存的合规决策 = [治理 07](../04-治理域/07-合规引擎.md)（**决策在治理**）；成本口径 = [算子设计-06](../02-生产域/算子设计/算子设计-06-算子成本模型.md)（**不重算**）；本篇只做**物理动作**：迁移、预热、归档、删除、回写凭证。物理布局 = [01](01-湖仓统一存储与多模态布局.md)；供数 = [05](05-TrainingRelease装配与导出.md)。

## 核实状态（2026-10-18）

- ✅ 已核实：热/温/冷分层与生命周期策略（按访问频率+时间自动迁移）为对象存储业内通识（S3/OSS 标准存储/低频/归档类别即此模式）；归档层取回有时延与成本权衡（通识：分钟到小时级，依产品而定）；「元数据/血缘不随数据迁冷」与 [治理 02 §5](../04-治理域/02-血缘制品与版本三锁.md) 一致
- ⚠️ 设计通识：三层的具体判据（访问频率阈值、版本状态组合）、缓存预热策略、TTL 执行器与凭证回写为本平台设计（**字段与阈值以实现为准**）
- ❓ 待补：各层单价与迁移收益基线、缓存命中率目标、归档取回时延实测——待团队标定

## 1. 定位与边界

- **本篇管**：存储分层（热/温/冷）与**自动迁移**、训练热点**加速**（本地 NVMe/缓存集群）、TTL 的**物理执行**（归档/删除 + 回写凭证）、冷数据取回
- **不管**：版本处于什么生命周期状态（治理 01）、这份数据能不能删（治理 07）、训练加载之后的事（消费域）、成本模型口径（算子-06）
- **一句话**：治理说「这版该归档了」，本篇把数据**真的搬过去、搬得便宜、要时还能拿回来**——规则与执行分离，本篇是执行层

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 生命周期策略引擎 | 依据信号算出迁移/过期动作 | 输入：访问统计（[02 操作元数据](02-数据集目录与检索.md)）+ 版本状态（治理 01）+ 时间 |
| 热层（在线/SSD） | 高频训练数据 | 本地 NVMe / 缓存集群；容量小、时延低 |
| 温层（标准对象存储） | 默认摆放层 | 01 湖仓默认落点；容量大、单价低 |
| 冷层（归档） | 低访问长期留存 | 取回有时延/费用；**元数据不随之降级** |
| 缓存预热 | 训练前把热点拉到热层 | 与 [05 供数](05-TrainingRelease装配与导出.md) 联动 |
| TTL 执行器 | 物理归档/删除 + 回写凭证 | 决策来自治理 07；执行结果可审计 |

> **与负载均衡/控制面同构**：这套就是**缓存分层**的搬运——热/温/冷 ≈ 内存 / 本地磁盘 / 回源；生命周期策略 ≈ 缓存逐出策略（LRU 按「访问频率+年龄」逐出，这里一样，只是动作从「扔掉」换成「降级摆放」）；缓存预热 ≈ 我做 XLB 时的配置/Session 预热——知道要来大流量，提前把热点推到边缘；「元数据不迁冷」≈ 回源可以慢，但寻址系统必须永远在线。CDN 的每一层分级都是「用容量换时延、用时延换成本」，这里一字不改。

## 3. 三层存储分层

| 层 | 介质 | 放什么 | 读路径 |
| --- | --- | --- | --- |
| **热** | 本地 NVMe / 缓存集群 SSD | 正在训练的数据集、Golden Set、高频访问版本 | 直读，低时延 |
| **温** | 标准对象存储（湖仓默认） | Published 常规版本、近期数据 | 拉取后读（或经缓存） |
| **冷** | 归档存储 | Deprecate 待留存的旧版本、低访问长期数据 | **先取回再读**（时延/费用） |

```
              写入/发布（01 落盘）
                    │ 默认
                    ▼
                 ┌──────┐  训练引用（05 预热）   ┌──────┐
   高频访问 ◄────┤ 温层  ├─────────────────────►│ 热层  │
   （回写访问统计）│ 标准  │◄────── 淘汰（冷却）───┤ NVMe │
                 └──┬───┘                       └──────┘
      低访问 + 留存 │ 生命周期策略（频率+状态+时间）
                    ▼
                 ┌──────┐   物理删除（治理 07 决策，凭证回写）
                 │ 冷层  │────────────────────────────▲
                 │ 归档  │   取回（按需，分钟~小时级） ──┘
                 └──────┘   目录条目仍在（02），血缘仍在（治理 02）
```

- **迁移是单向为主、可逆付费**：温→冷省钱，冷→温付时延——所以判据要保守（见 §4），高频数据误落冷层会把训练 IO 打爆
- **CAS 与分层正交**：去重（[01 §5 `_cas/`](01-湖仓统一存储与多模态布局.md)）省的是「存几份」，分层省的是「每份单价」——blob 被哪个版本引用决定它的热度上限（被热版本引用的 blob 不能单独落冷）

## 4. 迁移依据与生命周期策略

三个信号合成决策（**阈值为设计通识，以实现为准**）：

1. **访问频率**：滚动窗口访问统计（来自 [02 操作元数据](02-数据集目录与检索.md) `access_30d` 等）——长期零访问是降温主信号
2. **版本状态**（治理 01 状态机）：Published 默认温层；**Golden Set 与「当前默认指针」指向的版本钉在热/温层**（回归与现役训练依赖，治理 05 回归口粮）；Deprecate 才允许进冷
3. **时间**：创建后 N 天未访问、归档留存满 N 月——兜底信号，防止「遗忘的热点」永远占热层

- **策略即配置**：生命周期策略版本化、可审计、变更走治理审批（对齐治理 01 变更受控精神）——降本动作本身不能是黑箱
- **预热与淘汰的对偶**：预热把「将热」拉上来（训练任务创建时按 TrainingRelease 声明预取，[05 §6](05-TrainingRelease装配与导出.md)）；淘汰把「变冷」降下去——一进一出，热层容量恒定可控

## 5. 训练热点加速（供数吞吐）

- **两级加速**（引 [01 §2 加速层](01-湖仓统一存储与多模态布局.md)）：① 训练节点本地 NVMe（最热）；② 缓存集群（共享热池，同数据集多个任务复用）
- **预热时机**：训练任务入队（管控域调度命中）即触发预取——**不让 GPU 等 IO**（数据就绪率是调度 gang 就绪的一部分，[管控 02](../03-管控域/02-调度与多租户.md)）
- **流式加载**：训练按 episode/chunk 流式读（对齐 01 分区大文件布局），不做整版拷贝；随机访问强的阶段（如均衡采样）靠缓存集群兜
- **边界**：本篇保证「数据到训练节点/缓存集群的通道与热度」，加载框架与训练循环在 [06-消费域](../06-消费域/README.md)

## 6. TTL 的物理执行（决策与执行分离）

```
治理 07 合规引擎：删除/留存判决（可删性、留存期、法定留存）
治理 01 生命周期：状态判决（Deprecate / 待归档 / 待删除）
        │ 两者都齐 → 下发物理动作指令（带决策凭证引用）
        ▼
资产域 TTL 执行器：
  ① 校验：目标版本处于允许删除的状态（治理 01）+ 判决文书在（治理 07）
  ② 执行：物理删除 blob / 转归档；CAS 引用计数归零的 blob 才真删
  ③ 回写：删除凭证（谁批准、什么依据、删了哪些 hash）→ 审计留痕（治理 07 §8）
  ④ 例外路径：删除是版本不可变的**显式例外**——必须留决策文书，禁止「顺手删」
```

- **为什么资产不能自己判**：能不能删含合规判断（主体撤销权、法定留存、出境义务）——那是治理 07 的 policy-as-code；资产域自作主张删除 = 不可回溯的事故
- **CAS 删除的引用计数**：blob 可能被多版本共享——只删「无引用」的 blob，有引用的保留（对齐 01 §5 共享语义）
- **导出过的数据怎么办**：TrainingRelease 已导出到外部白名单的（[05 §7](05-TrainingRelease装配与导出.md)），删除决策在治理 07 覆盖范围内统筹（导出记录是治理 06/07 的审计输入），本篇不另设规则

## 7. 归档可恢复与冷数据在线寻址

- **取回是常态操作**：冷→温取回按需触发（目录命中后用户/任务发起），分钟到小时级时延要在产品层明示——**归档不是删**，是「用时延换成本」的摆放
- **元数据/血缘仍在线**（治理 02 §5 红线）：数据在冷层，[02 目录](02-数据集目录与检索.md) 条目、血缘图、[03 快照](03-不可变快照与训练样本快照.md) 记录全部在线——「找得到、看得见，取回慢一点」
- **快照与分层的关系**：快照记录指针清单（03），分层搬运的是 blob 本体——搬完做一轮 manifest vs blob 对账（03 §6 演练同源），防「搬家搬丢」

## 8. 成本视角（引 SSOT，不重算）

- 成本口径（GPU 秒/样本、单小时数据成本）与省钱策略（规则前置、分层采样、模型降级、常驻、缓存、监控）SSOT = [算子设计-06](../02-生产域/算子设计/算子设计-06-算子成本模型.md)
- 本篇的增量贡献是**存储侧三板斧**：分层降单价、CAS 去重降份数、缓存预热降重复拉取带宽——三者的收益曲线均以「层间单价差 × 迁移命中率」衡量，基线待标定
- **热层是稀缺资源**：NVMe 容量有限，预热策略的质量直接决定训练 IO 体验——热层给了不该给的版本，等于把别人的训练降速

```yaml
lifecycle_policy:                  # 设计通识（字段与阈值以实现为准）
  scope: {dataset: ego-daily | "*"}
  rules:
    - if: {state: Published, access_30d_below: X, age_days_over: Y}

    - if: {referenced_by: golden | default_pointer}

  action: archive | delete / target: v1.9.0
  basis: {governance_state_ref, compliance_verdict_ref}   # 治理 01/07 凭证
  blobs_deleted: N（引用计数=0）/ receipt_hash: …          # 回写审计
```

## 10. 指标与质量门

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| 热层缓存命中率 | 训练读命中热层/缓存比例 | 待标定（命中即省拉取） |
| 数据就绪率 | 训练开跑前预取完成比例 | 100%（不让 GPU 等 IO） |
| 分层迁移正确率 | 迁移动作符合策略判据 | 100%（误判可回滚——冷层取回） |
| 误降级告警 | 高频访问数据落冷次数 | 0（防训练 IO 事故） |

## 12. 红线与速讲话术

**红线**：

1. **决策与执行分离**：删除/留存的判断永远在治理（07 判决 + 01 状态），资产域只执行并回写凭证——执行层自作主张删数据是不可回溯事故
2. **无凭证不删除**：物理删除必须带回写审计记录（谁批、依据、删了什么 hash）——删除是版本不可变的显式例外，例外必须有文书
3. **元数据不随数据降级**：数据进冷层，目录/血缘/快照记录必须在线——寻址系统永不迁冷
4. **Golden Set 与默认指针钉层**：回归与现役训练的数据不许落冷——省存储的钱不能拿回归的稳定性换
5. **CAS 引用计数归零才真删**：共享 blob 被别的版本引用着就不能删——去重与删除必须联动
6. **归档≠删除**：冷层是摆放策略不是丢弃；取回时延对用户明示，误把高频数据落冷按事故处理

**速讲话术（30 秒）**：

> "资产域降本我做冷热分层加 TTL：热层本地 NVMe 和缓存集群放正在训练的数据，温层标准对象存储是湖仓默认落点，冷层归档放 Deprecate 待留存的老版本。迁移依据三个信号合成：访问频率来自目录的操作元数据、版本状态来自治理的状态机、再加时间兜底，策略本身版本化可审计。训练热点做两级加速，任务入队就预热，gang 调度的就绪条件里包含数据就绪，不让 GPU 等 IO。关键口径是决策与执行分离：能不能删是治理合规引擎的判决，生命周期状态是治理状态机管的，资产域只做物理迁移、归档、删除并回写凭证，CAS blob 引用计数归零才真删，删了必须留审计文书。冷数据的目录、血缘、快照记录全在线，归档不是删除，是拿时延换成本的摆放。这套就是 CDN 缓存分层的搬运：热度分级、预热、逐出、回源，把被缓存对象从网页换成多模态数据集。"
