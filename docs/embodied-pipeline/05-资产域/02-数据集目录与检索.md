# 02 · 数据集目录与检索（Catalog / 数据发现 / 多维检索 / 向量检索）

> 05-资产域第 2 篇。定位：**资产域的数据地图**——数据集、版本、样本怎么登记、怎么被打上业务与技术标签、怎么被找到。边界：物理文件怎么存 = [01-湖仓统一存储与多模态布局](01-湖仓统一存储与多模态布局.md)（SSOT）；血缘图模型与查询 = [治理 02](../04-治理域/02-血缘制品与版本三锁.md)（**本篇只挂入口不重写**）；split 权限 = [治理 06](../04-治理域/06-数据分流与防泄漏.md)；制品 schema = [总线 §4.1](../00-总体架构/README.md)。本篇管「**怎么找到、怎么浏览**」——找到之后的冻结（[03](03-不可变快照与训练样本快照.md)）、降本（[04](04-冷热分层与TTL.md)）、供数（[05](05-TrainingRelease装配与导出.md)）各归各篇。

- ⚠️ 设计通识：目录条目与检索 API 字段、profile 统计项、向量索引选型（HNSW 类近似检索为通识参数域）为本平台设计（**字段以实现为准**）

## 1. 定位与边界

- **本篇管**：目录登记（数据集/版本/样本三级）、三类元数据统一、**多维条件检索**（任务/场景/本体/模态/标签/来源/版本）、样本预览与统计画像、**向量检索**（相似样本/场景/指令）
- **不管**：物理布局（01）、血缘查询本体（治理 02）、快照与时间旅行（03）、导出装配（05）
- **一句话**：01 解决「字节摆哪」，本篇解决「**要用的那份数据怎么被一句话找到**」——目录是资产域的门面，也是所有下游消费的寻址入口

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 目录服务（Catalog） | 数据集/版本/样本登记与元数据管理 | 三类元数据统一（§3）；条目与物理 blob 靠内容指纹对账（01 §6） |
| 术语表（Glossary） | 业务术语与标签体系 | 「场景」「任务类型」的受控词表——业务口径的 SSOT |
| 检索引擎 | 多维条件过滤 + 排序 | 条件检索走元数据库（结构化过滤） |
| 向量索引 | embedding 近邻检索 | 数据落盘在 01（Parquet 向量列），**索引在本篇**（可重建） |
| 预览/画像（Profile） | 样本级预览、数据集统计分布 | 采样生成，浏览与选数决策依据 |

> **与负载均衡/控制面同构**：数据目录 ≈ 服务/配置注册中心——注册中心按服务名/标签/健康度寻址服务实例，目录按任务/场景/来源/版本寻址数据资产；术语表 ≈ 配置的 schema 约束（防止同名不同义）；向量检索 ≈ 按语义模糊匹配而不是精确 key 查注册表。我在 XLB 天天用的就是「元数据寻址 + 受控词表 + 健康度过滤」这套。

## 3. 三类元数据（一个条目三层信息）

| 元数据类 | 内容 | 例子 | 谁维护 |
| --- | --- | --- | --- |
| **技术元数据** | schema、分区、文件布局、hash、大小、行数 | `videos/chunk-000/…`、Parquet 列定义 | 系统自动（登记时写入） |
| **业务元数据** | 业务术语、任务类型、场景、本体、项目归属、标签 | `task=抓取`、`scene=厨房`、`robot=xxx型号` | 数据 owner / 标注（受控于 glossary） |
| **操作元数据** | 访问统计、热度、最近使用、归属团队、成本 | 访问次数、被哪些训练引用 | 系统累计（供 [04 分层](04-冷热分层与TTL.md) 决策） |

- **统一管理的意义**：技术元数据回答「长什么样」，业务元数据回答「是什么、给谁用」，操作元数据回答「还有人用吗」——三层合起来才支撑检索、选数与降本决策
- **登记时机**：版本晋升（治理 01 §5）与落盘（01）完成即自动登记技术元数据；业务标签由 owner 补充，**未打业务标签的版本标记「不可检索仅可列举」**（防裸奔资产）

## 4. 多维条件检索（找数据的主路径）

| 检索维度 | 过滤对象 | 典型问题 |
| --- | --- | --- |
| 任务类型 / 动作类型 | 业务标签 | 「所有抓取类样本」 |
| 场景 / 本体型号 | 业务标签 | 「厨房场景、某型号本体的第一视角」 |
| 模态 | 技术元数据 | 「含深度图和 6DoF 标注的」 |
| **label_source** | 来源标记 | 「sim_GT 与 human_GT 分开列」（[标注体系-02](../02-生产域/标注体系/02-标注质检与来源标记.md) 四分类） |
| 版本 / 状态 | 版本元数据 | 「v3.x 全部 Published 版本」（[治理 01](../04-治理域/01-版本管理与不可变快照.md)） |
| 质量指标 | gate_result / 评测报告 | 「G4 一次通过且 L1 达标的批次」（[治理 03/04](../04-治理域/03-质量门禁G0-G6.md)） |

- **样本预览**：命中集合内的样本级预览（帧抽取 + 轨迹摘要）——**预览走权限**：test/hold-out 的预览同样过 split RBAC（[治理 06 §5](../04-治理域/06-数据分流与防泄漏.md)）
- **统计画像（profile）**：数据集/版本级的分布统计（样本数、时长分布、场景占比、label_source 占比、置信度分布）——选数（该用哪版）与配比（混训比例）的决策依据

## 5. 向量检索（语义近邻，条件检索的补集）

- **布局分工**（对齐 01）：embedding **落盘**在湖仓 Parquet 向量列（数据的一部分，随版本走）；**索引**建在向量库（本篇管理，可从落盘重建——索引是衍生物，不是 SSOT）
- **索引对象**：样本级（帧/片段 embedding）、场景级、指令文本 embedding（VLM 指令的语义空间）
- **四类用途**：① 找相似（「再找十条像这样的」）；② **去重佐证**（近重复检测的证据链，[算子-07 §4](../02-生产域/算子设计/算子设计-07-四层数据集分流与防泄漏.md) 的治理侧复查入口）；③ 案例/素材挖掘（按语义聚簇找长尾）；④ **badcase 快速检索**（给一条坏样本，找全语义近邻——影响面分析的样本级补充，[治理 02 §4](../04-治理域/02-血缘制品与版本三锁.md) 的正向 complement）
- **互补关系**：条件检索 = 精确召回（确定的集合，可复现）；向量检索 = 近似召回（语义相关，供探索）——**正式取数走条件检索 + 版本引用**，向量检索用于发现与佐证，不作为正式供数依据
- **业内参照（通识）**：Milvus / FAISS / pgvector 等；选型与索引参数（HNSW 类）以实现为准

## 6. 目录挂血缘（从目录一键溯源）

- 目录条目内嵌血缘入口：数据集/版本页直接跳转 [治理 02 get_lineage](../04-治理域/02-血缘制品与版本三锁.md)（正向「怎么来的」/反向「被谁用了」）——**本篇只做入口与展示，图本体在治理域元数据服务**
- **三级对齐**：目录条目 ↔ 01 物理布局（内容指纹对账）↔ [03 快照](03-不可变快照与训练样本快照.md)（条目标注快照状态）——一个版本在目录里可见，意味着物理在湖仓、快照在快照服务、血缘在图上，四者一致
- **冷数据不断供**：数据迁冷归档（[04](04-冷热分层与TTL.md)）后目录条目仍在（元数据不随数据迁冷，治理 02 §5），检索命中后按需取回

## 8. 指标与质量门

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| 目录-物理一致率 | 条目指向的 blob 存在且 hash 一致 | 100%（对账，01 §7 同源） |
| 业务标签覆盖率 | Published 版本带全业务标签比例 | 趋势 100%（未标注仅可列举） |
| 检索时延 P95 | 条件检索 / 向量检索 | 待标定（体验底线：秒级） |
| 向量索引覆盖度 | 应建索引样本的实际覆盖 | 趋势 100%；索引可重建 |
| 预览可用率 | 预览请求成功率 | 100%（含冷数据取回场景） |

## 10. 红线与速讲话术

**红线**：

1. **目录是唯一寻址入口**：禁止绕过目录裸路径取数——权限、审计、防泄漏检查全部会被旁路（对齐治理 06「默认拒绝」精神）
2. **术语表是业务口径 SSOT**：标签必须受控（glossary 受控词表），禁止各团队自定义同义标签——「厨房/Kitchen/厨房间」三个标签等于没有目录
3. **索引不是数据**：向量索引可随时从落盘 embedding 重建；把索引当数据的系统在重建日会丢资产
4. **正式取数不走向量检索**：供数与训练引用必须条件检索 + 版本精确引用（可复现）；向量检索只做发现与佐证
5. **预览走权限**：test/hold-out 预览同样过 split RBAC——「只是看看」也是访问
6. **冷数据不断供不隐藏**：归档后条目保留可检索（元数据不迁冷），只是取数时延变长

**速讲话术（30 秒）**：

> "资产域的数据地图我按 catalog 做：数据集、版本、样本三级登记，技术、业务、操作三类元数据统一管理——技术说长什么样，业务说是干什么的，操作说还有没有人用。检索两条路：条件检索走任务、场景、本体、模态、label_source、版本这些维度做精确召回；向量检索把样本、场景、指令的 embedding 建索引，做找相似、去重佐证、badcase 近邻这些语义活，但正式供数必须走条件检索加版本精确引用，保证可复现。目录条目直接挂血缘入口，一键查这份数据怎么来的、被谁用过。这套和我做 XLB 服务注册中心一个思路：元数据寻址、受控标签、健康度过滤，查到实例再精确引用——把被寻址对象从服务换成数据资产。"
