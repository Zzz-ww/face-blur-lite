## 1. 定位：样本用于计算，数据集用于发布

“数据集为中心”保留：跨域仍传 DatasetVersion/TrainingRelease。“以样本为计算单位”是在版本内部定位变化，“列”表示可独立追踪的信号，既可同表保存，也可用按样本连接的结果表/外部大数组实现。

| 对象 | 作用 | 不变量 |
| --- | --- | --- |
| Session / Episode | 采集会话与任务轨迹，保留时序/多视角关系 | 上游身份和时间基准可追溯 |
| Clip / sample | 本期默认生产单元；单个受管时间区间 | ID 不随列重排、存储压缩或算子结果改变 |
| Frame / window | Clip 内帧或训练时采样窗口 | 使用时间戳/区间映射，不能拿表行号代身份 |
| 信号列/列组 | 手部、相机、深度、语义、质检等结果 | 带输入指纹、产出版本、状态与来源 |
| DatasetVersion | 一致发布的样本与结果集合 | Published 后不可覆盖 |

训练窗口可与 Clip 长度不同，通过 manifest 映射，不强制“每一训练帧就是一条生产样本”。

## 2. 身份和逻辑宽表

### 2.1 样本身份

设计采用 `sample_id = H(source_identity, stream_group, [start_tick,end_tick), segmentation_version)`：

- `source_identity` 绑定不可变原始内容与采集身份；`stream_group` 区分视角组，时间 tick 带单位与时间基准。
- 算子/模型升级不改变 sample_id；修改切分边界、时间基准或切分版本产生新 sample_id，以 `parent_sample_ids`/derived 血缘说明关系。
- 文件路径、表内部 row ID 都不能替代 sample_id；同内容跨会话是否去重，由去重规则和 split 防泄漏分别决定，不混用身份与相似性。

### 2.2 最小逻辑记录

```yaml
# 设计字段，非现有数据库表；单列大数组可用不可变 result_ref 保存。
sample_record:
  sample_id: s-ego-001
  source_ref: {package_id: raw-017, source_identity: sha256-source}
  episode_id: ep-009
  stream_group: ego-stereo
  time_range: {start_tick: 0, end_tick: 600, unit: frame, timebase_ref: tb-30fps-v1}
  segmentation_version: seg-1
  media_refs: [{uri: "s3://example/raw/017.mp4", sha256: sha256-source}]
  split_ref: split-manifest-003
  signals:
    hand_pose: {result_ref: hand-004, materialization_key: mat-hand-004, status: valid}
    camera_pose: {result_ref: camera-002, materialization_key: mat-camera-002, status: valid}
  parent_sample_ids: []
```

来源分类沿用 AnnotationSet 的 `label_source`，另记采集来源/本体/生成器版本；不同信号可以有不同来源，不能给整行一个 model 标签掩盖人工修订。原始媒体只读引用，新列不需要复制原视频；若候选格式嵌入 blob，显式测量转换产生的额外副本与引用策略。

## 3. 列依赖与物化键（SSOT）

| 声明 | 语义 |
| --- | --- |
| `read_fields` / `write_fields` | 精确输入/输出字段集合；前置算子 ID 仅描述顺序，不能替代字段依赖 |
| `dependency_scope` | sample / episode / dataset；跨样本平滑、全局去重/归一化须声明真实范围 |
| `input_fingerprints` | 所读字段的内容哈希或受保护的不可变结果引用，含媒体区间、标定/时间基准 |
| `materialization_key` | 对输入指纹、代码/算子版本、模型 digest、配置、Schema、随机性与必要环境约束做规范化哈希 |
| `result_state` | missing / computing / valid / invalid / quarantined，区别尚未计算与失败结果 |
| `lineage_ref` | produced_by/derived 及发布引用，使用既有血缘账本，不另建一套权威图 |

缓存命中要求键相同、产物存在且完整性/质量状态允许复用。仅“版本号相同”或“文件存在”不足以命中。全局统计、随机采样与不确定性模型应携带集合指纹、seed 和确定性等级；不能证明可复用时按声明范围重算。

前置规范需要兼容旧算子：未提供字段依赖的算子仍可执行，但不享受列级增量优化，按阶段或整集保守失效。新接入算子想启用增量能力，必须先完成声明与验证。

## 4. 由变化生成重算计划

1. **固定基线**：输入 DatasetVersion、表快照、样本选择和依赖图版本；重算过程不跟随 latest。
2. **求差异种子**：区分新增/删除样本、信号/模型/参数变化、Schema 变化与质量策略变化。
3. **求受影响闭包**：沿字段依赖传播，并按 dependency_scope 扩展样本集合；集级去重规则变化可能影响全数据集。
4. **查询可复用结果**：逐项校验物化键、完整性与状态；缺失、GC 后失效或新门禁不接受的结果不能复用。
5. **提交执行计划**：交给 PipelineSpec/作业编排，不由资产服务直接启动 GPU；每项写明样本范围、读写字段、预算与恢复点。
6. **校验并发布新版本**：汇总完整结果，执行受影响质量检查和正式发布回归，经治理晋升后由资产域装配 release。

```yaml
incremental_plan:
  base_dataset_version: ego-v3
  dependency_graph_version: deps-2
  changed: {operator: op-per-hand, from: "1.2.0", to: "1.3.0"}
  sample_manifest_ref: train-candidates-018
  recompute_fields: [hand_pose, hand_pose_smoothed, action, hand_quality]
  reuse_fields: [camera_pose, depth]
  output_candidate: ego-v4-candidate
  publication: {requires_gates: true, requires_golden_regression: true}
```

本例假设 hand 输出不回注 camera/depth，动作解算依赖平滑后的手部轨迹；若真实链路的 mask/尺度先验有其他依赖，必须扩大闭包，不能照抄复用清单。执行代码、权限和资源规格仍由原有控制/执行契约管理。

## 5. 提交、失败恢复与发布一致性

- **单项写入**：按物化键写暂存结果，校验后登记 valid；任务重试允许 at-least-once，用键与受控提交去重，不能仅凭固定 seed 假定字节一致。
- **多列一致**：相关列作为一次候选结果集合，manifest 固定各字段/结果版本。部分成功可以留作检查点，不可冒充完整 DatasetVersion。
- **并发更新**：提交检查父快照和期望版本；冲突时重新求差异/验证，不静默最后写入覆盖。具体用后端事务或 catalog 的 CAS 提交实现。
- **发布边界**：候选结果就绪 → 治理门禁/审批 → 冻结清单 → 资产 TrainingRelease；未通过的候选保持隔离。Published 的默认指针切换与旧版本内容分开处理。
- **重算范围与回归范围分离**：省去不变结果的生产计算，仍执行 G0–G6 中适用的校验和 G6 Golden 回归；只改质量阈值也要重新验证筛选分布与发布条件。

| 故障 | 处理 |
| --- | --- |
| 上游结果缺失/损坏 | 标 invalid，沿依赖图补算，禁止静默补零当有效结果 |
| 样本切分或时间戳改变 | 建新身份与映射，旧列不按行号拼接；重审 split/近重复隔离 |
| 字段维度/坐标系改变 | Schema 检查失败即阻断；显式转换也作为受版本管理的算子 |
| 部分列成功、下游失败 | 保留可验证检查点，恢复未完成项；整版发布保持阻断 |
| 依赖缺失或集合级变更 | 保守扩大重算范围；记录原因，不能虚报缓存命中 |

## 6. 三种版本与引用保护

**表快照 ≠ DatasetVersion ≠ TrainingRelease**：表快照描述存储提交；DatasetVersion 描述通过治理的样本/信号集合；TrainingRelease 固定 split、选择和消费权限。一份 release 可引用多个表快照及外部媒体对象，必须整体留存。

| 引用来源 | 保护动作 | 解除条件 |
| --- | --- | --- |
| 发布 release / 保留实验 | 钉住表精确版本、样本/媒体清单及其可达对象 | 发布留存策略允许解除；不是退出默认指针即自动解除 |
| 排队/运行训练与评测 | 开跑前登记消费意图与持久化保护，运行期间续约/对账 | 任务终止且实际消费与最终状态归档，转交实验留存或受控解除 |
| 保留快照/回滚版本 | 保留对应表元数据、媒体和结果对象 | 快照保留策略批准解除 |

GC 先读取一致的引用保护集合，再计算不可达对象；清理与新引用登记必须有并发保护，避免“检查后被引用、随后删除”的竞态。表引擎清理和外部 CAS 清理都受同一治理决策约束，不能各自按年龄独立删除。任务崩溃/续约超时需核对持久状态，不能凭心跳过期立刻删数据。

引用保护是普通清理的护栏，不阻止既有[合规删除例外](../04-治理域/07-合规引擎.md)：经裁决的数据可撤销访问、失效相关 release 并依法删除，同时保留允许留存的审计记录，不能继续承诺该版本完整重放。

## 7. 物理实现与开放读取

| 实现 | 适用起点 | 必须验证 |
| --- | --- | --- |
| Parquet 结果表 + 不可变媒体 + manifest | 复用现有生态，按 sample_id/信号版本连接 | 大数组布局、选择性重算写放大、跨表一致提交 |
| Lance 表 + 外部媒体或 blob | 列信号更新及多模态随机读取候选 | SDK/格式版本、更新粒度、权限、保留与旧版读取 |

Iceberg/Hudi/Delta、Lance、媒体格式及 catalog 属不同能力层；不把 Lance 当作必须替代所有表格式的统一结论，也不要求部署 LanceDB 才能实现逻辑契约。物理存储分区、split 权限不能因宽表连接而放开。

开放读取经 TrainingRelease 发放精确版本清单和受限凭证；兼容引擎可直读授权的数据面。catalog 管元数据和授权，无需代理全部媒体字节。版本/Schema/媒体引用的兼容测试见[消费04](../06-消费域/04-训练供数性能与DataLoader基准.md)。

## 8. 指标与设计验收

| 指标/场景 | 计算或验收口径 |
| --- | --- |
| 复用率 | 同一变更计划中复用的有效结果项 / 所需结果项；同时报字节量、估算与实际算力 |
| 增量计算与写放大 | 实际重算样本/字段、读写字节、GPU/CPU 占用；不只数新增列 |
| 计划完整性 | 声明依赖的受影响闭包均被覆盖；缺依赖走保守路径 |
| 升级场景 | 按 §4 假设复用相机/深度；检查新旧版读取、结果比较和 G6 回归入口 |
| 并发/失败场景 | 冲突不覆盖、重复提交不重复发布、半成品不能晋升 |
| 保留场景 | 退出默认指针的活跃训练版本仍可读，受保护对象不会被普通 GC 选中 |

数值阈值以实际规模标定；本篇只完成设计验收清单。有效小时、成本与收益不在本篇另定义，统一见[成本06](../02-生产域/算子设计/算子设计-06-算子成本模型.md)。
