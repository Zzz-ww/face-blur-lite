# 04 · 训练供数性能与 DataLoader 基准

> 06-消费域第 4 篇。定位是定义 TrainingRelease 从准入到喂给训练进程的时延、完整性和复现口径，并用同一训练工作负载比较取数路径。供数契约见 [消费域 01](01-训练导出与模型平台衔接.md)，TrainingRelease 的装配和准入见 [资产域 05](../05-资产域/05-TrainingRelease装配与导出.md)。模型平台负责训练循环、设备侧埋点与检查点，数据平台提供经授权、可校验的供数与血缘证据。

## 1. 组件与职责

| 组件 | 职责 |
| --- | --- |
| TrainingRelease 接入 | 验证准入结果、manifest 摘要、精确版本、样本快照与 split 授权，开跑前登记消费引用 |
| 供数引擎 | 按授权清单读文件、对象范围或固定表快照，校验输入字节并上报读、解码与预取情况 |
| DataLoader | 应用采样和 rank/worker 分片规则，解码、变换、组合并交付批次。实际执行位置随引擎与模型配置记录 |
| 调度与训练 | 汇总每个 rank 的数据就绪状态与资源状态，统一开跑。模型平台记录 H2D、训练 step、实际消费游标与检查点 |

## 2. 供数准入与就绪

1. **开跑前登记并 pin 快照。** 以 `training_id` 和精确 release 引用幂等登记，验证 `dataset_version@release_id`、manifest 摘要、split 授权和 `sample_snapshot_ref`，建立运行中的快照保护引用，再启动预取与训练。重试沿用同一次登记，保留各 attempt 状态。运行中续保与基于引用的回收见资产域。
2. **数据面按清单读。** 引擎可使用短期凭证按授权 manifest 直读对象存储或固定表快照。元数据服务负责准入、签发及审计，数据字节可由存储直接传输。授权收敛到该 release、所需 split、对象或表及其必要索引和媒体范围。对象或表跨 split 时使用可隔离访问的发布布局或数据通道，单靠客户端过滤无法提供权限隔离。版本固定到清单，禁止发现数据后自行拼装或跟随浮动指针。 [资产域 05](../05-资产域/05-TrainingRelease装配与导出.md) · [治理域 06](../04-治理域/06-数据分流与防泄漏.md)
3. **声明供数模式。** 每个 rank 检查实际可达的本地或共享数据与缓存；调度以全部 rank 的模式化就绪信号和 gang 资源就绪作为开跑条件。预取范围、就绪期限及后续预算随任务记录。
4. **结束时对账。** 按 release、split 和 attempt 回写实际消费样本、最后一次已提交的进度、校验统计与停止原因。区分已读、已校验、已交付和进入训练的批次，保留失败任务和部分消费证据。运行保护在终态对账后按资产域规则收尾，审计记录继续保留。 [消费域 01](01-训练导出与模型平台衔接.md) · [治理域 02](../04-治理域/02-血缘制品与版本三锁.md)

| 供数模式 | 每个 rank 的开跑条件 | 开跑后约束 |
| --- | --- | --- |
| 离线全量预取 | 任务声明的全量输入已本地化或在分配给该 rank 的缓存可读，按 manifest 验完所需数据；资源及工作目录就绪 | 读取仍受授权与校验状态约束；缓存丢失时回到已登记的同一快照重新准备 |
| 流式加载 | manifest、权限、版本和快照已验证，首批工作集或声明的启动预取窗口已可读且校验通过；预取队列和后续供数预算可观测 | 使用经过验证的块，持续观测各 rank 后续有效吞吐、预取队列低水位及尾延迟；预算按目标样本速率、实测读放大与存储限流标定 |

流式预取窗口覆盖首批所需列块、视频头及解码依赖的关键帧和媒体块。数据就绪率按达到对应条件的 rank 数除以计划 rank 数计算，开跑时为 100%。供数完整性覆盖率按**通过校验的实际消费块数 ÷ 实际消费块数**计算，目标为 100%。另记校验尝试与失败数。空消费登记为无样本。 [冷热分层与预热](../05-资产域/04-冷热分层与TTL.md) · [调度与多租户](../03-管控域/02-调度与多租户.md)

### 字节校验

- 整对象模式按 manifest 校验算法、长度、对象版本及摘要。全量验证后可从受保护的不可变缓存切片读取，缓存记录绑定对象版本与内容摘要，交付前确认缓存内容仍可信。
- 大视频按 range 读取时，使用绑定对象版本的分块校验清单。清单记录块边界、长度和摘要，验证请求范围覆盖到的所有完整校验块，包含视频索引及解码依赖，再切出需要的字节。可用可信根验证分块证明。清单与证明缺失时通过整对象校验缓存提供范围读取，整对象摘要本身无法证明单次 range 响应的内容。
- 校验失败停止交付并通知协调器停止训练，保留 object/blob 标识、版本、range、期望与实际摘要和已消费游标。后续 attempt 须重新通过校验，使用同一授权快照及可恢复检查点。

## 3. 时间边界与归因

| 指标 | 计时边界 | 统计说明 |
| --- | --- | --- |
| 任务首批时延 | 提交固定 release 的训练请求 → 全部参与 rank 的首批输入满足模型第一处 GPU 使用的数据依赖 | 分解准入、排队/资源分配、模式化预取、Loader 首批和 H2D，记录实际重叠；首个训练 step 完成另报 |
| 准入时延 | 训练请求接收 → 清单、授权、版本校验与消费引用登记完成 | 记录预取开始和各 rank ready、gang ready 的事件；可与排队重叠 |
| 数据预取时延 | 任务触发模式化预取 → 最后一个 rank 达到本地就绪条件 | 记录缓存预热及归档取回，按离线或流式口径分别报告 |
| Loader 首批时延 | 开始创建本轮迭代器 → `next()` 首批返回 CPU 批次 | 包含首轮 worker 启动与迭代器预填，逐 rank 记时；另报首个 `next()` 耗时 |
| `DataLoader next wait` | 每次调用 `next(iterator)` → 数据返回训练进程 | CPU 单调时钟，包含队列等待、同步转换等；报告首批与稳态分布 |
| 读、解码和预处理 | 逐 worker 或执行流记录发起读请求、字节可用、校验结束、解码起止、变换/拼批起止 | 拆出读和校验、视频解码、样本窗口构造以及图像变换；声明 CPU/GPU 执行位置，避免重复归因 |
| H2D | GPU 拷贝流实际开始传输 → 批次所需传输完成 | 以设备事件或时间线计时，同时记录提交与排队；若异步，追踪输入等待的事件依赖 |
| 训练 step | 模型平台进入逻辑 optimizer step，含首个微批次取数 → 本次更新完成 | 包含同一步的梯度累积微批次；记录计算、通信、数据等待与其它开销。用一致的 step 边界计算吞吐 |

**GPU 数据等待**指 GPU 或训练关键路径因下一批输入依赖未满足而暴露的等待。用带 `rank/step/batch_id` 的 CPU、CUDA、H2D、通信时间线对齐定位。前一批计算覆盖住的 `next()`、读、解码、拷贝时间，以及由通信、同步、编译或主机提交造成的空档，按实际根因归类。拆出等待 CPU 批次、暴露的 H2D 和设备预处理，用依赖关系去重，避免在不同流之间累加重叠时间。单独报告最后就绪 rank 导致的全局尾部影响，多卡其他 rank 的同步等待与根因 rank 关联。

常规吞吐测量让流水线自然重叠，按窗口采集端到端已完成步数。另选代表性窗口做 profile，标注埋点开销。卡内阶段使用设备时钟，跨进程阶段以同一个调度时钟记录或校正事件时钟，避免直接相减无同步的时间戳。缺少可归因时间线时，GPU 数据等待标记为未测，仍可报告 CPU `next()` 等待。

```text
请求提交 ── 准入与快照登记 ── 模式化预取 ── 各 rank 数据就绪 ─┐
    └──── 模型初始化 / 排队 / 资源分配 ── 资源就绪 ──────────┤
                                                           ▼
             gang 就绪 → 迭代器启动 → 首批 CPU → H2D / 设备预处理
                                                    └─→ 首批 GPU 可用 → 首步完成
```

示意中的并行阶段按实际记录的依赖计算，任务首批时延以端到端边界为准。单 rank 的 `next()` 在前一批 GPU 计算期间返回，且其后 H2D 在模型需要输入前完成时，该批次可以有 CPU 等待但没有 GPU 数据等待。

## 4. 基准对照

| 组别 | 对照路径 | 记录重点 |
| --- | --- | --- |
| A · 原生 LeRobot | 标准 Parquet + MP4，按任务清单预取或本地化，以原生数据集读取 | 离线准备、元数据打开、随机窗口命中、视频 seek/解码、缓存占用 |
| B · 原生 streaming | 标准 LeRobot 数据，以公开实现的流式路径访问对应存储 | 首批范围读、解码跨度、请求放大、随机采样与 checkpoint 恢复 |
| C · Lance 候选 | 固定 Lance 表快照，读取保留原 MP4 blob 的候选布局 | 转换后的媒体内容校验、远端读取和索引开销、随机采样、是否可恢复相同消费顺序 |

### 固定输入与实验矩阵

- **固定数据契约。** 同一准入 release 或其经核验的等价物理视图，锁定逻辑训练清单及摘要、split、样本 ID、episode、摄像头、时间窗口、标签和动作版本。固定 sampler 种子和分片规则、batch/全局 batch、梯度累积、`drop_last`，以及解码、图像变换、归一化参数和执行后端。每个拓扑的对照先复放可比的样本顺序，同步核验各组原生采样的能力。
- **固定环境。** 同一比较组使用同型号 GPU/CPU、内存、网络与对象存储区域/服务级别、NVMe 与缓存配额、软件栈、训练模型与精度、后台负载预算；记录驱动、编解码器、框架和引擎版本。单独记录各引擎布局、索引构建及本地化等准备开销，并把每次任务在线等待纳入首批时延。
- **独立调优。** 主矩阵覆盖单 GPU 与多 GPU、cold 与 warm。每组、每种拓扑在相同资源上限内单独扫描每 rank `num_workers = 0/1/4/8/16`，以及适用的预取深度、持久 worker、解码线程和 pinned memory。记录受限或不支持的格子和原因。调优与正式测量使用独立重复轮次，记录公共配置和各组最佳合规配置。
- **缓存状态可追踪。** cold 明确训练节点本地缓存、共享缓存和可控页缓存的初始状态，无法清理的服务端缓存记录为限制。warm 用固定同版本、同热身窗口与预热方式构造，报告缓存覆盖与命中率。交错运行顺序、为每次冷试验重建初始状态，记录并发负载与限流情况。
- **分层计量。** 先测纯 Loader 交付能力和读取/解码各段资源占用，再跑同一模型的端到端训练；达到相同的测量窗口规则后比较稳态。记录每次首批、样本/秒、step/s、step p50/p95/p99、各 rank 等待和 GPU 数据等待率，对独立重复报告中位数、波动及样本量；p99 样本量不足时标成未标定。多卡另报最慢 rank 及全局吞吐。失败、超时和有效运行数都进入结果。

| 测试层 | 运行方式 | 用于判断 |
| --- | --- | --- |
| 启动 | 每次新建任务，覆盖冷缓存与热缓存，分别测各路径实际准备过程 | 任务首批总时延及其中的模型初始化、调度、预取、Loader 和传输开销 |
| 同序供数 | 在同一 split 上按样本清单回放相同窗口顺序，固定拓扑、资源及变换 | 内容与读取、解码、拼批时延是否可比 |
| 原生采样 | 在同一采样目标下运行各引擎支持的连续访问、随机或加权采样 | 功能覆盖、样本分配、随机访问成本与恢复能力 |
| 同模型训练 | 单 GPU 和生产代表性多 GPU 均运行，保留冷启动，另取稳定 step 窗口 | 加载瓶颈是否暴露在训练关键路径，吞吐和尾部是否改善 |

合并报告时，供数吞吐按交付的有效样本数统计，训练吞吐按完成 step 中实际参与训练的逻辑样本数统计。对数据并行 rank 汇总，对模型并行复制的批次去重，并记录 padding、丢样和采样策略本身产生的合法重复。不同拓扑间比较时，明确是固定全局 batch 还是固定每 rank batch。

### 等价性与恢复验收

1. **媒体与结构化内容。** 用同一视频对象或提取的 blob 验证长度及完整摘要，抽样覆盖 episode 边界、跨块窗口、不同摄像头和关键帧附近的随机定位。对齐帧序/时间戳、颜色通道、像素和变换后的张量，核对 state、动作、标签、缺失填充值与窗口 padding。按字段预先声明精确比较或数值容差，保留失败样本 ID 和判定依据。
2. **采样能力。** 分别验证连续与随机访问、全局 shuffle、各 rank/worker 样本分配、重复/漏样、配额与加权采样。用样本 ID 序列或其分段摘要校验同序对照。仅支持近似或局部 shuffle 的组别单列其采样语义，比较同一采样制度下的性能结果。
3. **断点恢复。** 固定 epoch、sampler 状态、shuffle 缓冲状态或可重放的流位置、rank/worker 拓扑与变换随机状态，检查从最后一个已提交的训练检查点恢复后，接续批次与无中断基线一致。预读队列里的数据按相同顺序重建或恢复，恢复起点使用已提交批次进度。拓扑变化和确实只支持样本集合或分布一致的路径分别记录边界。验收基于数据内容、采样语义与恢复证据，模型浮点损失允许受训练栈影响。

无法回放同序输入的路径记录可比较的样本范围与采样语义，比较同序读取时延时标记该格不可比。转换、索引构建或为了回放而添加的适配层计入对应测试路径，结果说明该层是否出现在正式训练中。

## 5. 故障处理与记录

| 现象 | 处理 | 证据 |
| --- | --- | --- |
| 权限到期或撤销 | 到期时按原 release 与 split 复核并续发。续发失败或授权撤销时暂停发批，按模型平台的统一停止策略处理全部 rank | 失效时间、授权范围、续发结果、最后消费游标 |
| 断网、限流或短时超时 | 对同一固定对象、范围或表快照有限重试，监测队列；超过预算时协调停跑或从已提交检查点恢复 | 重试次数、限流信号、队列水位、最后有效快照与检查点 |
| 缓存污染或摘要不匹配 | 隔离缓存，停止训练并记录校验失败；重新取数并验证后才可重启 | 预期与实际摘要、对象版本、块范围、命中层、已消费进度 |
| 负载漂移或慢 rank | 记录 CPU/解码争用、缓存命中、带宽和通信，报告预算偏离；对照运行在同等负载下重测 | 负载时间线、各 rank 水位与吞吐、版本和硬件配置 |
| 快照 pin 或终态对账失败 | pin 失败时阻止开跑；终态回写失败时以同一登记键重试，运行状态未核清前保留保护引用 | `training_id`、attempt、pin 引用、终态写入结果和对账游标 |

## 7. 指标与判定

| 指标 | 判定方式 |
| --- | --- |
| 准入与数据完整性 | 版本、split 授权和开跑前消费引用登记覆盖 100%；已消费块全部通过校验，单次失败须留证 |
| 首批时间与就绪 | 模式化就绪率在开跑时为 100%；首批及各阶段时延按 cache、拓扑和路径报告，目标待标定 |
| 稳态供数与读放大 | 有效样本/秒、读字节/有效样本、请求数、CPU、内存、缓存命中、解码和 H2D 结合分析，目标待标定 |
| GPU 数据等待与训练吞吐 | 用训练关键路径上可归因的数据等待时长除以同测量窗口的训练时长，同时报告 step/s 和每 step 尾延迟；目标待标定 |
| 数据等价与恢复 | 内容、采样覆盖及接续顺序满足预先声明的验收语义，偏差和失败单独记录 |

读取收益要结合 profile 和完整训练指标判定。解码、设备传输、模型算力或慢 rank 足以吞掉读取提速，冷启动节省也可能伴随更高稳态尾延迟。候选路径只有通过数据等价与故障验收并获得目标工作负载下的实测结果，才进入选型比较。成本与有效数据小时的口径见 [算子设计-06](../02-生产域/算子设计/算子设计-06-算子成本模型.md)。

每组正式结果附上以下证据，便于复跑和定位性能差异。

- 运行标识、精确清单摘要、引擎版本和配置、缓存状态、负载及测量窗口。
- 性能分布、独立重复次数、空跑或失败次数、代表性时间线及对应批次和 rank。
- 等价性与故障演练结果、能否精确续序、仍需标定的资源及调度参数。
