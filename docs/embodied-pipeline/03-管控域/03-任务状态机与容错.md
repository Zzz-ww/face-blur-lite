## 3. 状态持久化与控制面重启恢复

- **存哪**：作业状态存**平台元数据库**（etcd/关系库），不存 Ray GCS——GCS 是集群内部的元数据中枢（调研笔记-02 §1.2），集群销毁即消失；按需 RayJob（跑完即毁）的最终状态必须由平台侧留痕
- **怎么写**：每次状态迁移带 `resourceVersion` 做 **CAS 乐观锁**——两个控制器实例/并发生命周期事件同时推进同一作业时，后写者冲突重读再试，杜绝状态回退或跳跃
- **重启怎么恢复**：控制面重启后**不依赖内存**——reconcile 重建：读 CR 实际态（RayJob status/Pod 状态）+ 事件流，把内存状态机重新收敛到实际（level-triggered，与 [01 篇 §3](01-KubeRay控制面.md) 同范式）。**状态机是期望态与实际态的对齐结果，不是副作用日志**
- **审计**：每次迁移记录（前态、事件、后态、时间戳、操作方）追加写不可改——回答「这个作业为什么 Failed」不靠翻日志

## 4. 完整状态机与转换表

主干：`Pending → Queued → Admitted → Starting → Running → Succeeded`；分支：`Retrying / Failed / TimedOut / Cancelled / Evicted`。

| 当前态 | 事件 | 目标态 | 动作 |
| --- | --- | --- | --- |
| Pending | 静态校验通过（[04 篇 §5](04-PipelineSpec与编排DSL.md)） | Queued | 创建 Workload 入 LocalQueue（02） |
| Queued | Kueue 准入 | Admitted | 资源预留；触发 KubeRay 起 CR（01） |
| Admitted | 集群 ready（CR status/探针） | Starting | 提交 entrypoint；接通心跳 |
| Starting | entrypoint 运行、首算子心跳到达 | Running | 记开始时间（SLO 时钟起点） |
| Running | 瞬时失败且重试预算未耗尽 | Retrying | 指数退避后从检查点续跑（§7） |
| Retrying | 恢复成功 | Running | 继续推进；重试计数保留 |
| Retrying | 重试耗尽 / 结构性失败 | Failed | 终态拦截上报，不再重试（算子-03 §7） |
| Running/Retrying | `activeDeadlineSeconds` 超时 | TimedOut | 终止作业 + 清理（§8） |
| 任意非终态 | 用户取消 / 上游 DAG 级联取消 | Cancelled | 沿 DAG 向下游传播（K8s 驱逐语义） |
| Admitted/Running | 被抢占 / spot 回收（02 §5.2） | Evicted | 释放资源，保留检查点，重回 Queued |
| Running | 数据性失败（样本级） | **不迁态** | 打标降级 + 进 DLQ（§6），主流程继续 |
| Running | 全部算子过 Gate（G2–G4） | Succeeded | 产物落库 + 血缘登记（[算子设计-04](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md)） |

- **状态来源三路合流**：RayJob/RayCluster `.status`（权威）+ 算子心跳（细粒度进度）+ K8s events（驱逐/OOM 等旁路信号）；冲突时以 CR status 为准，心跳只做进度细化
- `Evicted` 与 `Cancelled` 的区别：前者**还会回来**（重排队续跑），后者是终态——这是抢占语义能成立的前提（[02 篇红线 4](02-调度与多租户.md)）

## 5. 四级故障域（谁出事、谁负责恢复）

| 故障域 | 典型故障 | 检测信号 | 恢复机制（配置项通识） | 状态机影响 |
| --- | --- | --- | --- | --- |
| **任务级**（Ray task/Actor） | 单分片推理 OOM/超时、Actor 崩溃 | 任务异常、Ray 重试计数 | Ray task 重试 `max_task_retries`、Actor 重启 `max_restarts`（节点内重启保留编号） | 不迁态；耗尽上抛作业级 |
| **作业级**（RayJob） | entrypoint 失败、瞬时崩溃 | RayJob `.status` 失败事件 | `restartPolicy` / `backoffLimit` 重启 | Running→Retrying（§4） |
| **节点级**（worker） | worker Pod 崩溃、GPU 故障、spot 回收 | Pod NotReady/驱逐 events | KubeRay 重建 Pod + Ray 节点丢失后任务重调度（[01 篇 §6](01-KubeRay控制面.md)）；spot 走 Evicted | 检查点续跑（§7） |
| **集群级**（head/GCS） | head 故障、GCS 元数据受损 | head 探针失败 | 开 GCS FT：外部存储恢复、worker 重注册（01 篇 §6）；未开 FT：集群重建 | 重建后定位最近一致检查点重放（§7） |

判断口径：**从下往上归因**——任务级能兜住的不惊动作业级，作业级能兜住的不惊动节点级；升级的标志是「重试预算耗尽」或「物理基础不在了」。

## 6. 失败四类的控制面编码与 DLQ 实现

### 6.1 失败类别编码（引用不复制）

四类定义（瞬时/结构/资源/数据）见 [算子设计-03 §7](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md)。控制面为每个失败事件附加结构化编码：

```yaml
failure_event:                   # 设计通识（字段以实现为准）
  job_id / node_id / sample_ref
  failure_class: transient | structural | resource | data   # 四类对齐算子-03 §7
  retry_policy: {backoff: exponential, base: 30s, cap: 15min, max: 3}
  terminal: true|false           # structural=true 且不可重试
```

### 6.2 重试与幂等

- **指数退避 + 上限**：`30s → 2min → 8min`（封顶 15min、≤3 次，示例值待标定）——防雪崩式同步重试打挂上游
- **幂等前提**：重试安全 = 算子幂等（规则算子天然幂等；模型算子固定 seed，[算子设计-02 §0](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md)）+ 检查点续跑（不整段重跑）
- **结构性失败不重试**：schema/参数/版本错误重试一百次也一样——立即 Failed + 上报，修 spec 再提交（04 篇提交期校验把这类失败尽量前移拦截）

### 6.3 at-least-once 的理由（引用）

恢复语义与粒度（样本/批次/阶段级、对象存储介质、at-least-once 不做 exactly-once）SSOT = [算子设计-03 §8](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md)；本篇只做**恢复流程编排**（§7）。

### 6.4 DLQ 实现（队列 + 表）

数据性失败样本进 DLQ 不阻塞主流程（算子-03 §7 口径），落地为「队列（驱动仲裁）+ 表（留痕血缘）」：

```yaml
dlq_record:                      # 设计通识（表结构示意，字段以实现为准）
  record_id / sample_id / segment_id
  failed_at: {operator: op-per-cam@1.1.0, stage: L2, job_id}
  failure_class: data            # 四类之一（多为 data；structural 类不进 DLQ 直接拦截）
  reason: "空帧占比 37%，时间戳断裂"
  lineage_ref: {data_version, operator_version, model_version}   # 三锁（算子设计-04）
  state: pending → arbitrated → reflowed | discarded
  arbitrated_by / arbitrated_at  # 人工仲裁留痕
```

流程：样本打标降级继续跑 → DLQ 落记录 → 人工仲裁（标注台/治理域通道）→ **reflowed**（带豁免/修复标记重新入队）或 **discarded**（废弃，登记原因）。**DLQ 率即人工介入率的执行层来源**（算子-03 §7 口径，G4 工程门消费）。

## 7. 检查点恢复的控制面流程

```
运行中 ──barrier──► 快照（分片清单 + 游标 + 中间产物指针）──► 对象存储（OSS/S3）
                                                              │
故障后：读血缘 output_hash（[算子设计-04](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md)）
        │
        ▼
定位最近一致检查点 ──► 重放缺失分片 ──► hash 校验一致 ──► 续跑
                                       （at-least-once：重复产出靠算子幂等去重兜底）
```

- **定位**：「最近**一致**」不是「最近」——重放后每个分片产物 `output_hash` 与血缘记录比对，不一致的检查点弃用（防从脏检查点续跑）
- **不做 exactly-once**：成本高且数据管线不需要（算子-03 §8 口径）——重复产出由幂等去重消化
- **与四级故障域配合**：任务级/作业级 = 段内续跑；节点级 = 该节点在途分片重放；集群级 = 从最近一致检查点整体重放（01 篇 GCS FT 未开时的兜底路径）

## 8. 超时、取消级联与清理

- **超时**：`activeDeadlineSeconds` 管作业级 wall-clock；算子级超时口径（如 GPU 推理段 ≤4h/样本批，示例值）见算子设计-03 §5——超时进 TimedOut，不占资源硬耗
- **取消级联**：上游取消沿 DAG 向下游传播（K8s 驱逐语义）——下游正在跑的算子收到终止信号后**写检查点再退**（优雅取消），不许直接 SIGKILL 丢进度
- **清理三层**：`shutdownAfterJobFinishes`（按需集群跑完即销）→ `ttlSecondsAfterFinished`（作业对象保留期，留排查窗口）→ 中间产物 GC（分片过 G2 校验后清缓存，调研笔记-02 §6.4「防磁盘膨胀」口径）

## 9. 指标与质量门（L2/L3 落点）

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 端到端成功率 | 提交到 Succeeded 的比例（月度） | L2 主指标；SLO 示例 ≥99%（算子-03 §10） |

## 11. 红线与面试话术

**红线**：

1. **状态机与 Ray 集群解耦**：平台状态存元数据库，不存 GCS——按需 RayJob 跑完即销，状态必须活过集群；把 GCS 当平台状态存储 = 集群级故障连带丢作业账本
2. **状态迁移必须乐观锁 + 审计留痕**：并发推进（双控制器/生命周期事件竞争）靠 CAS 防回退跳跃；不可改的迁移记录是「为什么 Failed」的唯一权威答案
3. **重试只给可重试的失败**：结构性失败重试是浪费资源放大故障；瞬时类指数退避 + 上限 + 检查点续跑，缺一不可
4. **数据性失败不阻塞主流程**：进 DLQ 带全血缘与原因，人工仲裁回流或废弃——DLQ 不是垃圾桶，record 不可无仲裁废弃
5. **脏检查点必须弃用**：重放后 hash 与血缘不一致的检查点禁止续跑——从脏点续跑等于把错误焊死进产物
6. **取消要优雅**：级联取消先写检查点再退；直接 kill 丢进度 = 白白烧掉的 GPU 秒

**面试话术（30 秒）**：

> "作业状态机我把它从 Ray 集群里解耦出来，存在平台元数据库，配乐观锁防并发双写，控制面重启后靠 reconcile 从 CR 实际态和事件流重建——跟我在 XLB 做的控制面状态恢复是同一个范式：状态是对齐出来的期望态，不是副作用日志。主干状态 Pending 到 Succeeded，关键分支 Evicted 和 Cancelled 分开：被抢占或 spot 回收的作业保留检查点重排队，还会回来；取消是终态。故障分四级：任务级靠 Ray 的 max_task_retries，作业级靠 backoffLimit，节点级 KubeRay 重建 Pod 加任务重调度，集群级靠 GCS FT 或整体重建后从检查点重放。失败按四类编码，数据性的进 DLQ 带三锁血缘，人工仲裁后回流或废弃，DLQ 率就是人工介入率的执行层来源。检查点是 at-least-once，恢复时必须过血缘 output_hash 校验，脏检查点宁可弃用重放，不能带病续跑。"
