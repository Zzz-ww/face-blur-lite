# 06 · 优先级抢占与公平性（PriorityClass / 抢占护栏 / DRF / 防饥饿）

> 03-管控域第 6 篇，拆自 [02-调度与多租户](02-调度与多租户.md) §5 深化。定位：**资源紧张时的秩序**——高优作业（Golden Set 回归 G6、线上 badcase 修复）怎么插队、低优怎么被抢、被抢了怎么体面回来、长期低优怎么不饿死。边界：准入与队列在 [02](02-调度与多租户.md)；被抢占语义（Evicted→Queued）在 [03-任务状态机与容错](03-任务状态机与容错.md) §4，检查点恢复流程在其 §7（深化归 [09](09-检查点与断点续跑.md)）；spot 实例回收同通道；本篇只讲优先级来源、抢占模型与护栏、公平性建模。

## 核实状态（2026-10-19）

- ✅ 已核实：PriorityClass = K8s 原生机制（Pod/作业优先级，抢占依据）；Kueue 抢占策略 `withinClusterQueue`/`withinCohort`/`ReclaimNominalQuota` 为官方文档化机制（对象字段与策略名随版本演进有差异，以部署版本为准，同 [02 篇核实状态](02-调度与多租户.md)）；DRF（主导资源公平）= 多资源公平调度通识（max-min 的多维推广）；高优示例（Golden Set 回归 G6 / 线上 badcase 修复）与 [算子设计-03 §5](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md) 同口径
- ⚠️ 设计通识：抢占护栏细则（只抢可从检查点恢复的批处理、Golden/发布类不得被抢）、P0–P2 分级建议、防饥饿年龄加权与最小份额策略为本平台设计（以团队标定为准）
- ❓ 待补：抢占成功率/被抢恢复率阈值、高优排队时延 P95 目标、年龄加权系数与最小份额数值——待团队标定

## 1. 定位与边界

- **本篇管**：**优先级体系**（优先级从哪来、怎么叠加）、**抢占模型与护栏**（谁抢谁、被抢的怎么回来、什么不许抢）、**公平性建模**（多资源公平、借用公平、防饥饿）
- **不管**：准不准入、配额怎么算（02 §4）、被抢后的状态推进与检查点细节（03 §4/§7）、跨作业 DAG 里 step 级优先级怎么声明（05）
- **一句话**：优先级决定「排队顺序与挤占资格」，公平性决定「长期不饿死」——两件事一套体系（PriorityClass → Workload priority → Kueue 抢占策略）

## 2. 优先级体系（来源、叠加与分级）

| 组件 | 归属层 | 职责 |
| --- | --- | --- |
| PriorityClass | K8s 原生 | 优先级声明源头：平台/用户给作业打的优先级类 |
| Workload priority | Kueue | 排队单元携带的优先级（由 PriorityClass 映射）——排队与抢占的排序依据 |
| LocalQueue / ClusterQueue 优先级 | Kueue | 队列级叠加：同一配额主体下多个入口队列的相对次序 |
| 抢占控制器 | Kueue | 按策略选被抢对象并执行（§3） |

- **来源与叠加（三层合成）**：单作业声明（PriorityClass）→ 排队快照（Workload priority）→ 队列级（LocalQueue/ClusterQueue）——**排队序是合成的，不是单值排序**；只看作业优先级会漏掉「同优先级作业落在不同入口队列」的次序问题
- **分级建议**（通识，具体分级以团队为准）：

| 级 | 谁在这里 | 语义 |
| --- | --- | --- |
| P0 | Golden Set 回归（G6）、线上 badcase 修复 | 质量基准与线上止血——可插队、**不得被抢**（§3.3） |
| P1 | 常规生产批（L2/L3 日常数据生产） | 平台主干负载，保底配额内正常排队 |
| P2 | 探索性/评测批 | 可被抢占的主体，靠检查点续跑兜底 |

- **高优为什么是这两类**（02 §5.2 口径展开）：G6 回归是版本晋升的基准关（[治理 05 §3](../04-治理域/05-回归与发布.md)）——它排队排长 = 发布流程堵在门口，全平台的版本流转慢一拍；线上 badcase 修复是止血批——回流样本按「新数据」走全门禁复检（[消费 03](../06-消费域/03-Badcase回流闭环.md) §6/§7），修复批拖慢 = 数据飞轮停转。两类共同点：**下游有整条流程在等它**，不只是它自己慢
- **P2 为什么愿意被抢**：被抢 ≠ 白干——检查点续跑（03 §7）让被抢方从断点回来；换来的是 P2 平时能借到超出自身配额的空闲资源（02 §4.2 借用），被抢是这笔账的代价

> **与负载均衡/控制面同构**：优先级队列 ≈ 转发面 QoS 队列（高优业务先进、低优业务不丢只是后进）；队列级叠加 ≈ 端口/板级优先级与业务优先级的合成；抢占 ≈ 高优业务挤占低优带宽、低优降级重试——**资源争抢的秩序问题在哪个控制面都长一样**，差别只是被管对象从带宽换成 GPU。

## 3. 抢占模型与护栏（重点节）

### 3.1 三种抢占策略（官方机制，何时谁让路）

| 策略 | 触发场景 | 谁让路 |
| --- | --- | --- |
| `withinClusterQueue` | 同一 ClusterQueue 内高优在等、低优在跑 | 队列内低优 Workload |
| `withinCohort` | 组内跨队列：高优队列要资源，组内有队列借了份额 | 借出方队列的低优 Workload |
| `ReclaimNominalQuota` | 配额主人回收自己的保底份额 | 正占用主人份额的组内作业 |

- 与 02 §4.2 的衔接：cohort 借用「空闲即借、回收有度」——**ReclaimNominalQuota 就是「回收有度」的执行器**，没有它，借用就是有去无回
- 策略选择是配置项不是默认全开：开哪种、开到哪一级，决定抢占的波及范围（队列内 → 组内 → 跨池回收），配置随团队标定（❓）

### 3.2 抢占的完整链路（与状态机对接）

```
高优 Workload 到达，配额/资源不足
   │ 抢占控制器选被抢对象：策略（§3.1）× 护栏过滤（§3.3）
   ▼
低优作业 → Evicted（03 §4：释放资源、保留检查点）
   │ 资源让出 → 高优作业 Admitted（插队完成）
   ▼
被抢作业重回 Queued（带原优先级与排队年龄）
   │ 再次准入 → 从检查点续跑（03 §7；深化见 09）
   ▼
Running（从断点回来，不是从头来）
```

- **Evicted ≠ Cancelled**：被抢的作业「还会回来」，取消是终态——这是抢占语义能成立的前提（[03 §4](03-任务状态机与容错.md) 对两者的区分及状态机图）
- **spot 实例回收同通道**：云侧提前回收节点 = 外部驱动的被抢占——同样走 Evicted → Queued → 检查点续跑；因此**上 spot 的作业必须满足护栏第 1 条**（可检查点恢复），spot 折扣是用可恢复性换的
- **抢占是两段动作不是一段**：让出资源（Evicted）与高优准入（Admitted）之间可能有空隙——护栏里「只抢可恢复的」保证空隙不变成损失

### 3.3 护栏三条（本平台设计，以团队标定为准）

1. **只抢「可从检查点恢复」的批处理**——被抢后从头重跑等于先浪费一次再浪费一次；恢复不了的作业在选被抢对象时就被过滤掉，不是抢完再发现
2. **Golden Set 回归/发布类作业不得作为被抢客体**——动了它就破坏回归基准与发布在途状态（发布中作业被抢 = 版本状态不可信）；被抢客体过滤名单是硬配置
3. **抢占必须可观测、留审计**——每次抢占记录谁抢谁、策略、释放量、恢复耗时，入审计（[横切 02](../90-横切/02-安全合规.md)）；无审计的抢占不许发生

## 4. 公平性建模（多资源 / 借用 / 防饥饿）

### 4.1 多资源 DRF（主导资源公平）

- **单维度为什么是陷阱**：只对齐 GPU 份额，「GPU 大户 CPU 也大户」的租户在 GPU 维度看份额正常，CPU 维度早已挤占别人——组合型大户总能挑一个对自己有利的维度钻空子
- **DRF 口径**（通识）：对每个租户算所有资源维度的份额，取最大者为主导资源；调度对齐各租户的**主导资源份额**（max-min 的多维推广）——想多占，至少有一个维度上别人也同步多占了，占便宜没有免费维度
- **本平台维度**：GPU 为核心 + CPU + 内存（与配额维度一致，02 §4.1 resourceGroups）——公平性建模的维度集合必须与配额声明的维度集合相同，否则配额管得住的公平管不住

### 4.2 cohort 借用公平

- **借用按需、回收有度**（02 §4.2）：空闲即借解决利用率，ReclaimNominalQuota 解决主人保底——两个方向合起来借用才是可持续的
- **防长期占 borrowed**：借用份额滞留时长是公平性审计指标（02 §7）——长期把主人挤成二等公民 = 公平破坏；预算侧同款口径：长期低执行率的配额回收再分配，「配额是公共资源不是领地」（[横切 03 §5](../90-横切/03-多租户与计量计费.md)）

### 4.3 防饥饿

- **风险**：P0 常态高峰时，P2 可能永远排不到——**优先级是排队顺序，不是饿死许可**
- **兜底（通识）**：年龄加权（排队越久等效优先级越高）+ 最小份额（低优队列保底吞吐）——防饥饿是调度器的义务，不是给低优的福利
- **与抢占闭环**：被抢作业重回 Queued 时**年龄不从零起算**（Evicted → Queued 带原年龄）——否则「抢了排、排了抢」的循环就是程序性饿死；护栏 1 保住「抢了能回来」，年龄保留保住「回来不用从头等」

## 5. 指标与质量门（L2/L3 落点）

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 高优作业排队时延 P95 | P0 从提交到 Admitted | 质量基准不堵车（❓ 阈值待标定） |
| 抢占成功率 | 触发抢占后高优成功准入比例 | 护栏过滤是否过紧（该抢的抢不成） |
| 被抢作业恢复率 | Evicted → 检查点续跑成功比例 | 验证护栏第 1 条：恢复不了的本来就不该被抢 |
| 低优最长等待时长 | P2 从提交到首次 Running 的最大值 | 饥饿监控——防兜底失效（§4.3） |
| 抢占审计覆盖率 | 留审计记录的抢占事件比例 | **应 100%**（护栏第 3 条） |

> 分工：准入等待/配额利用率等闸门面指标归 [02 §7](02-调度与多租户.md)；本篇只看「**秩序好不好**」——高优不堵、低优不死、每次抢占说得清。

## 7. 红线与速讲话术

**红线**：

1. **只抢可从检查点恢复的批处理**：恢复不了的作业被抢 = 双倍浪费——护栏前置到被抢对象选择，不是事后补救
2. **Golden Set/发布类作业不得被抢**：回归基准与发布在途神圣——被抢客体过滤名单是硬配置，不是建议
3. **抢占必须可观测可审计**：每次抢占谁抢谁、策略、恢复耗时留痕（横切 02）——无审计的抢占不许发生
4. **低优不得饿死**：年龄加权 + 最小份额兜底，被抢后年龄不从零起算——防饥饿是调度器义务，不是福利
5. **优先级不能绕过配额**：高优也在配额内插队——优先级改变排队序，不改变资源上限；P0 超出配额照样排队或走借用（02 红线 1/2 仍然成立）
6. **单维度公平是陷阱**：只对齐一个资源维度会被组合型大户钻空子——必须多资源 DRF（§4.1）

**速讲话术（30 秒）**：

> "优先级这块我分三层讲：来源是 K8s PriorityClass 映射到 Kueue 的 Workload priority，再叠加队列级优先级——排队序是合成的。分级上 Golden Set 回归和线上 badcase 修复是 P0，因为下游有整条流程在等它；P2 之所以愿意被抢，是平时能借到超额空闲资源，被抢是这笔账的代价。抢占三种策略：队列内高优抢低优、组内借出方可被抢、配额主人 ReclaimNominalQuota 回收保底。护栏三条：只抢可检查点恢复的批处理、Golden 和发布类不得被抢、每次抢占留审计。被抢的走 Evicted 回 Queued，从检查点续跑，排队年龄不从零算——不然抢了排排了抢就是程序性饿死。公平性用多资源 DRF：单维度会被 GPU 大户 CPU 也大户的租户钻空子，主导资源份额对齐才没有免费维度。这套就是 XLB 的 QoS 搬运：优先级队列、高优挤占低优带宽、低优降级重试、防饥饿的公平性承诺——被管对象从带宽换成 GPU，秩序逻辑一字不改。"
