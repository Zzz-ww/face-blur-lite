## 1. 定位与边界

- **本篇管**：**型号分池**（什么卡）、**放置策略**（放哪：装满还是打散）、**拓扑约束**（多卡怎么贴）、**弹性伸缩**（什么时候有）、**成本感知**（花多少钱）
- **不管**：配额与准入（02）、租户总量隔离与三池口径（07）、被抢占/被缩容后的恢复流程（03/06/09）、成本口径定义（算子-06）、账单出账（横切 03）
- **一句话**：配额管「多少卡」，本篇管「**什么卡、放哪、什么时候有、花多少钱**」——配额是账面，资源池是物理

## 2. 核心概念与组件

| 组件 | 归属层 | 职责 |
| --- | --- | --- |
| ResourceFlavor | Kueue | 型号分池落点：型号→节点标签→配额按 flavor 声明（[02 §4.1](02-调度与多租户.md)） |
| worker 组 | KubeRay（[01 §4.1](01-KubeRay控制面.md)） | RayCluster 内按型号分组（`gpu-a100`/`gpu-l40`），大模型独占卡 |
| 放置策略 | 调度层 | BinPacking（装满）/ Spread（打散）两种取向（§4） |
| 拓扑约束 | 调度层 | NVLink/同交换机亲和——只加同步训练类（§4） |
| Ray autoscaler | 集群内控制面 | 三层伸缩执行器（§5，[01 §5](01-KubeRay控制面.md)） |
| 成本感知调度器 | 决策层增强 | spot 优先/利用率阈值/型号不降级（§6，⚠️ 进阶） |

> **与负载均衡/控制面同构**：硬件型号池 ≈ 板卡型号资源池（转发资源按单板型号归堆，业务按需取用）；放置策略 ≈ 流量收敛（BinPacking=链路收敛省板卡）与负载打散（Spread=防单板故障一锅端）；拓扑 ≈ 端口/板级亲和（同交换机的卡=同一转发单元内的资源）；弹性 ≈ 容量伸缩的触发与收敛——**物理资源怎么用是同一道运筹题**，被管对象从带宽板卡换成 GPU。

## 3. GPU 型号分池（重点节）

```
GPU 型号（如 A100-80G / L40）
  → 节点标签（nodeLabels / instance-type）
  → ResourceFlavor（gpu-a100 / gpu-l40，[02 §6](02-调度与多租户.md) 示例）
  → ClusterQueue resourceGroups 按 flavor 声明配额
     └─ 作业经 Workload 申请 flavor → 型号不匹配在准入层即拦
```

- **链路口径**：配额跟着型号走——A100 的配额不会放行 L40 的活；型号约束在 L1 准入层生效（02 §4.1「GPU 型号分池的落点」），而不是等 Pod 落到节点才发现跑不动
- **与 07 的两层关系**（[07 §4](07-多租户与分池隔离.md) 前瞻兑现）：池（namespace/ClusterQueue 级）管**总量隔离**（数据平台/训练/评测互不挤兑）；型号（flavor 级）管**错配**——两层正交：池回答「哪个业务域的账」，型号回答「哪种卡能跑这个活」；[07 红线 6](07-多租户与分池隔离.md)「型号约束归 08 的 ResourceFlavor/拓扑层」即落在此节与 §4
- **混跑 OOM 红线展开**（[01 红线 2](01-KubeRay控制面.md) + [调研笔记-02 §6.5](../92-调研笔记/调研笔记-02-Ray分布式框架调研与管线应用.md)）：错配有两种形态，拦截点不同——

| 错配形态 | 例子 | 拦截层 |
| --- | --- | --- |
| 型号错 | A100 的活落 L40（跑不动/显存不够） | ResourceFlavor 准入（本节） |
| 共享错 | MoGe/SAM2 挤同卡（显存叠加 OOM） | `num_gpus=1` 独占 + worker 组按型号分（[01 §4.1](01-KubeRay控制面.md)） |

- **型号匹配优先于拓扑**（[02 §4.4](02-调度与多租户.md) 调度优先级序展开）：GPU 型号池匹配 > 配额/优先级 > 网络/拓扑——型号不匹配，拓扑再好也白搭；数据局部性不在序里（数据主存在对象存储、worker 经网络拉取，与 ML 训练集群「本地盘亲和」是不同场景，不照搬其局部性调度）

## 4. 放置策略与拓扑感知（重点节）

- **两种取向**（调度器通识，执行层 = 批调度层 Volcano 的 backfill/FIFO+priority 等放置算法与 kube-scheduler 节点绑定，[02 §3](02-调度与多租户.md)）：

| 取向 | 做法 | 利 | 弊 | 本平台默认 |
| --- | --- | --- | --- | --- |
| BinPacking | 装满节点再开新节点 | 利缩容（空出整节点）、省成本 | 风险集中（同节点密度高） | 批处理默认 |
| Spread | 打散到不同节点 | 利容错（同节点故障不一锅端） | 碎片化闲置 | 常驻关键池 |

- **碎片取舍**：BinPacking 过度 = 单点风险集中；Spread 过度 = 碎片化——谁都差一张卡、gang 的 `minMember` 永远凑不齐（[02 §5.1](02-调度与多租户.md)），资源占着却谁也跑不起来；口径：**批处理默认 BinPacking、常驻池 Spread、训练类 gang 作业凑齐优先**（凑不齐 = 资源白占）
- **拓扑感知（⚠️ 收益待标定，进阶）**：多卡同步训练（Ray Train）需要 NVLink/同交换机亲和——跨节点梯度同步是通信性能墙（业内通识）；推理/批处理对拓扑不敏感——**拓扑约束只加在同步训练类作业**，与 02 §5.1「管线松、训练严」的分级依据同源；给批处理加拓扑 = 白等资源（红线 3）。实现层：节点拓扑标签 + 亲和调度（以团队标定为准）

## 5. Ray autoscaler 弹性

- **三层伸缩**（SSOT = [01 §5](01-KubeRay控制面.md) 表，此处只列链路不重抄）：Ray autoscaler 看**挂起的逻辑资源请求**（不看 CPU 利用率）→ KubeRay 转物理 Pod（min/max 范围内）→ Pod Pending 无节点时 K8s Cluster Autoscaler 扩主机——「逻辑需求 → 物理 Pod → 物理主机」逐级放大，每层有自己的配额与冷却（配额如何卡第②③层见 [02](02-调度与多租户.md)）
- **不用 HPA**（[01 红线 1](01-KubeRay控制面.md)）：HPA 看 CPU/自定义指标扩 Deployment 副本，不理解 Ray「集群内按逻辑资源动态增减节点」的模型——绕过 autoscaler = 逻辑资源视图与物理节点错位
- **三形态**（[01 §6](01-KubeRay控制面.md) 成本权衡表回顾）：常驻（L2 高频感知重建：无冷启动、权重常驻 vs 空闲空转）/ 按需（L3/L4 低频批：无空闲成本 vs 冷启动慢）/ 折中（常驻最小池 + 弹性上限：基线低延迟、波峰再扩）——本平台 L2 常驻、L3/L4 按需的落位即 [01 红线 5](01-KubeRay控制面.md)「常驻/按需分离」的执行
- **弹性触发信号**：三层各有信号（挂起资源请求 → Pending Pod → 节点池水位）；平台侧再看队列深度与准入等待（[02 §7](02-调度与多租户.md) 排队深度）作容量规划输入——阈值 ❓ 待标定。**弹性与准入的关系**：Kueue 在前（该不该进）、autoscaler 在后（进了不够再扩）——扩容不能替配额做决定，否则配额体系被架空（[02 红线 1](02-调度与多租户.md) 的另一面）
- **缩容优雅 drain**（[01 红线 4](01-KubeRay控制面.md) 展开）：`autoscalerOptions.idleTimeoutSeconds` 控制空闲回收（通识默认约 60s，长任务池须调大）；drain 必须等在途分片收尾、Actor 写完检查点——强杀长时重建 Actor = 丢任务触发无谓重跑；被缩容驱逐的作业走 Evicted → Queued → 检查点续跑（[03 §4](03-任务状态机与容错.md)，恢复流程归 [09](09-检查点与断点续跑.md)）

## 6. 成本感知调度

- **口径**：GPU 秒/样本（含加载摊销）= [算子-06 §1](../02-生产域/算子设计/算子设计-06-算子成本模型.md)——成本感知调度的优化目标就是**单样本 GPU 秒**
- **省钱策略组合**（[算子-06 §3](../02-生产域/算子设计/算子设计-06-算子成本模型.md) 的管控面落点）：

| 策略 | 管控面动作 |
| --- | --- |
| 规则前置 | 无效样本在进 GPU 环节前被拦（CPU 便宜，GPU 贵——入口即省） |
| 型号匹配不降级 | 型号错配宁可排队等匹配卡，降级跑 = 跑不动或返工，更贵 |
| BinPacking 利缩容 | 装满才空得出整节点，空得出才回收得了（§4） |
| 常驻池摊销加载 | 模型权重常驻复用，加载成本摊进多分片（[01 §6](01-KubeRay控制面.md)） |
| 按需池无空闲 | 跑完即销（`shutdownAfterJobFinishes`），零空转窗口 |
| 缩容及时 | `idleTimeoutSeconds` 调优，空闲窗口越小越省（§5） |
| spot 优先 | 折扣用可恢复性换——必须可检查点恢复，走 [06 §3.2](06-优先级抢占与公平性.md) 被抢占恢复通道 |

- **花销入计量**：弹性池（常驻/按需/spot）的每作业 GPU 秒入 [横切 03 §4](../90-横切/03-多租户与计量计费.md) 算力计量（算子成本→数据集成本→项目成本）——**弹性不是免费的**，扩出来的卡都要入账（红线 6）

## 7. 指标与质量门（L2/L3 落点）

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 池利用率（按型号分列） | 各 flavor nominal 使用占比 | 容量规划：哪个型号该扩/收（联动 [横切 03 §5](../90-横切/03-多租户与计量计费.md) 预算复盘） |

| 碎片率 / 单节点卡均数 | 空闲卡分布 | BinPacking/Spread 取舍的验证（§4） |
| 弹性伸缩时延 / 扩容成功率 | 扩容请求到节点可用 | 高峰补卡能力（[01 §7](01-KubeRay控制面.md) 同款） |
| 单样本 GPU 秒 | [算子-06 §1](../02-生产域/算子设计/算子设计-06-算子成本模型.md) | 成本感知调度的优化目标（联动数据面指标） |

## 9. 红线与速讲话术

**红线**：

1. **禁止 HPA 直伸缩 Ray worker**（[01 红线 1](01-KubeRay控制面.md) 重申）：HPA 不理解 Ray 逻辑资源视图——绕过 autoscaler = 视图与节点错位
2. **型号混跑即 OOM**：大模型独占卡（`num_gpus=1`）、worker 组按型号分（[01 红线 2](01-KubeRay控制面.md)；调研笔记-02 §6.5）——型号错配拦在 flavor 准入，共享错配拦在独占
3. **拓扑约束只加同步训练**：推理/批处理对拓扑不敏感——给批处理加拓扑 = 白等资源
4. **缩容必须优雅 drain**：强杀长时重建 Actor = 丢任务无谓重跑（[01 红线 4](01-KubeRay控制面.md)）；长任务池调大空闲回收时长
5. **常驻/按需分离**（[01 红线 5](01-KubeRay控制面.md)）：低频不常驻（GPU 空转）、高频不按需（反复冷启动）
6. **弹性花销必须可计量**：扩出来的卡都入账（[横切 03 §4](../90-横切/03-多租户与计量计费.md)）——无计量的弹性 = 成本黑洞

**速讲话术（30 秒）**：

> "GPU 资源池我按物理视图讲：型号分池走 Kueue 的 ResourceFlavor——型号打节点标签、配额按 flavor 声明，A100 的配额不放行 L40 的活，型号错配在准入层就拦住；租户分池和型号分池两层正交，池管总量隔离、型号管错配。混跑 OOM 是两条线拦：型号错在 flavor，共享错在 num_gpus 独占、worker 组按型号分。放置两种取向：批处理默认 BinPacking 装满利缩容，常驻关键池 Spread 打散防单节点一锅端；拓扑约束只加同步训练——跨节点梯度同步是通信墙，批处理加拓扑是白等资源。弹性是三层伸缩：Ray autoscaler 看挂起的逻辑资源请求、KubeRay 转物理 Pod、Cluster Autoscaler 扩主机，不能用 HPA，它不理解 Ray 的逻辑资源视图；扩容不替配额做决定，Kueue 管该不该进、autoscaler 管进了不够再扩。缩容必须优雅 drain，强杀长时重建 Actor 就是丢任务重跑。成本感知的优化目标就是算子成本模型里的 GPU 秒/样本：型号匹配不降级、BinPacking 利缩容、spot 用可恢复性换折扣，扩出来的卡全入计量。这就是 XLB 板卡资源池的搬运：型号池、流量收敛、端口亲和、容量伸缩——物理资源的运筹逻辑一字不改。"
