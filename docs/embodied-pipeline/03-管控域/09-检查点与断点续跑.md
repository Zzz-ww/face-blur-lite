## 1. 定位与边界

- **本篇管**：**检查点体系**（粒度三档、存储分层、频率策略、与血缘的关系）、**恢复流程**（四种入口合流到同一条恢复链）、**at-least-once 语义**（为什么不 exactly-once、幂等怎么兜底）
- **不管**：状态迁移与故障分域（03 §4/§5）、算子内部检查点字段（算子-03 §8）、reconcile 判重机制本身（04 §6）、被抢占的选客体与护栏（06 §3）
- **一句话**：检查点是「**不怕断的底气**」，续跑是「断了还能算」的机制，幂等是「重放无害」的保证——三件一套，缺一不可

## 2. 核心概念与组件

| 组件 | 侧 | 职责 |
| --- | --- | --- |
| 检查点 | 数据侧快照 | 分片清单 + 游标 + 中间产物指针（[03 §7](03-任务状态机与容错.md)）——断点坐标 |
| 恢复控制器 | 控制面决策者 | 接恢复入口、定位最近一致检查点、按优先级排恢复 |
| 血缘 `output_hash` | 校验依据 | [算子-04 §1](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md) 三锁——「最近一致」的裁判 |
| 重放 | 恢复执行 | 从检查点重放缺失分片；重复产出靠幂等去重 |
| at-least-once | 语义承诺 | 不丢、可重复——重复无害的前提是幂等 |

> **与负载均衡/控制面同构**：检查点 ≈ 配置下发失败的重放锚点（已下发的批次不用重来，从断点续传）；续跑 ≈ 收敛循环的断点续传（level-triggered 不靠记忆、靠对账，[04 §6](04-PipelineSpec与编排DSL.md) 同范式）；at-least-once ≈ 配置投递至少一次（不丢配置，重复投递可接受）；幂等 ≈ 重复下发无害（同配置下发两次结果一致）——**控制面「不怕断」的语义在哪个系统都长一样**。

## 3. 检查点体系（重点节）

- **粒度三档（控制面视角）**：

| 档 | 覆盖 | 恢复成本 | 定位 |
| --- | --- | --- | --- |
| 作业级 | 整链只看最终产物 | 最粗：中间节点失效要整节点重跑 | [04 §6](04-PipelineSpec与编排DSL.md) reconcile 的整链判重（全跳过/级联重跑） |
| 节点级 | 阶段节点产物 | reconcile diff 的天然单位（拓扑序跳过有效节点） | [04 §6](04-PipelineSpec与编排DSL.md) ②③ |
| 算子级 | 算子内部分片进度 | 最细：恢复最快、快照开销最大 | 算子内部再分样本级→批次级→阶段级（[算子-03 §8](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md) 字段粒度，**SSOT**） |

粒度越细恢复越快、开销越大；**本平台默认算子级**（批次粒度起步——[04 §8](04-PipelineSpec与编排DSL.md) 示例 `checkpoint: {level: batch, store: oss, at_least_once: true}`），全局默认可被节点级 `checkpoint` 字段覆盖（[04 §3](04-PipelineSpec与编排DSL.md)）
- **存储分层**：大文件走对象存储（跨节点可恢复，算子-03 §8 介质口径；[03 §7](03-任务状态机与容错.md) OSS/S3）；本地盘只做热缓存不作恢复依据——检查点仓与资产域对象存储同基础设施
- **频率策略**：按时间（固定间隔 barrier）vs 按进度（分片/游标边界打快照，对齐 [03 §7](03-任务状态机与容错.md) barrier 在分片边界）——按进度的快照天然对齐重放单位，恢复重放的浪费更小（以团队标定为准）
- **检查点与血缘的关系**：检查点是**数据快照**、血缘是**逻辑关系**——恢复是找快照，定位是查血缘；每个检查点带三锁与 `output_hash`（[算子-04 §1](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md)），恢复后 hash 一致才可复现——**不带血缘锚点的检查点无法验证一致性，等于没存**

## 4. 断点续跑流程（重点节）

- **四种入口，一条恢复链**：

| 入口 | 触发 | 语义 |
| --- | --- | --- |
| 失败重试 | 瞬时失败 Running→Retrying（[03 §4](03-任务状态机与容错.md)） | 段内续跑（指数退避后从检查点恢复） |
| 被抢占 | Evicted（[06 §3.2](06-优先级抢占与公平性.md) 抢占 / [07 §3](07-多租户与分池隔离.md) ReclaimNominalQuota 回收） | 保留检查点重回 Queued，带龄再排（[06 §4.3](06-优先级抢占与公平性.md)） |
| spot 回收 | 云节点提前回收（同通道） | 同 Evicted——折扣用可恢复性换（[06 §3.2](06-优先级抢占与公平性.md)） |
| 中断重提交 | 控制面重启 / 人工取消后再提 | reconcile 推论：再次提交同 spec 自动跳过已完成（[04 §6](04-PipelineSpec与编排DSL.md)） |

```
恢复入口（四类同流程）
   → 重回队列/重新提交（同 spec 版本——三锁不变才叫续跑）
   → reconcile 读血缘：已完成且 output_hash 一致 → 跳过
   → 定位「最近一致」检查点（不是最近的——重放分片 hash 与血缘比对，不一致即弃用）
   → 重放缺失分片 → hash 校验一致 → 续跑 Running
   → 重复产出由幂等去重消化（at-least-once，§5）
```

- **恢复到哪个 checkpoint**：沿血缘逆向找「**最近一致**」——一致性由 `output_hash` 裁决，不由时间戳裁决（时间戳新的可能是脏的；脏检查点宁可弃用重放，[03 红线 5](03-任务状态机与容错.md)）
- **验证什么（三道）**：① 检查点自身可读且完整；② 重放分片 hash 与血缘记录一致；③ 三锁匹配（spec/算子/模型版本同锁）——锁变了就不是续跑，是新 run（版本变更走 [04 §7](04-PipelineSpec与编排DSL.md) 版本绑定）
- **恢复优先级**：恢复作业带原优先级与排队年龄回队列——P0（Golden 回归/badcase 修复）被抢后优先回来（[06](06-优先级抢占与公平性.md) 分级联动）；恢复不是特殊通道，还是走 02 准入
- **优雅取消的「优雅」就是检查点**：级联取消先写检查点再退（[03 §8](03-任务状态机与容错.md)）；跨作业链上，上游失败下游从失败处重启而非整链重跑（[05 §6](05-跨作业编排与触发链.md)）

## 5. at-least-once 语义（重点节）

- **为什么不是 exactly-once**：数据管线重放成本远小于漏数据成本——exactly-once 要两阶段提交/全局屏障，GPU 管线为此付出的吞吐与时延代价不值（[算子-03 §8](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md) 口径）；漏数据的兜底不在语义层而在通道层：数据性失败进 DLQ 人工仲裁（[03 §6](03-任务状态机与容错.md)）、血缘断链检测兜漏登记（治理 02）
- **幂等兜底三件套**（[算子-04 §1](../02-生产域/算子设计/算子设计-04-算子血缘与版本三锁.md)）：**版本三锁**（同锁同输入才叫重放——锁不同是新 run 不是重放）、**固定 seed**（模型算子可安全重跑，[算子-03 §7](../02-生产域/算子设计/算子设计-03-算子执行与编排规范.md) 幂等口径：规则算子天然幂等）、**输出 hash 校验**（重复产出可识别、可去重）——三件缺一，at-least-once 就从「不丢」退化成「越重越乱」
- **重放 = 审计友好**：同 spec + 同输入版本重放 = 同结果（[04 红线 4](04-PipelineSpec与编排DSL.md) 重放一致性硬承诺；[05 §6](05-跨作业编排与触发链.md) run 级幂等同口径）——这是回归验证（Golden 重跑）与事故复盘（历史 run 复现）能成立的根基

## 6. 指标与质量门（L2/L3 落点）

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| 检查点成功率 | barrier 快照落对象存储成功比例 | 检查点质量——失败必须告警（红线 6） |
| 恢复时长 P95 | 断点到续跑回 Running | MTTR 的组成部分（[03 §9](03-任务状态机与容错.md) 分域统计的深化） |
| 检查点存储开销 | GB/样本（❓ 待标定） | 容量预算输入（红线 4） |
| 续跑占比 | 成功作业中经历过续跑的比例 | 弹性/抢占/故障的综合性信号——高占比要看是环境抖动还是抢占过频 |
| 因检查点丢失的重跑比例 | 无可用一致检查点被迫从头跑的比例 | **应趋 0**（趋 0 = 「不怕断」的底气兑现） |

> 分工：状态机健康指标（成功率/MTTR/DLQ 率）归 [03 §9](03-任务状态机与容错.md)；本篇只看「**断了回来得快不快、真不真**」——恢复快（粒度/预热）、恢复真（hash 一致性）。

## 8. 红线与速讲话术

**红线**：

1. **检查点粒度不细于算子级**：只有作业级检查点的恢复 = 白跑中间算子——粒度是恢复成本的第一决定项（默认算子级批次，§3）
2. **无检查点的作业不许被抢占**（[06 护栏 1](06-优先级抢占与公平性.md) 重申）：不可恢复就不可被抢、不可上 spot——可恢复性是被抢资格的前提
3. **重放必须幂等**：不幂等的重放 = 越修越坏——三锁 + 固定 seed + hash 校验三件套缺一不可（§5）
4. **检查点存储不可无限膨胀**：容量预算 + 过期清理（GB/样本 ❓ 待标定）——无限存 = 把 GPU 的成本问题挪到存储
5. **恢复不等于重跑**：续跑 ≠ 从头来——禁止整链重放；脏检查点弃用后也是重放缺失分片，不是全量重来（[03 红线 5](03-任务状态机与容错.md) 同源）
6. **检查点失败要有告警**：静默丢检查点 = 假安全感——成功率指标 + 告警接 [横切 01](../90-横切/01-可观测性.md)

**速讲话术（30 秒）**：

> "断点续跑我拆成三件事：检查点、恢复、幂等。检查点粒度控制面看三档——作业级、节点级、算子级，算子级内部再分样本/批次/阶段，我们默认算子级的批次粒度，快照落对象存储，每个检查点带三锁和 output_hash。恢复四个入口一条链：瞬时失败重试、被抢占 Evicted、spot 回收、中断后重提交——全部走重新提交同 spec，reconcile 读血缘自动跳过已完成节点，所以断点续跑不是一个专门模式，是声明式 reconcile 的自然推论。定位恢复点找的是最近一致检查点，不是最近的：重放分片 hash 和血缘对不上就弃用，宁可多放一段，不带病续跑。语义上是 at-least-once 不做 exactly-once——数据管线重放远比漏数据便宜，重复产出靠幂等去重：版本三锁、固定 seed、输出 hash 三件套。恢复作业带原优先级和排队年龄回队列，Golden 回归被抢了优先回来。这就是 XLB 配置下发那套的搬运：检查点是下发失败的重放锚点，续跑是收敛循环的断点续传，at-least-once 是配置投递至少一次，幂等是重复下发无害——控制面不怕断的语义，换个被管对象一模一样。"
