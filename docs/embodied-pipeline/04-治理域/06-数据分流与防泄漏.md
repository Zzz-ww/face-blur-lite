## 1. 定位与边界

- **本篇管**：泄漏的**类型学**（什么算泄漏）、治理侧**审计**（怎么发现）、split **访问隔离**（谁能看哪个集）、**事件响应**（发现后怎么办）

## 3. 泄漏类型系统（什么算泄漏）

| # | 类型 | 机制 | 检测手段（引用算子-07 §4） |
| --- | --- | --- | --- |
| 1 | **跨集重复** | 同/近重复样本跨集（train 里有 test 的孪生兄弟） | 内容 hash + 语义近重复检测（`op-clean-dedup`/`op-clean-sdedup`）——**去重必须在切分前**（算子-07 红线） |
| 2 | **时间泄漏** | 同采集会话/连续帧跨集（动作前后帧分进两集） | 会话/场景 ID 分组切分核验（`op-stat-sample` 参数） |
| 3 | **本体/场景泄漏** | 同一本体/同一场景跨集（模型背下了这个厨房） | 分组标签对账（从严口径：同本体同场景只落一个集合） |
| 4 | **标注泄漏** | 标注环节泄漏答案（标注员接触过 test 内容） | 标注任务分配审计（[标注体系-01](../02-生产域/标注体系/01-自动标注与人工标注台.md) 人工任务范围） |
| 5 | **指令/语义泄漏** | 相似指令/模板跨集（换个说法的同一条指令） | embedding 相似度审计（跨集抽样比对） |

- **共同本质**：五类都是「**评测集信息以任何形式进入了训练侧**」——形式不同（像素级/时序级/实体级/人员级/语义级），本质相同（结论虚高）
- **从严口径说明**（算子-07 核实状态）：按会话/场景分组、同本体同场景只落一个集合是**治理选择**——业内也有按样本级切分再抽检的宽口径；从严多花数据成本，换泄漏风险下限

## 4. 治理侧审计（三道巡逻）

| 审计 | 时机 | 内容 | 依据 |
| --- | --- | --- | --- |
| **发布前审计** | G5 封装门 / G6 回归门 | 封装前泄漏检查 + Golden 与新增训练数据泄漏抽检 | 算子-02 §9（泄漏=0 硬门）；[03 §5](03-质量门禁G0-G6.md) 硬门无豁免 |
| **定期审计** | 常设周期（频率待标定） | 训练 vs test/golden 抽样算 embedding 相似度，超阈值告警 | 算子-07 §4 |
| **血缘交叉核验** | 版本聚合时 / 事件响应时 | `op-clean-dedup` 执行记录 + 切分日志 vs split 标签对账 | 算子-07 §4；[02 §5](02-血缘制品与版本三锁.md) 血缘完整性 |

- **审计不可关停**：定期审计是常设机制，不是「出过事才开」——泄漏的最大风险恰恰是**不知道有泄漏**（结论虚高无人怀疑）
- **阈值标定**：相似度阈值在本数据上标定后纳入 [03 §6 阈值治理](03-质量门禁G0-G6.md)（版本化、改走评审）——阈值也是判例，不许线上手调

## 5. split 访问隔离

- **按 split 授权（RBAC）**：谁能看哪个集合是权限问题——train 常规授权，val 按需，**test/hold-out 白名单制、默认拒绝**（Golden/Hold-out 的管理链 [05 §7](05-回归与发布.md)，隔离红线 [04 §4](04-四层评测体系L1-L4.md)）
- **导出侧执行**：TrainingRelease 只含被授权 split（资产域执行导出，治理域定策略——[总线 §4.2](../00-总体架构/README.md) 资产→消费契约「split 隔离 + 防泄漏检查」）
- **消费侧延伸**：训练/评测侧防泄漏责任延伸到消费域——拿到 test 访问权的人不得参与训练侧调参（契约条款，操作审计在 [07 §8](07-合规引擎.md) 留痕）
- **人员通道**：标注员/审计员按任务最小授权（标注任务分配审计防标注泄漏，§3 #4）

## 6. 泄漏事件响应（出了事怎么办）

```
发现泄漏（定期审计告警 / G5-G6 拦截 / 人工举报）
   │
   ▼ ① 止损：停止发布 / 撤回版本（01 §6：标 Deprecated + 切指针回稳定版）
   │
   ▼ ② 影响面：血缘反向查询 blast radius（02 §4 find_impact）
   │      —— 哪些版本、哪些训练、哪些下游结论被污染
   ▼ ③ 根因：定位失效防线（去重没跑？切分分组漏了？访问控制破了？）
   │
   ▼ ④ 恢复：重切分 → 重训（受影响训练）→ 重新回归（05 §3）
   │
   ▼ ⑤ 复盘：防线补强 + 审计规则更新 + change record 留痕（泄漏类型注册表迭代）
```

- **顺序不可乱**：先止损再查因（边查边泄漏着）；影响面在重训**之前**圈定（否则不知道该重训谁）
- **被污染的结论要标记**：用了泄漏数据训出的模型，其评测结论（L4 报告）标注「数据污染，仅供复盘」——假收益比没收益更危险

## 7. 四集用途纪律（引用 + 治理立场）

四集定义与更新频率 = 算子-07 §1（训练持续增长 / 验证随训练受控更新 / 测试固定 / Golden 固定受控扩充）。治理立场：

- **用途严禁混淆**：训练迭代 / 验证调参 / 测试一次性结论 / Golden 回归防倒退——**一个集合一个用途**，借用（拿 test 调参）= 制造泄漏
- **测试集「一次性」的含义**：反复在 test 上看结果再做决策 = 事实上的调参集——测试集结论按「一次性」纪律使用，看多了就作废换新（重配走 05 §7 受控流程）

## 10. 红线与速讲话术

**红线**：

1. **去重在切分前**（算子-07 红线引用）：切分后去重 = 阈值再准也拦不住跨集孪生
2. **test/hold-out 白名单制、默认拒绝**：能随便看的测试集不是测试集，是第二训练集
3. **泄漏事件必须走响应流程**：禁止悄悄删样本了事——不圈影响面、不重训、不留复盘的处置等于把污染埋进土里
4. **定期审计不可关停**：告警可以调阈值（走 03 §6 阈值治理），审计本身不能停
5. **四集用途严禁混淆**：借用集合 = 制造泄漏；测试集按一次性纪律用
6. **被污染结论必须标记**：泄漏数据训出的评测结论标「仅供复盘」——假收益流进决策链比没有收益危害大

**速讲话术（30 秒）**：

> "防泄漏我把算子层的防线和治理层的安防分开。防线是算子-07 的三道：跨集去重、按会话场景分组切分、同本体同场景只落一个集合，去重必须发生在切分前。治理层做类型学——泄漏分五类：跨集重复、时间泄漏、本体场景泄漏、标注泄漏、指令语义泄漏，本质都是评测集信息进了训练侧。发现手段三道巡逻：发布前 G5/G6 硬门、定期 embedding 相似度审计、血缘交叉核验切分日志。访问上 split 做 RBAC，test 和 hold-out 白名单制默认拒绝。出了事走五步：止损撤版本、血缘圈 blast radius、定位失效防线、重切分重训重回归、复盘补强。最容易被问的权衡是从严口径——同场景只落一个集合会多花数据成本，但把泄漏风险压到下限，我认为评测可信度值这个价。这套和我在 XLB 做环境隔离加安审扫描一个思路：默认拒绝、例外审批、事件有预案。"
