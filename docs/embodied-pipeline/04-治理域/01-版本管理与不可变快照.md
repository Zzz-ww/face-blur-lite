## 1. 定位与边界

- **本篇管**：版本是治理域的**一等公民**——版本号怎么定、版本里装什么、版本怎么从 Raw 走到 Published、发布后如何冻结/回滚/退役
- **不管**：三锁在算子执行时怎么落（算子-04）、门禁阈值怎么判（03 篇）、物理快照怎么存（资产域）
- **一句话**：版本服务是「数据集的户籍与档案系统」，门禁是「升迁审批」，资产域是「仓库」；本篇管户籍档案，审批在 03/05，仓储在资产域

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 版本服务（Version Service） | 版本号分配、晋升、状态机 owner | 状态迁移由门禁/治理动作触发，不由人随意改（机制同 reconcile，见 [03 管控域状态机](../03-管控域/03-任务状态机与容错.md)） |
| DatasetVersion | 不可变版本制品（档案袋） | 数据文件 + 元数据 + 标注 + 质检 + 血缘图 + 三锁（§4） |
| 逻辑版本号 | 人读、用于沟通与发布 | 语义化版本 / 日期+序号（§3） |
| 内容指纹 | 机器读、完整性校验与去重 | 对文件清单 + 三锁 + 血缘算 hash（§3） |
| 版本注册表（registry） | 版本清单与状态查询 | 记录全部版本、状态、指针（当前默认版本） |
| 草稿 / 已发布 | mutable draft vs immutable release | 类比 Git：branch 是草稿、tag 是发布、commit 是内容 hash |

> **与负载均衡治理同构**：DatasetVersion 发布 ≈ 配置版本化 + 灰度发布；不可变 + 可回滚 + 精确引用，和 LB 配置「变更即新版本、可回滚、转发面锁定版本」是同一套治理逻辑。

## 3. 版本号与内容寻址

- **双标识并行**：
  - **逻辑版本号**（人读）：语义化 `MAJOR.MINOR.PATCH`（或 `日期+序号`）——正式发布、沟通、下游引用用它
  - **内容指纹**（机器读）：对 manifest（文件清单 + 每文件 hash）+ 三锁 + 血缘图计算的 content hash——完整性校验、去重、复现判定用它
- **为什么不能只用一个**：
  - 只用自增号：无法判断两个版本内容是否相同，无法跨版本内容去重
  - 只用 hash：人无法沟通，也无法表达「这是经过审批的正式发布」
- **不可变的实现（内容寻址 + 只追加）**：
  - 对象存储 key 取内容 hash（CAS），**同内容同 key、天然不可变**；未变更文件跨版本共享物理块（存储去重）
  - Published 版本只追加、不可改/删（WORM：Write Once Read Many）
  - 任何内容修改 = 新 hash + 新版本号，**绝不覆盖**
- **引用精确到版本**：正式发布与下游训练引用必须带确定版本号；`latest`/`main` 这类可变指针只允许用于开发测试，禁止用于发布与复现性实验

## 4. DatasetVersion 制品构成

一个 DatasetVersion 是**自包含的档案袋**——仅凭它即可复现、可审计、可追责（字段为设计通识，以实现为准）：

```yaml
DatasetVersion:
  version_id: v3.1.0                 # 逻辑版本号（人读）
  content_hash: sha256:c3d4...       # 内容指纹（机器读，完整性/去重）
  state: Published                   # 生命周期状态（§5）
  three_locks:                       # 版本三锁（算子-04 §1）
    data_version: ...
    operator_version: ...
    model_version: ...
  manifest:                          # 文件清单：每个文件 path + hash + 大小
    - {path: ..., sha256: ..., size_bytes: ...}
  lineage_graph_ref: ...             # 血缘图（02 篇）
  gate_result_ref: ...               # G0–G6 门禁结果（03 篇）
  eval_report_ref: ...               # L1–L4 评测报告（04 篇）
  annotation_set_ref: ...            # 标注集（含 label_source）
  qc_report_ref: ...
  schema_version: LeRobotDataset/v3
  split_summary: {train: ..., val: ..., test: ..., golden: ...}
  parent_version: v3.0.0             # 上一版本（diff/回滚用）
  release_notes: ...                 # 变更说明（数据增删/算子升级/指标变化）
  created_at / published_at / published_by: ...
```

## 5. 版本生命周期状态机

```
  Raw ──接收──► Processing ──G0–G4 全过──► Validated ──G5/G6 + 审批──► Published（不可变）
  （接入域）     │  （生产中）                    （待发布）              │
                │                                                  ├─ 新版本发布/废弃决策
                └──门禁失败 / DLQ──► Quarantined ──修复回流──► Processing   │
                                    （隔离）                              ▼
                                                                  Deprecated（不推荐但留痕）
                                                                         │ TTL/冷热分层
                                                                         ▼
                                                                     Archived（冷归档）
```

| 状态 | 含义 | 进入/退出触发 |
| --- | --- | --- |
| Raw | 原始数据包（接入域已做源头校验） | 接入域产出 |
| Processing | 生产中、可重跑 | 接收进入 |
| Quarantined | 隔离（门禁失败/执行层 DLQ）；与 [03 管控域 DLQ](../03-管控域/03-任务状态机与容错.md) 共用通道 | 门禁失败进入；修复后回 Processing 或显式废弃 |
| Validated | 通过 G0–G4，待发布 | 阶段门全过；G5 封装/泄漏检查在发布前完成 |
| Published | 通过 G6 全门禁 + 发布审批，**不可变** | 05 篇发布流；之后只能发新版本 |
| Deprecated | 有更新版本或被废弃，不再推荐但保留 | 新版本发布 / 废弃决策 |
| Archived | 冷归档降本（数据迁冷存储，元数据/血缘不删） | 资产域 TTL/冷热分层 |

- **两个状态机的分工**：[03 管控域](../03-管控域/03-任务状态机与容错.md) 的状态机管「作业运行态」（Pending→Succeeded）；本篇管「数据集版本态」（Raw→Published）。作业成功不代表版本可发布——还得过门禁
- **Published 不可回到可编辑态**：要改只能发新版本；`Published → Deprecated/回滚` 是治理动作，不是编辑

## 6. 版本演进：diff、回滚与归档

- **版本 diff**：比较两个版本的 manifest（文件增删改）+ 三锁变化 + 指标变化，生成 release notes；影响面（哪些下游作业/训练引用了受影响样本）由血缘反向查询给出（02 篇 blast radius）
- **回滚（切指针，不删历史）**：发布后发现倒退/缺陷 → 当前版本标 Deprecated，把「默认版本指针」切回上一个稳定版本；问题修复后走新版本重过 G6。**回滚是指针切换，不是删除**——已发布版本物理保留
- **废弃与归档**：Deprecated 保留可追溯（历史实验复现、事故复盘都要用）；Archived 只把数据文件迁冷存储，**血缘与元数据不删**，仍可索引
- **去重**：内容寻址天然按物理块去重，跨版本只存差异文件

## 7. 指标与质量门

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| manifest 完整性校验通过率 | 文件 hash 与 manifest 一致 | 100% |
| 版本可复现率 | 凭三锁重跑结果一致的比例 | 应趋近 100%（确定性栈下） |
| 晋升成功率 / 平均晋升时长 | 提交发布到 Published 的转化与耗时 | 时长 SLA 待标定 |
| 回滚次数 / 回滚时长 | 发布后撤回频率与切回耗时 | 回滚次数是发布质量的反向指标 |
| Quarantined 占比 | 隔离样本/批次比例 | 趋势下降，定位生产质量 |

- **门禁衔接**：只有 `state=Validated` 且三锁齐全才允许进入 G6；对 Published 版本的任何写操作直接拒绝（不可变在服务层强制）
- L1/L2 质量与 L4 收益指标的评测组织见 [04 四层评测](04-四层评测体系L1-L4.md)；回归与发布见 [05 回归与发布](05-回归与发布.md)

## 8. 跨域衔接

- **上游**：生产域 `StructuredDataset + AnnotationSet + QCReport` 过 G0–G4（[总线 §4.2](../00-总体架构/README.md)）→ 形成 Validated 候选
- **下游**：Published `DatasetVersion` 作为晋升令牌 → 资产域做物理快照（存储/TTL），→ 消费域据此生成 `TrainingRelease`（split 隔离）
- **同域**：三锁/血缘执行细节链算子-04 与本篇 [02 血缘](02-血缘制品与版本三锁.md)；门禁链 [03](03-质量门禁G0-G6.md)；发布/回滚链 [05](05-回归与发布.md)；泄漏导致版本撤回链 [06](06-数据分流与防泄漏.md)
- **边界**：版本合法性与晋升令牌在治理域，物理快照/湖仓/冷热分层在资产域，二者不混

## 9. 红线与速讲话术

**红线**：

1. **Published 不可变**：禁止原地覆盖/修改；改数据只能发新版本——否则下游引用的内容会悄悄变化，复现性崩塌
2. **正式发布与下游引用必须精确到版本**：禁止 `latest`/可变分支用于发布与复现性实验
3. **晋升无捷径**：不过 G0–G6 + 发布审批不得 Published；禁止任何「直发/旁路发布」
4. **三锁缺一不可**：少算子/数据/模型任一锁的版本不得发布（无法复现即无审计意义）
5. **已发布版本不物理删除**：只能 Deprecated / Archived；历史版本是审计、复现、回滚的底线
6. **隔离件不得带病晋升**：Quarantined 必须修复重跑或显式废弃，禁止静默回灌

**速讲话术（30 秒）**：

> "数据集版本是治理域的一等公民。我们用双标识：对人用语义化版本号沟通和发布，对机器用内容指纹做完整性校验和去重，对象存储按内容寻址，天然不可变。一个 DatasetVersion 是自包含档案袋——文件清单加每个文件 hash、三锁、血缘图、门禁结果、评测报告，单凭它就能完整复现。版本有生命周期状态机：Raw 到 Processing，门禁失败进 Quarantined 隔离，过了 G0–G4 到 Validated，过 G6 加发布审批才 Published 冻结，之后只能 Deprecated 或归档，回滚是切默认指针不是删历史。最硬的两条红线：发布后绝不原地改，改数据只能出新版本；下游引用必须精确到版本，禁止用 latest。这套和负载均衡里配置版本化、灰度发布、可回滚是同一套治理逻辑——被管对象从转发配置换成数据集版本，不可变加可追溯的原则完全一致。"
