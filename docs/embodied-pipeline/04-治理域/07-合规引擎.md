# 07 · 合规引擎（policy-as-code / 分级分类 / 脱敏前置 / 审计与删除传播）

> 04-治理域第 7 篇。定位：**治理者视角**——合规怎么引擎化：策略即代码、数据分级分类、PII 检测、脱敏前置、留存与删除、跨境控制点、审计与合规报告。边界：脱敏算子实现（`op-pre-desensitize` / `op-des-*`）= [算子设计-02](../02-生产域/算子设计/算子设计-02-算子接口规范与质量门体系.md) §2/§6（SSOT）；G1 脱敏覆盖 / G4 违规率=0 的门禁裁决 = 算子-02 §9 与 [03-质量门禁](03-质量门禁G0-G6.md)；脱敏先于人工标注的标注台侧红线 = [标注体系-01](../02-生产域/标注体系/01-自动标注与人工标注台.md)；版本不可变与归档 = [01-版本管理与不可变快照](01-版本管理与不可变快照.md)。**本篇只写工程机制，不做法律意见**；法规条款仅背景提及并标「需法务确认」。

## 1. 定位与边界

- **本篇管**：合规策略的**引擎化**（策略即代码 + G1/G4 拦截落点）、数据**分级分类**与 PII 检测、**脱敏前置**的链路纪律、**留存与删除**的传播机制、跨境**工程控制点**、**审计**与合规报告
- **不管**：脱敏算法与算子实现（算子-02 §6）、门禁裁决流程（03）、法务解释与法条适用
- **一句话**：合规引擎是**把「应该怎么处理数据」写成机器可执行的规则**——规则版本化、判定留痕、违规在门禁拦截；法务定口径，引擎管执行

## 2. 核心概念与组件

| 组件 | 职责 | 要点 |
| --- | --- | --- |
| 策略引擎（Policy Engine） | 策略评估：数据 × 操作 → 允许/拒绝/要求处理 | 策略即代码（§3） |
| 分级分类标签 | 数据敏感级别的元数据 | 随样本与版本走（§4） |
| PII 检测 | 隐私对象识别（人脸/姓名/位置/声音/设备标识） | `op-des-detect` 承载（算子-02 §6） |
| 审计日志 | 操作/访问/导出三类留痕 | 不可篡改（§8） |
| 删除传播器 | 删除请求沿血缘执行并出凭证 | §6；与 01 不可变语义的张力在 §6 说明 |

> **与负载均衡治理同构**：policy-as-code ≈ 配置下发前的 ACL/安审规则引擎——规则进版本库、改动走评审、判定全留痕，「线上手改策略」和「线上手改 ACL」一样是事故。审计日志 ≈ 操作审计（谁在何时改了哪条配置、从哪个 IP）；删除传播 ≈ 配置回收的级联清理。**规则版本化 + 判定留痕 + 违规拦截**，三件套一个不少。

## 3. 策略即代码（policy-as-code）

- **三可**：**可版本化**（策略进版本库，变更有 diff 有评审）、**可测试**（策略单测：给定样本断言判定——上线前用历史违规样本回归）、**可审计**（每次判定记录策略版本，判例可追）
- **拦截落点**：违规判定挂 G1（脱敏覆盖不达标拦截）/ G4（违规率=0 硬红线，全批拦截）——引擎不自己拦，**通过门禁拦**（治理一致性：所有拦截都在门上，03 §3）
- **策略示例**：

```yaml
policy: face-blur-mandatory              # 设计通识（结构示意，字段以实现为准）
  match: {data_level: [sensitive, personal_info], modality: video}
  require:
    - check: 脱敏覆盖
      op: op-pre-desensitize             # 算子-02 §2：人脸检出≥99%（默认建议值）
      gate: G1
    - check: 违规率
      rule: "=0"                         # G4 硬红线（算子-02 §9）
      gate: G4
  on_violation: {action: block_batch, notify: [合规角色]}   # 全批拦截，无豁免（03 §5）
  version: 2.1.0 / reviewed_by / effective_from
```

## 4. 数据分级分类与 PII 检测

- **四级分类**（设计通识，标签体系以实现为准）：`公开` / `内部` / `敏感` / `个人信息`——分级标签写入样本元数据，**随版本走**（01 §4 元数据组成），版本 diff 时可见分级变化
- **分级决定处理矩阵**：留存期限（§6）/ 访问范围（RBAC）/ 能否出境（§7）/ 脱敏强度与必要性
- **PII 检测类别**：人脸/人像、姓名、位置（GPS/场景地标）、声音、设备标识（序列号/车牌）——检测由 `op-des-detect` 承载（算子-02 §6），检出即打标进元数据
- **检测召回是底线指标**：PII 漏检（假阴）直接变成 G4 违规流出——召回实测**待团队标定**，未标定前用保守阈值

## 5. 脱敏前置（链路纪律）

**顺序红线**：`脱敏（op-pre-desensitize）→ 人工标注台 → 外部 VLM API`——**先脱敏，再给任何「人」或「外部 API」看**：

- **人也是数据出域消费者**：标注员看到未脱敏数据 = 隐私事件（标注体系-01 红线：标注员所见必须已脱敏）
- **外部 VLM API 同理**：调第三方 API 做指令生成/场景描述（`op-sem-*`）= 数据离开平台边界——出域前必须脱敏 + 分级允许（§7 出境控制点同源逻辑）
- **仿真旁路豁免是有据的**：合成数据无隐私，跳过脱敏（[仿真GT旁路 01 §5](../02-生产域/仿真GT旁路/01-仿真数据生产与三套GT.md)，`label_source=sim_GT` 可核验——血缘可查是不是真仿真）
- **双门兜底**：G1 查脱敏覆盖（检出≥99%），G4 查违规率=0（硬红线）——前置纪律 + 门禁拦截，缺一不可（算子-02 §9 门-阶段映射）

## 6. 留存、删除与传播

- **留存期限**：按分级设 TTL（具体数值**待团队标定**）——留存在 [01 §5 生命周期](01-版本管理与不可变快照.md) 上叠加：Archived 冷归档**不等于豁免删除**，到期照样执行
- **删除传播**：删除请求 → [02 血缘 blast radius](02-血缘制品与版本三锁.md)（该数据进了哪些版本/训练）→ 逐级执行删除 → **凭证**（deletion_certificate：谁、何时、删了什么、依据什么请求）
- **与不可变的张力（显式处理）**：[01 红线 5](01-版本管理与不可变快照.md)「已发布版本不物理删除」与合规删除冲突时，**合规删除是例外路径**——走法务确认 + 审批 + change record；执行后**血缘与元数据保留「已删除」凭证**（账本不删，记一笔「应请求删除」）——审计链不断，数据实体已清
- **重训提醒**：被删数据训过的模型是否重训属法务/业务决策——引擎负责把影响面（哪些训练）摆到桌面上

## 7. 跨境/出境（工程控制点）

- **控制点**（本平台能做的）：存储区域标记（本地化部署区域作为元数据）/ 出境清单（哪些数据集、什么分级、去哪个外部 API 或区域）/ 导出审计（§8）/ 外部 API 调用前的策略评估（§5——分级 + 脱敏双过才放行）
- **口径边界**：具体「什么算出境、要不要评估、走什么清单」——**需法务/安全确认**，本篇不编造法条；工程侧承诺的是**控制点存在、可审计**（监管来查时能拿出记录）

## 8. 审计与合规报告

- **三类审计日志**：**操作**（谁改了策略/阈值/版本状态）/ **访问**（谁读了哪个 split/版本——与 [06 §5](06-数据分流与防泄漏.md) split RBAC 联动）/ **导出**（谁把什么导去了哪——含外部 API 调用）
- **不可篡改**：追加写 + 哈希链（或外部存证，实现方式通识）——审计日志本身被改 = 审计失效；**不可关停**（对齐 06 §4 定期审计纪律）
- **与血缘联动**：审计记录挂 [02 血缘图](02-血缘制品与版本三锁.md)——「谁在何时访问/导出了哪个版本」可反向查询（访问也是图上的边）
- **合规报告**：给监管/内审的数据处理记录——采集同意情况、脱敏执行覆盖、访问/导出清单、删除请求与凭证、出境清单（§7）——**报告字段以法务要求为准**，引擎保证数据可取、记录完整

## 9. 指标与质量门

| 指标 | 含义 | 目标 |
| --- | --- | --- |
| 违规率 | 合规/隐私违规样本占比 | **=0（G4 硬红线）** |
| 策略覆盖率 | 数据操作受策略评估约束的比例 | 100%（策略外操作 = 裸奔） |
| PII 检出召回 / 误报 | 检测质量 | 召回待标定（保守优先）；误报可控 |
| 审计完整率 | 三类日志无缺口比例 | 100% |
| 删除请求时效 | 请求到凭证出具 | 待标定（SLA 与法务确认口径联动） |
| 脱敏前置执行率 | 人/外部 API 接触前已脱敏比例 | **100%（链路纪律，违反即事件）** |

## 11. 红线与面试话术

**红线**：

1. **违规率=0 硬红线，无豁免**：合规不讨价还价——质量阈值可豁免（03 §6），违规与泄漏不可以
2. **脱敏先于一切「人」与外部 API**：标注员、审核员、第三方 VLM 都算数据出域——未脱敏先出域 = 隐私事件
3. **策略即代码**：策略版本化、评审、测试；线上手改策略 = 绕过审计（等同手改 ACL）
4. **审计日志不可篡改、不可关停**：日志缺口 = 审计失效；能被关掉的审计保护不了任何人
5. **删除必须可传播、有凭证**：影响面摆上桌、逐级执行、出 deletion_certificate——「删了但说不清删了哪」等于没删
6. **法务口径不越位**：工程文档只承诺机制（控制点存在、可审计）；法条适用与出境结论**需法务确认**——替法务拍板是合规风险本身

**面试话术（30 秒）**：

> "合规我做引擎化：策略即代码，规则进版本库、能单测、判定留痕，违规不靠自己拦，挂到 G1 和 G4 门禁上拦——G4 违规率等于零是硬红线，和质量阈值的可豁免完全是两回事。数据先分级分类，公开到个人信息四级，标签随版本走；PII 检测人脸、姓名、位置、声音、设备标识，检出打标。链路纪律是脱敏前置：先脱敏再给标注台、再调外部 VLM——人和外部 API 都是数据出域消费者，这条和仿真旁路跳脱敏不矛盾，因为 sim_GT 血缘可查。留存按分级 TTL，删除请求走血缘圈影响面、逐级删、出凭证；和版本不可变的冲突我显式处理：合规删除是法务确认后的例外路径，账本保留删除记录。跨境只做工程控制点——本地化标记、出境清单、导出审计——法条口径交给法务。这套就是我做 XLB 安审规则引擎的搬运：规则版本化、判定留痕、违规拦截，对象从配置换成数据。"
