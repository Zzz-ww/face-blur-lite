# face-blur-lite 汇报：业界数据处理体系 × 本项目实证

> **用途**：对外汇报纸面版——以业界体系为纲（我理解了哪些流程/框架/功能模块），本项目作逐层实证注脚。深挖入口：[overview.md](overview.md)（总装与业界坐标）｜[README](../README.md)。数字口径基线 fa65f90，139 测试绿。

## 0｜主旨

我系统梳理过业界数据处理的**五层体系**，并用一个微缩实现（face-blur-lite：视频人脸脱敏管线，控制面/数据面分离的两层工作流）把其中三层的核心语义亲手踩过。下文按层展开：这层业界在解决什么问题、代表机制是什么、我的实证对应物是什么——**业界是纲，实现是注脚**。

## 1｜体系总览

```
┌─────────────────────────────────────────┬────────────────────────┐
│ 业界版图五层                            │ 本项目足迹             │
├─────────────────────────────────────────┼────────────────────────┤
│ L1 工作流编排引擎                       │ ● 实做：微缩控制面     │
│ Airflow·Argo·Kubeflow·Temporal·Ray 等   │   claim/lease/Join     │
├─────────────────────────────────────────┼────────────────────────┤
│ L2 数据引擎                             │ ○ 微缩：单机内嵌       │
│ Spark·Flink·Beam；Delta/Iceberg/Hudi    │   ffmpeg pipe O(1)     │
├─────────────────────────────────────────┼────────────────────────┤
│ L3 AI 数据平台能力层                    │ ◐ 雏形：质检断言       │
│ DVC·OpenLineage·CVAT·GE·MLflow；百舸等  │   版本/血缘=缺口       │
├─────────────────────────────────────────┼────────────────────────┤
│ L4 行业数据闭环                         │ ○ 微缩：脱敏一段       │
│ 具身 Ego·LeRobot·Cosmos；智驾 影子→OTA  │   qc_failed 隔离区     │
├─────────────────────────────────────────┼────────────────────────┤
│ L5 模型算子层                           │ ● 实做：主力位置       │
│ YOLO·SAM·SCRFD·DeepPrivacy2·CLIP        │   双检测器+A/B         │
└─────────────────────────────────────────┴────────────────────────┘
```

每层解决一个问题：**L1** 任务怎么被可靠调度执行；**L2** 数据怎么被高效加工；**L3** 数据资产怎么被管理；**L4** 数据怎么闭环成业务价值；**L5** 模型怎么以算子形态进管线。

## 2｜L1 工作流编排引擎（深讲）

**业界谱系**：Airflow（Python DAG+定时/依赖调度，批处理事实标准，Apache/Airbnb 出身）｜Argo Workflows（K8s 原生，每步一容器，CNCF 毕业）｜Kubeflow Pipelines（K8s 上 ML 管线组件化拼装）｜Temporal（**持久化执行**：代码即工作流，崩溃后从事件历史续跑，lease/attempt 语义的完全体，Uber Cadence 系）｜第二梯队分流：Dagster 资产导向 / Prefect 轻量 Pythonic / Flyte 强类型 ML / Metaflow 脚本即作业｜Ray（通用分布式后端，常当训练/数据处理底座）。

**我的理解聚焦在六语义公共内核**——这类系统无论叫什么，都在解同样六个问题：

```
    pending ──① 互斥认领：claim 事务＝单写者串行化
       │
    running ──② 租约回收：lease 900s TTL
       │                ≈ SQS visibility timeout
       │       ③ 重试预算：attempt≤3（≈ RetryPolicy）
       │       ⑤ 僵尸围栏：(worker_id, attempt)
       │                ≈ SQS receipt handle——迟到 ack 在此被拒
       │
    fan-in ──⑥ 原子 Join：rowcount==1 恰好一次
       │                ≈ 依赖边 join / futures 聚合
       │
    done ────④ 终态不可逆（契约测试锁定）
                ≈ 事件历史不可变
```

**六语义 × 引擎对照矩阵**：

| 语义 | 本项目 | Airflow | Argo | Temporal | K8s Job | Ray |
|---|---|---|---|---|---|---|
| 互斥认领 | `BEGIN IMMEDIATE` 事务 claim（单写者串行化） | scheduler 单点分派 | controller reconcile | task queue 长轮询 | 调度器绑定节点 | raylet 中央调度 |
| 租约回收 | lease 900s TTL 过期→pending 重派 | 僵尸 task 心跳超时重排 | pod 失败重建 | ScheduleToClose 超时 | node 心跳丢失→驱逐 | lineage 重算 |
| 重试预算 | attempt≤3 | retries+retry_delay | retryStrategy.limit | RetryPolicy.maximumAttempts | backoffLimit | max_retries |
| 终态不可逆 | 终态守卫（契约测试锁定） | terminal state 不回退 | Succeeded/Failed 终态 | 事件历史不可变 | completed pod 不重启 | —（无持久状态） |
| 僵尸围栏 | `(worker_id, attempt)` 复合谓词 | 引擎单写者 | 同左 | run ID 换代拒迟到结果 | UID/resourceVersion | — |
| fan-in 合并 | 原子 Join rowcount==1 | trigger rule join 节点 | 依赖边+withParam | futures 聚合 | 无原生 | futures gather |

语义锚点（业界文档级对应）：lease≈**SQS visibility timeout**、围栏≈**SQS receipt handle / K8s resourceVersion**、claim=单写者串行化。

**实证**：六语义全实做且被契约测试锁死——14 场景 ×2 实现（SQLite 内嵌 / gocp Go 服务）=28 双跑，行为漂移立刻红灯；fencing 用 `(worker_id, attempt)` 复合谓词拒僵尸 Worker 迟到 ack（同名转世场景测试钉死）。迁移路径已设计：gocp 静态单二进制即 Deployment，Worker 常驻模式即百舸任务式——**换调度层，算子层与质检策略 100% 保留**。

## 3｜L2 数据引擎

**业界机制**：Spark（批 ETL 代名词：内存中间态+shuffle）｜Flink（流优先：事件时间/状态计算，流批一体）｜Beam（统一编程模型，runner 挂 Flink/Spark）｜湖仓三件套 Delta Lake（Databricks）/ Iceberg（Netflix，表格式事实标准）/ Hudi（Uber）——给对象存储数据湖加 ACID 事务、time travel、schema 演进。核心分野在**中间态物化策略**（引擎托管 shuffle vs 流式不物化）与**容错**（checkpoint/lineage）。

**三种数据流模型对照**：

```
    Spark（批）  读 ─▶ 物化中间态 ─▶ shuffle ─▶ 物化 ─▶ 写
                 引擎托管物化：内存中间态；容错＝checkpoint

    Flink（流）  读 ⇄ 算子链（事件时间/状态计算）⇄ 写
                 流批一体：流式不物化

    本项目       ffmpeg 解码 ─▶ 检测 ─▶ 跟踪/糊 ─▶ 编码
                 全 pipe 帧不落盘：内存 O(1)，2121 帧 ≈6.4GB
                 split＝手工 fan-out；容错＝at-least-once+幂等覆盖写
```

**实证**：ffmpeg rawvideo pipe=单机流式管道——7 层格式变换 8 种形态全程 pipe、内存 O(1)（2121 帧 ≈6.4GB 帧流不落盘），split 切片=手工 fan-out，at-least-once+幂等覆盖写。分布式 shuffle/列存/批优化器**缺**——单机不需要，上云由存储层承接（BOS/PFS）；单机分片无净加速的负结果照写 README（批量 57.6s vs 串行 54.9s，加速位在容器配额/跨机池）——**知道边界在哪、加速位在哪**。

## 4｜L3 AI 数据平台能力层

**业界五件套**：版本（DVC：git 式大文件指针+远端存储；LakeFS：对象存储上的 git 分支语义）｜血缘（OpenLineage 开放标准，配 Marquez）｜标注（CVAT/Label Studio，模型预标注）｜质量断言（Great Expectations：「期望即测试」）｜闭环观测（MLflow/W&B：实验跟踪+模型注册）。国内坐标（三平台两层）：胜算/火山 LAS=**数据层**工作流（数据怎么被加工）、百舸=**算力层**工作流（任务怎么被调度执行）。

**五件套 × 本项目足迹**：

```
    版本      DVC / LakeFS           ✗ 缺口（backlog 第一优先级）
    血缘      OpenLineage / Marquez  ✗ 缺口（对标物已命名）
    标注      CVAT / Label Studio    — 本管线无标注环节
    质量断言  Great Expectations     ✓ 雏形完整（分级+隔离区+取证）
    闭环观测  MLflow / W&B           ◐ stats 只读旁路
```

**实证**：质量断言雏形完整——输出域抽帧复检 + T_FATAL=0.7 分级（fatal/marginal）+ qc_failed 隔离区（通过层永不见未验收件）+ 取证式违规清单（t_sec+conf+box）+ 抽样相位锁相两连的教训（BUG-010 滤镜相位偏移→016 等差抽样锁相，终局=互素步长+数学证明+性质测试：**抽样相位是质检语义的一部分**）。阈值分域（源域 det_conf=0.3 深检 / 输出域 pass_conf=0.5 复检，置信度不跨有损编码域守恒）=「便宜模型先筛、贵模型复核」模式的微缩版。stats 只读旁路=观测雏形。**版本/血缘=已知缺口，对标物知道（DVC/OpenLineage），已排 backlog**。

## 5｜L4 行业数据闭环（深讲）

**闭环骨架**：采集→上传→清洗/脱敏→入库→标注→训练→评测→部署→回流（badcase 回到采集或标注）。

**双泳道一图**（★＝本项目位置——入湖/入库前的法定脱敏工序）：

```
    具身泳道
    采集（遥操/Ego/仿真）→ 对齐（硬触发<1ms，33ms 差一帧不可修复）
      → 清洗/质检（三层：规则/物理/语义，约 30% 可进训练）
      → ★脱敏 → 入库（格式路由 LeRobot/RLDS/HDF5）→ 标注
      → 训练（VLA/世界模型）→ 回流（失败轨迹＝高价值样本）↺

    智驾泳道
    采集（影子模式+触发器，分歧才回传）→ ★脱敏（法定第一道工序）
      → 入湖（数百 PB/年）→ 4D 自动标注（离线范式）
      → 训练（端到端/RL）→ 仿真（世界模型补长尾）
      → OTA 灰度 → 影子 diff 回流 ↺
```

**具身泳道**：三路采集（真机遥操：废片率 30-40%／Ego 无本体：RGB→SLAM→手部姿态→IK→重定向，成本收敛到真机 1/2~1/3／仿真：Isaac/ManiSkill）→ 时序对齐是第一道工程约束（硬触发 <1ms，33ms=30fps 差一帧不可修复）→ 三层质检（规则/物理/语义，原始素材约 30% 可进训练）→ 入库格式路由（**模型↔格式强绑定**：π0/GR00T→LeRobot、Google 系→RLDS、RDT-1B→HDF5——平台必须做格式路由）→ 回流（**失败轨迹=高价值样本**）。

**智驾泳道**：影子模式+触发器筛选（分歧才回传，非全量上传）→ 长尾四路信号（规则触发器/不确定性/模型分歧/新场景聚类）→ 4D 自动标注（离线范式：多帧检测→跟踪→按 track 精修，无实时约束可用大模型；效率倍数各家口径分母不同、不可互换）→ 数据湖（车队年产数百 PB）→ 世界模型仿真补长尾 → OTA 灰度 → 影子 diff 回流。

**实证**：脱敏=链路**法定第一道工序**（车外视频入湖前的匿名化；国内 7 号令/GDPR 匿名化出口）——业界先例=百度百舸把 Meta EgoBlur（开源人脸/车牌脱敏模型）封装成平台算子；qc_failed 隔离区=badcase 隔离回流语义的微缩。具身侧对位：关节角/力矩通道与车牌/人体同走注册表扩算子路径——**换算子，不换错误模型**。

## 6｜L5 模型算子层（深讲）

**业界形态=「模型即算子」**：检测/分割/SLAM/VLM 内嵌于管线算子。YOLO 系（通用检测算子）｜SAM（预标注革命；SAM2 数据引擎：仅约 19% 帧需人工编辑）｜DeepPrivacy2（生成式替换，不可逆性最强）｜CLIP 嵌入（数据集去重/检索）｜VLM 打分（语义层质检：任务成败/因果链）。

**实证（主力位置）**：双检测器（YuNet 232KB 默认 / SCRFD 2.5MB opt-in）+ 三件方法论——**能力包络探针**（升级前画包络：YuNet 对 16-32px 小脸全盲，SCRFD 32px conf 0.374 可检出，选型由探针数据驱动）、**A/B 预注册判据**（胜出线预写死+同闸门原则；未胜出不翻默认——A/B 的价值是给你拒绝翻牌的理由）、**检测器协议注入**（`Detector` 协议+工厂，升级零控制面改动）。业界把「模型即算子」当默认形态，但公开材料少有带型号带实测的实例——本仓库是可核对的样本。

## 7｜收束：位置、边界、总纲

- **一句话对位**：第 5 层的算子 + 第 1 层的微缩控制面 + 第 3 层的质检雏形；缺 2、4 的规模化与真正的数据集版本管理——**边界即路线图**。
- **主动交代的边界**：数据集版本/血缘缺口（对标 DVC/OpenLineage）；K8s 集群实证未做（迁移五步已设计、MVP 已预留）；单机原型、规模未验证——但错误模型全踩过且文档化。
- **总纲**：业界体系是纲，本项目是三层的实证。交付的不是脱敏效果，是那套错误模型（幂等/租约/终态/契约/相位/取证）——放到具身数据平台上，就是把这套东西换成 K8s 调度层、算子换成多模态清洗。
