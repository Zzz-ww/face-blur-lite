# BUG-016：qc 抽样与检测节奏锁相（BUG-010 换马甲）

- **发现**：2026-09-25 业内对标冷读（docs/industry-benchmark.md 刀 1），当日亲手核实 + 本文档当日活证
- **任务**：修复波 fix/bug-016-017
- **状态**：已修复（互素步长）

## 现象

例行 qc（`sample_fps=1.0`）在 30fps 视频上**只抽中检测帧**：抽中帧号恒为
i ≡ 15 (mod 30)，而 15 mod 3 = 0 → det_every=3 下全部落在检测帧（i%3==0），
**2/3 的预测帧（i%3==1,2）例行 qc 永远看不到**。

活证（本机，6s 合成 30fps 视频 + 现行 FFmpegReader）：

```
stride=30 offset=15 抽中 6 帧
抽中帧号: [15, 45, 75, 105, 135, 165]
mod 3（det 相位类）: [0]  ← 只覆盖 1/3
```

这意味着"例行抽检通过"的置信度被系统性高估——抽检恰好避开了跟踪器
外推帧（BUG-011 的主场）。BUG-011 修复后预测帧本应是较弱环节，
而例行 qc 恰好对它零采样。

## 根因

BUG-010 修复把抽帧从 `-vf fps` 滤镜改为 Python 跨步抽样：步长
`N = round(fps/sample_fps)`、固定取窗口中点 `i % N == N//2`。
**任何固定 offset + 步长 N 的等差抽样，帧号 mod d 只取
gcd(N,d) 个残差类**。当 d | N（30fps@1fps、det_every=3 → 3|30）时
恒取同一类——抽样相位与内核检测节奏**锁相**。

BUG-010 的 postmortem 自己写了第二条方法论："stride 与 det_every 锁相
会系统性偏向某类帧"——**修复实现恰好踩中自己写的教训**：10fps 测试视频
（gcd(10,3)=1）天然逃过锁相，回归测试钉死的正是这个不锁相的个例，
于是绿灯常亮。部分锁（gcd(N,d)=g>1）同样存在：30fps@det_every=4 时
固定抽中奇数残差类（{1,3}），覆盖一半。

## 修复

**步长取整到与 2..8 互素的最近值**（`sample_stride_for(fps, sample_fps)`，
[ffmpeg_io.py](../../src/faceblur_lite/ffmpeg_io.py)）：

```python
n = max(1, round(fps / sample_fps))
m = n
while math.gcd(m, 840) != 1:      # 840 = lcm(2..8)
    m += 1
return m
```

数学：抽中帧号 `idx_k = k·m + m//2`，则 `idx_k mod d = (k·m + m//2) mod d`；
m 与 d 互素 ⟹ k·m mod d 遍历全部残差类 ⟹ **对 det_every ∈ 2..8 的任意
取值，连续 d 个窗口内抽样覆盖全部相位类**。60fps@1fps→61、25fps→29、
24fps→29、10fps→11。代价：窗口边界不再精确对齐 1s（1fps 抽样的实际
间隔 ≈ m/fps），时间戳仍逐帧精确（t=帧号/fps，BUG-010 语义保持）。
det_every > 8 或与步长有更大公因数的极端组合仍可能部分锁相（精确条件
gcd(m, det_every)>1，仅当 det_every 含 ≥11 素因子；如 10fps + det_every=11
→ m=11 全锁）——最终验收的 `sample_fps=None` 全密度复检仍是唯一硬闸门
（本仓既定分层：抽检=日常信号，全密度=验收）。

密度代价量化（验证波实测补记）：增量 ≤9（840 的 Jacobsthal 间隙），
常规 24-60fps 增 1-5 帧（3-21%）；**round 值落 2..10 时步长一律跳到
11**（比 1 大且与 840 互素的最小整数）——2-8fps 低帧率素材（监控/
录屏）或高 sample_fps 档有效密度最多降数倍（2fps@1fps 实得 0.18fps），
qc 的 sampled 计数可观测实际密度。

修后活证（同视频）：

```
修后 stride=31: mod 3 → [0, 1, 2], mod 2 → [0, 1]
```

## 教训

1. **方法论要对自己的实现做体检**：BUG-010 写下"锁相"教训时，
   没有对刚写完的跨步实现做残差类覆盖检查——教训描述的正是自己的
   默认参数（30fps@1fps@det3）。
2. **回归测试只钉住个例就会绿灯常亮**：10fps（gcd=1）是唯一逃过锁相的
   常见帧率，恰好成了唯一被钉死的帧率。抽样器的**相位类覆盖应是
   显式性质测试**（对 d∈2..8 全遍历），不是某个帧率上的时间戳快照。
3. 抽样工具的相位选择是**质检语义的一部分**，不是解码层的实现细节——
   步长选择必须有注释说明它防的是什么（本条已写入 sample_stride_for
   docstring）。
