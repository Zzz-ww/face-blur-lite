# BUG-013：低分不出生——持续 0.3–0.5 置信度的人脸长段裸奔

- **日期**：2026-09-24
- **发现场景**：真实视频全密度复检的长违规段（66/47/45 帧连续）定位：
  源域检测置信度长期落在 [low_thr, high_thr) = [0.3, 0.5) 的脸，每轮
  检测都进低分池，但 ByteTrack 语义"低分只救活不出生"使其永远成不了
  track → 永远不被糊 → 整段裸奔（输出域重编码后 conf ≥0.5 即被 qc 抓）。

## 根因

架构上让跟踪器的出生策略（防噪声 ghost）同时充当了脱敏门禁——两个
职责目标相反：跟踪要抑制噪声出生，脱敏要"宁可多糊"。检测帧上明明
看见了（≥det_conf=0.3）却因为不够"高分"而放行裸奔。

## 修复

`kernel.py process_video`：检测帧上糊框取 `track 横 ∪ 当帧检测框`
（`KernelParams.blur_all_dets`，默认开）。跟踪器回归本职——帧间预测
与关联，不再在检测帧上过滤检测。

## 效果与残余

det_every=1 + px8 + 并集：487 → 308 违规帧。det_every=3 时收益有限
（预测帧上无 track 仍裸奔，2/3 的帧），故与 det_every=1 搭配才有全效。

## 回归锁

`tests/test_kernel.py::test_blur_all_dets_blurs_low_conf_no_birth`
（monkeypatch 检测器恒返 0.35 检出：并集开→糊上；关→裸奔）
