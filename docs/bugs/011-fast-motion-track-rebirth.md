# BUG-011：快运动下 IoU 匹配失效 → track 每轮重生 → 速度永不收敛

- **日期**：2026-09-24
- **发现场景**：真实手机视频全密度复检 621/2121 帧违规（29%），且违规帧
  按 i%3 残差均匀分布（202/206/213）——推翻"预测帧独漏"假设后，重放
  内核链路（检测轮/跟踪框/qc 违规框逐帧对拍）定位本缺陷。

## 根因链（重放取证，段 1605–1675）

1. 视频中人脸（含相机横移）运动 ~10px/帧；det_every=3 下每检测轮位移
   ≈30px ≈ 1 个框宽（小脸 33px）
2. 新生 track `vel=0`：预测帧框原地不动 → 2 帧后人脸移出模糊区
   （margin 15%×33px≈5px < 位移 20px）→ **i%3==1 帧系统性脱靶**
3. 下一检测轮：预测框 vs 检测框错开 ≈1 框宽 → IoU≈0.05 < 0.1 失配
   → 高分未匹配框**重生新 track**（又 vel=0），老 track 滞留成幽灵
4. 循环 2–3：track 永远活不过一轮，EMA 速度永远从 0 爬坡，预测永远
   滞后——跟踪器退化为"糊在上一次检测位置"

附随：单元测试用 40px 框 + 30px 位移（IoU=0.14 恰好过线）从未暴露
此洞；真实人脸 33px 同速度 IoU=0.05 直接失配——**边界用例要从真实
数据形状里来**（同 BUG-009 教训）。

## 修复（两层，同根因）

- `tracker.py update()` 三轮兜底：IoU 高分匹配 + 低分救活之后，仍未
  匹配的 track × 高分框按**中心距 ≤ max(宽,高) 且面积 0.5–2×**做距离
  贪心配对。取舍：宁并勿重生——错并只是 track 提前挪位（同一张脸的
  概率极高），重生则让预测永久滞后（脱敏代价不对称：宁可多糊）
- 速度自举：`hits ≤ 2` 直接采纳瞬时速度 `inst_v`，EMA 从第 3 次命中
  起——vel=0 起步的 EMA 以 α=0.6 的 0.4 系数爬坡，快运动下长期欠速

## 效果与残余

- 真实视频 track 总数 88（重生消除，track_count 恢复"≈人脸出现次数"
  的语义）；全密度 qc 违规帧 621→584
- 残余违规为**覆盖类**问题（另两个独立机制）：未糊（入画空窗/低分
  不出生/检不出）与半糊（小脸 + 15% margin 太窄），见参数实验记录
